# Spec: 工作区「文件」主视图（资源管理器 + 编辑器）

## 目标

在左栏底栏增加第三档外壳主视图 **文件**。切到文件后：左栏是已打开工作区的文件树，右栏是可编辑的多标签工作台（文本用内嵌编辑器，图片 / PDF / Office / 媒体复用现有只读预览）。形态对齐 VS Code 的资源管理器 + 编辑区，而不是在右侧 Side Pane 里再塞一种 tab。

会话里点开文件的默认行为不变：仍在 Side Pane 只读预览。预览上另加「在文件视图中查看」，才切到本主视图。

## 产品规则

### 主视图身份

- 外壳主视图三档：`tasks` | `files` | `settings`。底栏第四格「更多」仍只是下拉，不是主视图。细则见 `workspace-shell-primary-tabs.md`、`workspace-shell-chrome-more.md`。
- **文件**：左栏为工作区下拉 + 该工作区文件树；右栏为编辑工作台。
- 切到文件时，任务树（会话列、底栏 Terminal、右侧 Side Pane）与设置正文都保活不卸，只是不画、不可点。切回任务时 `workspaceMainView` 保持进入文件前的值。
- 切到设置或任务时，文件工作台同样保活：已开标签、未保存缓冲、滚动与光标不得因切主视图而丢失。
- 无项目也可以进入文件主视图：下拉为空、树为空、右栏为空编辑区，不强制跳去设置。

### 左栏：工作区下拉 + 文件树

- 顶部下拉的候选项与任务栏里**已经打开的工作区 tab 同源**（含本地与远程）。不是「打开文件夹」对话框，也不在这里新开工作区。
- 选中哪一项，左栏文件树就显示哪一个工作区。切换**只改左栏列表**。
- 下拉不写全局当前工作区：会话所属工作区、Git 都不跟过去。
- 右栏已经打开的标签不受下拉影响，可以继续混排来自不同工作区的文件。
- 下拉上次选中按窗口记忆；再次进入文件主视图时恢复。若记忆项已从已打开列表消失，回退到列表第一项；列表为空则空态。
- 文件树复用现有工作区文件树能力（浏览、搜索、Git 状态、Reveal、本机资源管理器）。不再作为盖住任务列表的叠层。
- 任务行上的「查看文件」改为：切到文件主视图，下拉选中该工作区，若带路径则在树中定位。不另开一套叠层树。
- 不可用工作区仍可出现在下拉里；树展示既有不可用态，不可打开或保存。
- 文件树的创建、改名、删除与复制 / 剪切 / 粘贴规则见 `workspace-file-actions.md`。
- 顶部合并为单一工作区操作行与常驻名称 / 路径搜索；高级包含 / 排除、搜索被忽略文件、筛选数量与截断反馈见 `workspace-file-explorer-search.md`。搜索条件只影响当前文件树，不修改 `@` 文件引用范围或工作区忽略文件。

### 文件树与聊天的边界

- 文件和目录的右键菜单不提供「添加到聊天」，Desktop、Web、本地和远程工作区使用同一规则；删除菜单项及其独占的翻译、标签类型和全局事件发送 / 监听接口。
- 文件树不通过全局事件修改聊天草稿，也不自动切换会话、发送消息或选择聊天目标。移除末尾菜单项时一并移除其分隔线。
- 文件拖入聊天输入框与手动 `@` 文件引用继续使用现有流程。引用及草稿仍由目标 Composer 独占；拖拽 payload 保留工作区身份，同工作区引用相对路径，跨工作区引用绝对路径，不进入附件上传队列。
- 不新增状态、服务或协议，不迁移或清理已有聊天草稿；其它内容的「添加到聊天」入口沿用各自的规则。

```text
文件树右键 → 打开 / 打开方式 / 本机资源管理器 / 复制路径
文件树拖拽 → 目标 Composer → 文件引用 → 现有聊天草稿
```

交互 E2E 验收场景（需获准操作隔离应用后执行）：

1. Desktop 和 Web 的文件、目录右键菜单均无「添加到聊天」，打开、打开方式与复制路径仍按原规则提供，菜单末尾无多余分隔线。
2. 在独立文件视图或会话侧栏浏览文件，打开右键菜单不改变聊天草稿或切换会话；本地和远程工作区行为一致。
3. 把文件 / 目录拖入可交互的聊天输入框，仍生成引用且不自动发送或上传；跨工作区及远程身份相同路径的引用仍保持隔离。

### 右栏：编辑工作台

- 右栏是文件主视图自己的工作台，**不是** Side Pane tab。不与沙箱、子代理、计划、浏览器抢 Side Pane。
- 第一版只有**单组多标签**，不分屏，不做路径面包屑。
- 标签身份必须带工作区隔离 key 与路径：`workspaceIdentity?.trim() || workspacePath` + 文件路径。同一工作区同一路径重复打开只聚焦已有标签。
- 不同工作区的同一相对路径是两张标签，允许同时打开。
- 标签主文案是文件名；同名且来自不同工作区时，tooltip 或副文案带工作区名。
- **文本**：内嵌 Monaco 打开、编辑。工作台缓冲是正文的唯一权威；编辑器只是视图。用户输入写回缓冲；从缓冲程序化灌进编辑器时，不得再把这次灌入当作用户输入写回缓冲。换行符等规范化差异若形成来回改写，会把嵌套更新打到 React 上限，整块文件区被错误边界接管。
- **大文本**：`≤ 8 MiB` 且所有窗口 UTF-8 无损的文本按有界分块完整读取后进入 Monaco 编辑；`> 8 MiB` 使用固定 256 KiB 块的按需编辑，只加载当前块，不把全文写入缓冲；任一非法 UTF-8 块只读并显示替换字符，其它块仍可编辑，保存时服务逐字节保留未触碰的坏字节。8 MiB 是「完整正文模型 / 固定块模型」的切换阈值，不是编辑能力上限。读取决策、块边界、补丁与冲突细则见 `workspace-large-text-files.md`。
- **图片 / PDF / Office / 媒体**：同一条标签条里的只读预览，复用现有 Preview 能力，不塞进 Monaco。
- 未命名标签没有磁盘路径，保存成功后身份变成该路径的文件标签。
- **编辑器右键菜单必须跟随应用语言**。Monaco 的 ESM 产物不内置语言包，菜单文案默认硬编码英文；文件工作台在编辑器就绪后按当前语言改写 Monaco 右键菜单（含「转到定义 / 转到引用 / 转到符号 / 预览 / 重命名符号 / 格式化文档 / 剪切复制粘贴 / 命令面板」及 Peek 等子菜单），切换语言时同步刷新。未登记文案的菜单项保留英文，不做兜底翻译。

### 工作台顶部与文件标签

文件主视图按宿主能力安排顶部空间；菜单和标签的交互区域始终不可拖动。

- **菜单按平台只提供一套入口。** macOS Desktop 使用系统菜单栏（含全屏时由系统管理显隐）；Windows / Linux 使用左上应用菜单按钮打开既有原生菜单。Desktop 文件工作台不再额外渲染「文件 / 编辑」行，避免重复菜单和额外的 36px 高度。Web / 手机远控没有宿主菜单，在 48px 顶带内保留可点击、可触摸的「文件 / 编辑」入口。
- **Desktop 不单独保留标题行或拖动行。** 文件 Tab 直接从工作台顶边开始，不显示额外的文件 / 工作区标题，不为窗口拖动增加一整行高度。Desktop 不渲染页内文件 / 编辑行。
- **Web / 手机远控只有一条 48px 顶带。** 「文件 / 编辑」入口与既有 48px 全局左上操作组同处一行；该行之后直接是 36px 文件 Tab 条。删除原先独立的 36px 页内菜单行及其纯空占位，不再增加第二行菜单；空工作台与有标签工作台相同。Desktop 不渲染这条顶带，保持现有 Tab 顶边与局部避让。
- **Web 顶带按真实几何避让。** 「文件 / 编辑」组从全局左上操作组的实际右沿（含平台 padding）之后 8px 开始，按 DOM 矩形重算；窗口缩放、侧栏抽屉开合、更新入口显隐、主视图切换后都重新测量。菜单组不换行、不改变 48px 行高、不被其它操作遮住；下拉在视口内定位并可内部滚动。320px 下两个入口仍完整可点，430px 与 1280px 保持同一结构。几何只写派生布局，不进入 Zustand 或持久化。
- **窗口拖动归全局左上区域。** 侧栏展开时复用既有顶部拖动空白；Desktop 文件页侧栏收起或抽屉关闭时，只在全局按钮旁保留 20px 宽的小块拖动区。全局交互组为 `no-drag`，小块空白自己声明 `drag`，与按钮互不重叠。文件工作台、Tab、局部避让区域均不声明窗口 `drag`。
- **窗控只占右上角。** Windows / Linux 文件页通过绝对定位挂载既有 `DesktopWindowControls`，不增加正文流高度、不依赖隐藏任务 Header；仅实际按钮节点可命中，外围定位容器不拦截 Tab。macOS 使用原生交通灯。隐藏保活文件页不挂载窗控，也不保留可交互窗口层。
- **每组按真实重叠局部避让。** 文件工作台用一个 DOM 几何观察器读取全局左上操作组（包含交通灯前置安全区与局部拖动空白）、实际右侧窗控及各组 Tab 的矩形。只有水平、垂直都相交的组才预留对应左右空间；默认标签条 36px，必要时将该组标签条高度延伸到相交控件底边加 4px，不在其它组添加空白。全局按钮和窗控各保留 8px 横向间距。
- **窄组不能被完全遮住。** 左右避让后不足 `min(组宽, 96px)` 时，仅该组把 Tab 内容移至相交控件下方，恢复全组宽度，保留一条可操作标签条；不压缩避让到控件下面、不限制现有分屏、不把这个局部碰撞提升成整窗标题行。非相交组和下方分屏保持 36px 标签条。
- **几何是派生布局。** 观察各组 Tab、操作组及其包含平台 padding 的父层、窗控、工作台尺寸；分屏拓扑变化重新绑定，侧栏开合、窗口缩放、全屏与交通灯指标通过实际 DOM 尺寸重算。投影只写对应 Tab 节点 CSS 变量，不进入 Zustand 或持久化，不保留旧 caption 避让变量与双重写入路径。
- **标签交互保持独立。** Tab 的激活、关闭、右键、中键、排序与 HTML 拖动分屏只作用于标签层；空白双击新建不能接到窗口拖动区。
- **无工作区外壳也填满剩余宽度。** Desktop 保留左侧导航及其顶部拖动空白；Web 窄屏不让空文件树占用 264px，隐藏空树并把既有主视图导航置于底部，文件区使用全部可用宽度。
- 隐藏保活层遵守下文「隐藏保活层的原生拖动隔离」规则；后代不得继续注册窗口拖动区域。
- 标签条本身按编辑器组来画，不是普通按钮排：文件图标、预览斜体、当前项顶沿强调、关闭按钮在当前项/悬停时出现、脏态用圆点（悬停变关闭）、中键关闭。
- 右键：保存、另存为、保持打开（仅预览标签）、关闭、关闭其他、关闭右侧、关闭已保存、关闭全部、复制路径 / 复制相对路径、在文件树中定位、右侧 / 下方分屏。保存与另存为作用于被右键的那张标签，不要求它是活动标签。
- 双击标签条空白处：新建未命名标签（VS Code 双击标题区）。

### 文件工作台菜单的可达性

- 「文件」提供新建文件、保存、另存为、全部保存、关闭编辑器。「编辑」提供撤销、重做、查找、查找替换。文案复用共享应用菜单翻译；快捷键提示读取用户当前生效绑定，不另维护默认键位。
- Web 空工作台仍显示页内菜单；有已打开工作区时新建可用，真正没有工作区时新建置灰，不显示一个点击无效的入口；其余按实际对象置灰。未命名文本可保存并转入现有另存为流程；文本未修改时也可另存为。图片 / PDF / Office 等只读标签以及尚未加载、加载失败的文本禁用保存和文本编辑命令，但仍可关闭；全部保存只看全部工作区缓冲中的脏文本数量。
- 动作针对当前聚焦编辑器组的活动标签；点击菜单产生的失焦不得改变目标。撤销 / 重做后回到原编辑区，查找后保留查找框焦点，不能被菜单关闭后的自动回焦抢走。切走文件主视图后文件菜单关闭并不可交互，过期命令不得修改保活的工作台。
- 新菜单与原生菜单、快捷键共用现有文件命令处理与编辑目标路由；不新增缓冲、文件服务、磁盘写入路径或远程请求路径。失败、脏标签关闭及冲突仍交给现有控制器。
- Web 页内菜单采用现有 DropdownMenu 组件；窄屏菜单在视口内定位并内部滚动，不使用向屏外展开的嵌套子菜单。非文本预览不改变菜单平台规则。

```text
原生菜单 / 工作台菜单 / 快捷键
  → 既有文件命令处理（操作前核对当前主视图）
  → 工作台控制器 → filesEditorStore / 工作区 IFileService
  → 当前活动标签、脏态与菜单可用状态的只读投影

工作台编辑菜单 → 既有编辑命令路由 → 当前聚焦组的 Monaco 句柄

全局左上区域：[交互按钮 no-drag] [收起时局部空白 drag]
主视图 / 侧栏显隐 → 外壳 window-drag-disabled 边界
  → 隐藏根及所有后代 computed app-region=none → 不参与原生区域计算
实际操作区 / 窗控 / 各组 Tab 矩形 → 工作台 ResizeObserver → 各 Tab CSS 布局投影
  → 未相交组：[36px 文件 Tab / no-drag] [编辑器正文]
  → 相交组：[局部左右避让 + 文件 Tab / no-drag] [编辑器正文]
```

验收场景（交互 E2E；需要获准操作隔离应用后执行）：

1. Windows / Linux 普通、最大化、全屏窗口：左上应用菜单按钮可点；文件视图不再出现页内文件 / 编辑菜单，顶部避让仍保护窗控和全局入口。
2. macOS 普通及全屏：仅保留系统菜单，侧栏展开时文件 Tab 直接顶上，无额外标题 / 拖动行。侧栏收起、抽屉与窗口缩放后，按真实重叠局部避让交通灯和全局按钮；左侧小区域可拖窗口，点击 / 关闭 / 拖动 Tab 不移动窗口。
3. Web 1280px 与手机 320px / 430px：打开空文件工作台，从菜单新建、保存未命名文件、取消另存为、再次保存；抽屉开合后入口位置稳定，菜单不溢出屏幕。
4. 文本 / 非文本 / 空工作台之间切换：保存、编辑与关闭项正确启用或置灰；未保存文件关闭仍出现保存 / 不保存 / 取消流程。
5. 分屏并混合本地 / 远程工作区：聚焦另一组后打开菜单，保存、撤销、查找与关闭只作用于该组；切走主视图后保活工作台不响应过期菜单。
6. 修改保存快捷键或清空绑定：菜单提示同步变化；切中英文后标题及条目同步变化；键盘打开、选择、Esc 关闭菜单可用。
7. Windows / Linux 切到文件视图（含无工作区）后，右上角最小化 / 最大化 / 关闭窗控均可见且可点击，外围不遮挡 Tab，不出现额外标题行；左侧小块拖动、文件 Tab 拖动分屏是独立命中区域。
8. 任意嵌套横纵分屏：无全局标题行；只对实际相交的组预留空间。160px 窄组被控件横向占满时，该组 Tab 仅局部移到控件下方且仍可激活 / 关闭，其他组不跟着下移。恢复宽度后自动回到横向避让。隐藏文件页后不留下透明拖动层、旧避让或可点击窗控。

### 预览标签（对齐 VS Code Preview Mode / unpinned editor）

VS Code 编辑器组里 **unpinned = 预览**：斜体标题；一组最多一张。再打开另一张 unpinned 时，用 `replaceEditor` 换掉当前预览、占同一槽。`pinned` 之后不再被替换。Sticky（钉在左侧）是另一件事，第一版不做。

- 树中**单击**或 Enter：unpinned 打开。已有预览则换掉它，停在原槽位。没有预览则插在当前焦点右侧（对应默认 `openPositioning: right`）。
- 树中**双击**、双击斜体标签、右键「保持打开」、或开始编辑：变成 pinned，标题恢复正体。
- 已经 pinned 的同一路径再单击：只聚焦，不变回预览。
- 未命名、命令新建、双击标签条空白、会话「在文件视图中查看」、文件树右键「打开」：直接 pinned。
- 脏标签不可能仍是预览：正文一改就 pin。因此替换预览时不必问保存。
- 第一版不提供 `enablePreview` 设置，不做 sticky，不分屏多组。

### 文件类型识别与预览复用

- 任务 Side Pane 与文件工作台共用一套路径预览分类规则，组合现有图片、音视频、PDF、PPTX 和 Office 格式识别能力；不得在工作台另外维护支持格式列表。
- 已支持的位图 / 动图、音视频、PDF、PPTX、Word 和 Excel 均进入现有 `PreviewPane`。两处只保留容器与顶部操作的差异，复用预览渲染、工作区文件服务、加载失败和不支持类型的提示；不新增预览器、文件读取服务或协议。
- 普通文本、Markdown 和 SVG 在工作台仍用 Monaco 编辑；Side Pane 中的 Markdown / SVG 仍按现有规则预览或查看源码。统一分类不得把 SVG 源码编辑改成只读图片，也不把所有文本文件送入只读预览。
- 未知扩展名不能单凭路径断定为文本。现有 `IFileService.readTextFile` 返回 `isBinary` 时，工作台打开只读预览标签，复用 `PreviewPane` 的二进制提示，不建立可保存的空文本缓冲。重新打开和延迟恢复遵守同一规则。
- 干净标签恢复时按当前共用分类修正旧版本错误记录的文本类型，不在恢复元数据时读盘；未知类型仅在标签按需加载时根据 `isBinary` 修正。缓冲 ID、工作区身份、标签顺序、焦点及预览 / 固定状态保持不变，无需变更持久化版本。
- 已恢复的未保存草稿优先于路径分类与异步读盘结果，不因文件扩展名、外部文件类型变化或过期读取而丢弃。Files Editor Store 继续独占缓冲和标签状态；分类是纯派生结果，不新增缓存或第二份类型状态。
- 读取及类型修正仍在现有打开 / 恢复准入路径内完成，保留文件变更、请求所有权及远程身份隔离检查；Desktop / Web / 远控使用同一规则，不改变连续流或可恢复流的交付语义。

```text
文件路径 → 共用预览分类（无状态）
  ├─ Side Pane → 现有 PreviewPane → 工作区文件服务 → 只读预览 / 提示
  └─ 文件工作台控制器 → Files Editor Store（唯一缓冲与标签所有者）
       ├─ 已识别非文本 → 只读缓冲 → 同一 PreviewPane
       └─ 文本候选 → 现有 readTextFile（带工作区身份、验证读取仍有效）
            ├─ isBinary → 只读缓冲 → 同一 PreviewPane 的二进制提示
            └─ 文本 → 文本缓冲 → Monaco
恢复：草稿优先 → 干净标签按路径修正 → 激活后按需读取 → 原缓冲 ID 内提交
```

验收场景（单元 / 集成回归；交互 E2E 需获准操作隔离应用后执行）：

1. 从文件树打开 PNG / JPG / GIF / WebP / AVIF、音频 / 视频、PDF / PPTX / Word / Excel，再从任务 Side Pane 查看同一路径：均复用对应预览，不出现空 Monaco；非文本标签不可保存。
2. 工作台打开 Markdown / SVG / 代码仍可编辑；Side Pane 保留 Markdown / SVG 的只读预览和源码切换。未知扩展的真实文本仍可编辑，真实二进制显示已有二进制提示。
3. 恢复旧会话中的干净图片文本标签时无需预读文件即修正为只读标签；未知二进制在激活读取后修正。两者保留身份、顺序、焦点、分屏视图与预览状态。
4. 已有脏草稿（包括旧版本图片误开后产生的草稿）仍按草稿恢复，不被类型修正或异步读取覆盖；读取期间的改名 / 删除不得让旧结果重新建立旧路径标签。
5. 两个本地 / 远程工作区具有同名同路径资源时，文件服务仍按 `workspaceIdentity?.trim() || workspacePath` 和 `workspaceRemoteSessionId` 隔离；首次进入文件视图前不新增读盘。

### 图片预览体积与读取

- 任务 Side Pane 和文件工作台共用 `PreviewPane` 的图片读取生命周期；普通 PNG / JPEG 等不再受 `readMediaPreview` 默认 4 MiB 的整文件 base64 上限影响。Markdown 内联图片和工具卡缩略图维持各自现有读取规则，本次不改变文档、音视频或附件的大小限制。
- 图片先通过所属工作区的现有 `IFileService.stat` 取得大小，再串行调用 `readFileRange`，每块最多 1 MiB，以二进制字节组装 Blob URL 交给现有图片组件。不新增文件服务或协议，不将远端路径当作本机 URL，不上传图片到外部服务。
- 为约束 Renderer 内存，图片原始文件大小最多 64 MiB，边界值允许；超限时在读取字节前停止，并以当前语言提示「图片超过预览上限（64 MiB）」及使用其他应用打开。像素解码仍由浏览器负责，本次不引入转码、缩略图或取消浏览器自身的解码限制。
- 初始与结束时均要求路径仍为普通文件。读取必须覆盖最初观察到的完整字节数；短读 / 空块、超出请求长度、文件消失、变为目录或结束时大小改变均不得渲染部分图片。每块只保留返回视图覆盖的字节，并保存独立副本，避免缓冲复用改写已读内容。文件缺失使用现有缺失提示，其余错误使用本地化的图片不可用提示，不把原始绝对路径错误直接呈现给用户。
- `PreviewPane` 的图片加载生命周期是 Blob URL 的唯一所有者：换文件、换工作区、关闭标签或卸载时停止后续分块请求并撤销已有 URL；在途 RPC 可完成，但过期成功和失败结果均不得创建 URL、更新图片或错误状态。同源判定同时比较文件服务、`workspaceIdentity?.trim() || workspacePath`、`workspaceRemoteSessionId`、路径与媒体类型，共享文件服务不能省略身份隔离。加载失败必须退出 loading，不新增全局缓存、持久化或重试写入路径。
- 新版支持分块的文件服务使用同一路径；旧服务若没有文件大小，可仅退回既有 `readMediaPreview`，保留它原有上限，不通过无限重试或提升服务全局上限绕过边界。Desktop / Web / 远控都沿用 `useWorkspaceServices` 解析到的服务，身份与会话隔离不变，连续 / 可恢复传输语义不变。

```text
工作区身份 + 图片路径 → PreviewPane 图片加载生命周期（唯一 URL 所有者）
  → IFileService.stat → 校验 64 MiB 上限
  → 串行 readFileRange（每块 ≤ 1 MiB）→ 核对完整长度与结束时大小
  → Blob → object URL → 现有 ImagePreviewContent
换源 / 关闭 → 标记当前读取失效 → 停止后续 range → revoke URL
```

验收场景（自动化回归；真实应用交互 E2E 需获准后执行）：

1. 打开 4–8 MiB 的普通 PNG（包括约 4.55 MiB 的 2560×1440 截图）和超过 8 MiB 的图片：任务侧栏与文件工作台均能取得完整图片，不调用大尺寸整文件 base64 读取。
2. 分块边界和 64 MiB 文件读取完整且不多读；超过 64 MiB 不发起 range，提示正确；短读、空块、文件消失或读取期间大小改变均退出加载，不展示截断内容。
3. 读取中切换文件、工作区或关闭标签：停止追加请求，迟到结果不提交；成功加载后切换或关闭时撤销 URL。远程同路径资源仍使用各自工作区服务。
4. 旧服务无大小元数据时保持原兼容路径；Markdown / 工具卡图片、PDF / Office / 音视频及 SVG 源码编辑的既有行为不变。

### 打开与新建

- 在树中点文本或非文本，都进右栏工作台；打开方式由上一节的预览 / 固定规则决定，不按「是不是图片」另分一套单击语义。
- 应用菜单及快捷键「新建」只打开未命名标签，不立即落盘；文件树「新建文件」命名确认后立即创建空文件并打开，见 `workspace-file-actions.md`。
- 未命名标签保存时弹出选路；默认目录：
  - 文件树当前有选中文件夹 → 该文件夹；
  - 否则 → 左栏下拉当前工作区根。
- 内置保存对话框只选已存在的目录，不自动创建中间目录；目录创建和文件管理另走文件树操作。Desktop 本机目标另提供「使用系统对话框」选路，目录创建与覆盖确认由系统组件负责，写盘仍走原保存流程；远程 / Web 不使用本机路径。能力、取消与迟到结果规则见 `native-path-dialogs.md`。
- 允许多张未命名标签并存。
- Desktop、Web、远程工作区同一套行为；读、写都走该工作区的文件服务通道，远程必须带 `workspaceIdentity` 与 `remoteSessionId`，不得只按路径匹配。

### 保存、脏态、冲突

- 脏态：普通文本按当前正文与上次成功保存（或首次打开时读到的）基准比较；大文件按 `changes` 中任一有效项 `text !== originalText` 计算。预览标签、未改过的未命名空标签不算脏。
- 普通文本缓冲记录运行时 `diskVersion`（打开、自动重载或上次成功保存得到的磁盘版本）；普通文本与大文件都记录 `externalChange`（`modified` / `deleted`）。这些字段不写入 localStorage，也不作为跨重启的保存依据。
- 保存：所有入口统一调用 `IFileService.commitTextFile`。普通文本用 `full` 携带 `expectedVersion`；大文件用基于原文件坐标的 `patches`，`expectedVersion` 取 `baseVersion`。冲突、补丁校验、临时文件与原子 rename / link 都在该路径内完成。
- 普通文本冲突：盘上内容既不等于基准、也不等于当前正文时出现冲突，不写。用户选「用编辑器覆盖」时，以弹窗观察到的磁盘版本作为 `expectedVersion` 提交完整正文；磁盘在弹窗后再次变化必须再次冲突，不能静默套用上一次确认。选「用磁盘」丢弃缓冲并重载。
- 大文件冲突：不提供把补丁强套到新版本的覆盖；只能取消并保留草稿，或放弃草稿并按磁盘重载。
- Agent 或其它进程在编辑期间改盘：激活时 watch 与重新激活探测；干净普通文本安全自动重载，脏文本只设置 `externalChange` 并提示，绝不自动替换正文或重置基准；干净大文件提示后按需刷新，脏大文件不自动重基线。
- 已保存文件在保存时路径消失：不自动重建，按冲突处理；只有用户显式选择「重新创建」才对普通文本使用 `expectedVersion: null` + `full`。未命名或另存为新路径的首次创建可直接使用 `null`。大文件没有完整正文，不能重建；另存为仅在源版本仍一致时可用。删除后不得由自动保存或延迟请求复活原路径。
- 保存失败必须让用户看见：写盘异常时弹出提示，标签保持未保存态，关闭流程与「全部保存」就此停止，不静默吞掉错误。
- 冲突处理失败（覆盖写盘仍失败）时：待续接的关闭一并取消，「全部保存」队列停止，剩余文件保持未保存。
- 保存入口收敛到一条写盘路径（菜单、快捷键、标签栏保存按钮、标签右键、全部保存共用）：菜单与按钮只负责发起，提交、冲突判定、脏态清理由同一处实现。
- 保存快捷键沿用系统惯例（macOS ⌘S，其它 Ctrl+S），只作用于文件主视图焦点标签；键位可在快捷键设置里改，改完菜单提示同步变化。
- 标签栏保存按钮：只在「当前标签是可保存文本且有未保存改动」时出现，点击走同一条提交路径；普通文本与大文件都支持。
- 标签右键「保存 / 另存为」作用于被右键的那张标签，置灰规则与应用菜单 canSave 一致：已加载完成的普通文本或有大文件有效块修改的缓冲可用（含未命名与未修改普通文本），图片等只读预览及尚未加载 / 加载失败的文本置灰。另存为源与目标都受版本保护：源已变化或删除时失败，目标 `null` 必须不存在。
- 未命名标签（还没有路径）同样可保存：保存动作转入另存为对话框，因此应用菜单里的「保存 / 另存为」不因缺少路径而置灰。
- 关闭脏标签、全部保存与脏标记都覆盖普通文本与大文件；大文件保存提交补丁，不保存则清除 IndexedDB 草稿。
- 桌面端 ⌘W 的语义是「关闭当前聚焦编辑器组的活动标签」，任何界面都不回落为关闭窗口；非文件界面按 ⌘W 不关闭任何标签、侧栏或窗口。
- 应用菜单的「新建文件」在任何界面都可用：新建未命名标签并切到文件界面，让新标签立刻可见。

### 编辑器能力边界

- Monaco 在这里是文本编辑器，不是工作区语言服务。不读项目 tsconfig、paths、node_modules，也不接 LSP。
- TypeScript / JavaScript 只保留语法高亮与语法诊断，关掉语义诊断和建议诊断，避免把 `@zcode/services/node` 这类工作区别名报成「找不到模块」。
- JSON 按 JSONC 处理：允许注释和尾逗号，这样 `tsconfig.json` 不会因为合法注释画红线。

### 会话预览与「在文件视图中查看」

- 会话、工具结果、消息链接里点文件：**默认仍打开右侧 Side Pane 的只读预览**（现有 `code-viewer`）。
- 该预览除「复制路径」外，增加「在文件视图中查看」：切到文件主视图，打开或聚焦对应标签（文本进编辑器，非文本进预览标签），左栏下拉切到该文件所属工作区并尽量在树中定位。下拉切换仍不改全局当前工作区。
- Side Pane 预览与文件工作台是两条表面，内容不互相自动同步；文件工作台里已脏的缓冲，不会因为 Side Pane 又打开同一路径而被覆盖。

### 恢复

- 按窗口持久化：打开中的文件路径（含工作区隔离 key）、未命名标签、脏草稿及其基准、焦点标签、左栏下拉选中。
- 冷启动只恢复轻量标签元数据与未保存草稿；文件工作台未进入前，不调用文件服务读取已打开文件。恢复工作不得阻塞任务列表、会话订阅或首屏绘制。
- 首次进入文件视图时，先显示已恢复的标签与焦点；焦点文件按需读取，其它干净文件在用户选中时读取。不得对全部标签无界并发读取。
- 恢复读盘只更新「当前磁盘」认知，不在此时弹普通文本冲突；用户下次保存才按上面的规则比较。大文件块草稿的基准不一致只提示「不可套用」，不算保存冲突。恢复完成不得逐文件重复写入整份持久化会话。
- 普通文本超大草稿可只记路径、不落正文；恢复后按盘上内容打开，并视为未脏。大文件按下一行恢复块补丁。
- 大文件只恢复标签元数据（`id`、`preview`、`path`、`kind: "large-text"`）与工作区身份，不恢复窗口正文、块偏移、当前版本或总大小到 localStorage；激活时按需通过 `readTextFileWindow` 走同一读取决策。块补丁草稿异步保存在 IndexedDB，只有当前磁盘版本与草稿 `baseVersion` 一致时才套用，否则保留草稿并提示不可套用。细则见 `workspace-large-text-files.md`。

### 窄屏

- 切任务 / 文件 / 设置不收起抽屉，与 `workspace-shell-responsive-layout.md` 一致。
- 下拉换工作区不收起抽屉。
- 在树中点开一个文件（目标是右栏工作台）后收起抽屉。
- 「在文件视图中查看」从会话触发时：切到文件主视图；若当时是抽屉盖着正文，收起抽屉以便看见编辑区。

### Web 路由

- Web 地址栏增加 `/files`，表示文件主视图。刷新停在文件。
- 工作区下拉选中、打开了哪些标签**不进 URL**（与「workspace 不进 URL」一致）。见 `web-url-routing.md`。

## 文件服务

文件服务提供目录、文本 / 媒体读取、文件名搜索、带版本文本提交，以及 `.zcodeignore` 读写；文件监听沿用既有 watcher。

文件工作台的文本读取统一使用 `IFileService.readTextFileWindow`：`offset` / `length` 可选，`length` 默认且最多 256 KiB、最小 4 字节；带版本、UTF-8 边界安全，读前与读后（含路径 stat）校验版本，并可用 `expectedVersion` 拒绝混合版本。合法码点内部按既有规则回退到码点起始；前置序列非法时保留请求 offset，固定块按该非法字节边界精确读取。可选 `hasDecodingErrors` 用字节级 `isUtf8` 标记本窗非法 UTF-8；合法编码的 U+FFFD 不算错误。`> 8 MiB` 用固定 256 KiB 块按需编辑，非法 UTF-8 只把本块标为只读，其它块仍可编辑。该方法同时服务本地、Desktop 与远程工作区；Desktop 的 MessagePort 与 Web / 手机远控的 WebSocket / WebRTC 走同一套 typed RPC，不新增通道或 Host。既有 `readTextFile` 保留给 Side Pane 预览等旧调用方。完整契约见 `workspace-large-text-files.md`。

文本写入统一使用 `IFileService.commitTextFile`：普通文本 `full`，大文件 `patches`；`expectedVersion: null` 必须不存在且只允许 `full`，另存为同时保护源与目标版本。Host 对 canonical 路径使用现有共享文件锁，按源 / 目标排序加锁，在有界临时文件 + fsync 后复核版本并原子 rename；`null` 新建使用 `link`，不支持时直接失败，不降级。外部程序不参与合作锁，最终检查到 rename 的窄竞态不得宣称为绝对 CAS。UI 不再使用旧 `writeTextFile`；旧接口仍保留给非 UI 调用方并共用同一路径锁。

文件树通过 `IFileService.mutateWorkspaceEntry` 创建文件 / 目录、重命名、删除、复制和移动，细则见 `workspace-file-actions.md`。写接口必须落在对应工作区的文件服务通道，远程不得只靠路径。

## 负面边界

- 不把文件做成 Side Pane 的一种 tab，也不把 Monaco 塞进现有 `code-viewer` 预览里冒充可编辑。
- 不分屏、不做面包屑、不把 AI / 终端 / 搜索揉进文件工作台。
- 文件操作按 `workspace-file-actions.md` 扩展；不做文件拖拽移动或自动创建中间目录。
- 下拉不打开新工作区，不改全局当前工作区。
- 不把会话默认点文件改成跳进文件主视图。
- 不热更新正在编辑的缓冲；不在保存以外的时刻弹 Agent 冲突。
- 不把 instant-app 的虚拟文件系统、窗口系统、「打开方式」注册表搬进来。
- 不恢复设置覆盖层；文件主视图与设置一样是外壳档位，不是整窗遮罩。
- CLI/runtime 工具写文件的通道不变；UI 保存只通过 `IFileService.commitTextFile` 这一条写盘路径。
- 第一版不提供关闭预览标签模式的设置，不做多组编辑器各自一张预览。
- 不把 Monaco 接成项目 LSP：不解析工作区依赖、不跟 tsconfig references。
- 不把 `> 8 MiB` 文本整份读入可编辑缓冲、草稿 localStorage 或全文件缓存；大文件按固定块编辑，非法 UTF-8 块只读，未触碰字节由提交服务原样保留。见 `workspace-large-text-files.md`。
- 不把超过 8 MiB 的文件静默截断成完整可编辑文本；不在大文件冲突里把补丁强套到新版本；不在已保存文件路径消失时自动重建；远程断开时重试同一工作区通道，不回退到本机文件服务。

## 性能：冷启动恢复（2026-10-17）

隐藏的 `FilesWorkbenchSurface` 常驻挂载，但标签恢复不能因此扫描所有已打开文件。任务首屏只恢复标签元数据与脏草稿；正文从文件视图当前选中的标签开始按需读取。读盘完成只更新缓冲，不逐文件同步重写整份会话。

### 边界与状态所有者

- 打开标签、顺序、焦点、预览/固定状态及未保存草稿仍由窗口级 Files Editor Store 与其 localStorage 持久化独占。
- 磁盘正文仍以对应工作区的 Host `IFileService` 为准；不得在 Renderer 启动阶段预读所有正文。
- 任务/会话列表按现有任务索引与会话订阅流程加载；Files 恢复不能作为它们的前置条件。
- 文件标签的延迟正文状态属于 Files Editor Store，不复制进任务 Store，也不改变会话数据协议。

### 事件顺序

```text
应用启动 → 恢复标签元数据/脏草稿 → 任务与会话首屏独立显示
用户进入文件视图 → 显示恢复的标签 → 读取焦点文件
用户选中其它标签 → 读取该标签文件 → 更新对应缓冲
```

### 实施约束

- 恢复中的干净标签以轻量元数据显示路径、顺序、焦点和预览态；脏草稿正文直接恢复。
- 文件视图首次进入时只读取焦点文件；其它干净文件在用户选中时读取。重复请求幂等，读取串行执行。
- 恢复读盘不得阻塞任务列表、会话订阅或首屏绘制；读盘完成不触发整份会话持久化。
- 保留工作区 identity 隔离、脏草稿优先、预览替换/固定语义、读取失败可重试，以及现有 O(N) 标签消歧约束。

### 验收场景

| Case           | 初始状态 / 操作                                     | 结果                                                                                 |
| -------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 冷启动优先级   | localStorage 有大量干净标签与脏草稿；以任务视图启动 | 会话列表正常显示；Files 隐藏期间无 `file.readTextFile`；草稿仍在 Store 中可恢复      |

## 性能约束：标签栏渲染（2026-10-15 启动冻结修复）

恢复数百个打开文件时（实测 401 个），标签栏曾是启动主线程冻结 26 秒的来源
（cpuprofile：41% 采样在 `getPathLeaf`，11% 在尾斜杠正则）：

1. 工作区消歧必须按 title 分组一次算出（`resolveFilesWorkspaceDisambiguatedIds`，
   O(N)），禁止逐 tab 调 `needsFilesWorkspaceDisambiguation`（O(N²) 次
   `getPathLeaf` 正则）。语义保持一致：同一 title 出现 ≥2 个不同 workspace
   key 时，该 title 组内全部 tab 显示工作区后缀。
2. 单个 tab 是 memo 组件；`FilesWorkbenchSurface` 传给标签栏的 handler 必须是
   `useCallback` 稳定引用，不允许内联箭头击穿 memo。
3. 单个 tab 的重名判定结果（`disambiguate` 布尔）由父层一次计算后下发，
   tab 内不自算。

## 隐藏保活层的原生拖动隔离（2026-10-24）

- **隐藏表面不参与原生拖动区域计算。** 切到文件 / 设置后，下层保活的会话 Header、Side Pane、自动化 / 插件商店顶栏仍有布局盒。Chromium 按布局树顺序收集原生拖动矩形，忽略 `opacity`、`pointer-events`、`inert` 和 CSS 层叠；父节点的 `no-drag` 不能撤销后面遍历到的子节点 `drag`。外壳用统一 `window-drag-disabled` 边界，强制隐藏根节点及其所有后代为 `app-region: initial !important`，计算值回到初始 `none`，覆盖显式 drag 和内联非 important drag，完全不导出原生区域。这里不能用 `no-drag` 代替：它仍会导出扣除区域，可能清除其它活跃表面的拖动区域；也不直接写 `none`，该关键字会被 Chromium 映射为 `no-drag`。文件 / 任务保活层及收起侧栏共用该边界；恢复活跃后去掉边界，复用原有局部 drag 声明。不提高 Tab 的 z-index、不插入占位、不对每条 Header 分别复制活跃状态。

```text
主视图 / 侧栏显隐 → 外壳 window-drag-disabled 边界
  → 隐藏根及所有后代 computed app-region=none → 不参与原生区域计算
恢复可见 → 移除边界 → 复用原有局部 drag 声明
```

交互验收（真实 YCode 原生鼠标验证需要明确授权）：

先打开聊天 Header 与 Side Pane（含空态 / 有标签），或进入自动化 / 插件商店，再切到文件 / 设置：隐藏子树全部节点的 computed `app-region` 均为 `none`，包括显式及内联 drag；文件 Tab 可点击激活、关闭、中键关闭、键盘切换和 HTML 拖动排序。回到任务后 Header / Side Pane 恢复原有拖动；隐藏子树不会清除其它可见表面的左侧小块拖动区。必须验证最终 CSS 与布局树，不能只断言 Tab 自身含 no-drag 或 JS 回调可调用。
