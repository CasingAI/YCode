# Spec: 工作区「文件」主视图（资源管理器 + 编辑器）

## 目标

在左栏底栏增加第三档外壳主视图 **文件**。切到文件后：左栏是已打开工作区的文件树，右栏是可编辑的多标签工作台（文本用内嵌编辑器，图片 / PDF / Office / 媒体复用现有只读预览）。形态对齐 VS Code 的资源管理器 + 编辑区，而不是在右侧 Side Pane 里再塞一种 tab。

会话里点开文件的默认行为不变：仍在 Side Pane 只读预览。预览上另加「在文件视图中查看」，才切到本主视图。

## 已对齐决策

| 边界 | 决定 |
| --- | --- |
| 落点 | 第三档主视图 `files`，底栏为任务 / 文件 / 设置 / 更多 |
| 切走会话 | 与设置相同：会话、终端、Side Pane 保活、不卸、不画 |
| 写盘范围（第一版） | 打开已有文本并保存；允许新建。不做重命名、删除、拖拽移动 |
| 新建 | 只打开未命名标签；保存时才选路径 |
| 保存对话框默认目录 | 左栏下拉当前选中工作区的根；若从树发起新建且有选中文件夹，默认停在该文件夹 |
| 工作区下拉 | 顶部切换已打开工作区，只改左栏文件树；不改全局当前工作区；右栏标签可跨工作区混排 |
| 外部 / Agent 改盘 | 只在用户保存时查冲突，编辑过程中不弹冲突、不热更新缓冲 |
| 关脏标签 | 保存 / 不保存 / 取消 |
| 重启恢复 | 恢复打开路径 + 未保存草稿；启动再读盘；冲突仍只在保存时出现 |
| 非文本 | 文本进编辑器；图片 / PDF / Office / 媒体作为右栏一种只读预览标签 |
| 原「查看文件」叠层 | 并入本主视图：切到文件、选中对应工作区、必要时定位路径 |
| 会话点文件 | 默认仍 Side Pane 预览；另加「在文件视图中查看」 |
| 平台 | Desktop / Web / 远控远程工作区同一套打开、编辑、保存、新建 |
| 无项目 | 可以进入文件主视图，显示空态 |

## 产品规则

### 主视图身份

- 外壳主视图三档：`tasks` | `files` | `settings`。底栏第四格「更多」仍只是下拉，不是主视图。细则见 `workspace-shell-primary-tabs.md`、`workspace-shell-chrome-more.md`。
- **文件**：左栏为工作区下拉 + 该工作区文件树；右栏为编辑工作台。
- 切到文件时，任务树（会话列、底栏 Terminal、右侧 Side Pane）与设置正文都保活不卸，只是不画、不可点。切回任务时 `workspaceMainView` 保持进入文件前的值。
- 切到设置或任务时，文件工作台同样保活：已开标签、未保存缓冲、滚动与光标不得因切主视图而丢失。
- 无项目也可以进入文件主视图：下拉为空、树为空、右栏为空编辑区，不强制跳去设置。

### 左栏：工作区下拉 + 文件树

- 顶部下拉的候选项与任务栏里**已经打开的工作区 tab 同源**（含本地与远程）。不是「打开文件夹」对话框，也不在这里新开工作区。
- 选中哪一项，左栏文件树就显示哪一个工作区。切换**只改左栏列表**。
- 下拉不写全局当前工作区：会话所属工作区、Git、加到聊天的默认目标都不跟过去。
- 右栏已经打开的标签不受下拉影响，可以继续混排来自不同工作区的文件。
- 下拉上次选中按窗口记忆；再次进入文件主视图时恢复。若记忆项已从已打开列表消失，回退到列表第一项；列表为空则空态。
- 文件树复用现有工作区文件树能力（浏览、搜索、Git 状态、Reveal、加到聊天、本机资源管理器）。不再作为盖住任务列表的叠层。
- 任务行上的「查看文件」改为：切到文件主视图，下拉选中该工作区，若带路径则在树中定位。不另开一套叠层树。
- 不可用工作区仍可出现在下拉里；树展示既有不可用态，不可打开或保存。

### 右栏：编辑工作台

- 右栏是文件主视图自己的工作台，**不是** Side Pane tab。不与沙箱、子代理、计划、浏览器抢 Side Pane。
- 第一版只有**单组多标签**，不分屏，不做路径面包屑。
- 标签身份必须带工作区隔离 key 与路径：`workspaceIdentity?.trim() || workspacePath` + 文件路径。同一工作区同一路径重复打开只聚焦已有标签。
- 不同工作区的同一相对路径是两张标签，允许同时打开。
- 标签主文案是文件名；同名且来自不同工作区时，tooltip 或副文案带工作区名。
- **文本**：内嵌 Monaco 打开、编辑。工作台缓冲是正文的唯一权威；编辑器只是视图。用户输入写回缓冲；从缓冲程序化灌进编辑器时，不得再把这次灌入当作用户输入写回缓冲。换行符等规范化差异若形成来回改写，会把嵌套更新打到 React 上限，整块文件区被错误边界接管。
- **图片 / PDF / Office / 媒体**：同一条标签条里的只读预览，复用现有 Preview 能力，不塞进 Monaco。
- 未命名标签没有磁盘路径，保存成功后身份变成该路径的文件标签。

### 打开与新建

- 在树中点文本文件：在右栏打开或聚焦对应标签。
- 在树中点非文本：在右栏打开对应预览标签。
- 命令「新建」和文件树「新建文件」都只打开一张未命名标签，立刻不落盘。
- 未命名标签保存时弹出选路；默认目录：
  - 从树发起且当前有选中文件夹 → 该文件夹；
  - 否则 → 左栏下拉当前工作区根。
- 保存对话框只选已存在的目录；第一版不自动创建中间目录，也不做重命名 / 删除 / 拖拽。
- 允许多张未命名标签并存。
- Desktop、Web、远程工作区同一套行为；读、写都走该工作区的文件服务通道，远程必须带 `workspaceIdentity` 与 `remoteSessionId`，不得只按路径匹配。

### 保存、脏态、冲突

- 脏态：当前正文与上次成功保存（或首次打开时读到的）基准不同。预览标签、未改过的未命名空标签不算脏。
- 保存：先再读一次盘。若盘上内容既不等于基准、也不等于当前正文 → 冲突，不写。用户选「用编辑器覆盖」才强制写入，或选「用磁盘」丢弃缓冲并重载。
- Agent 或其它进程在编辑期间改盘：**不**弹横幅、**不**热更新缓冲。冲突只在这次保存时出现。
- 保存时路径已不存在：按保存路径重建文件。
- 关掉脏标签：保存 / 不保存 / 取消。保存失败或取消则标签仍在。
- 保存快捷键沿用系统惯例（macOS ⌘S，其它 Ctrl+S），只作用于文件主视图焦点标签。

### 会话预览与「在文件视图中查看」

- 会话、工具结果、消息链接里点文件：**默认仍打开右侧 Side Pane 的只读预览**（现有 `code-viewer`）。
- 该预览除「复制路径」外，增加「在文件视图中查看」：切到文件主视图，打开或聚焦对应标签（文本进编辑器，非文本进预览标签），左栏下拉切到该文件所属工作区并尽量在树中定位。下拉切换仍不改全局当前工作区。
- Side Pane 预览与文件工作台是两条表面，内容不互相自动同步；文件工作台里已脏的缓冲，不会因为 Side Pane 又打开同一路径而被覆盖。

### 恢复

- 按窗口持久化：打开中的文件路径（含工作区隔离 key）、未命名标签、脏草稿及其基准、焦点标签、左栏下拉选中。
- 冷启动先恢复草稿再读盘。读盘结果更新「当前磁盘」认知，但**不**在此时弹冲突；用户下次保存才按上面的规则比较。
- 超大草稿可只记路径、不落正文；恢复后按盘上内容打开，并视为未脏。

### 窄屏

- 切任务 / 文件 / 设置不收起抽屉，与 `workspace-shell-responsive-layout.md` 一致。
- 下拉换工作区不收起抽屉。
- 在树中点开一个文件（目标是右栏工作台）后收起抽屉。
- 「在文件视图中查看」从会话触发时：切到文件主视图；若当时是抽屉盖着正文，收起抽屉以便看见编辑区。

### Web 路由

- Web 地址栏增加 `/files`，表示文件主视图。刷新停在文件。
- 工作区下拉选中、打开了哪些标签**不进 URL**（与「workspace 不进 URL」一致）。见 `web-url-routing.md`。

## 状态所有者

| 状态 | 所有者 | 说明 |
| --- | --- | --- |
| 任务 / 文件 / 设置 | 扩展现有 `tabStore` 主视图投影 | 今天是设置 tab 激活态 vs 工作区 tab。增加 `files` 身份，仍只此一个权威，不另做覆盖层 |
| 左栏下拉选中的工作区 | 文件主视图自己的偏好 | 只驱动文件树；与 `tabStore` 当前工作区 tab、会话 `activeTaskId` 隔离 |
| 文件树展开 / 监听 | 现有 `WorkspaceFileTree` 与文件监听服务 | 按树正在显示的那个工作区 |
| 打开标签、正文、基准、焦点 | 文件工作台状态（按窗口） | 缓冲表与标签条分离：缓冲按「工作区 key + 路径」记正文；标签条记打开顺序与焦点。未命名标签有自己的缓冲 id |
| 磁盘内容 | Host `IFileService`（需补通用写文本） | UI 不直打文件系统；远程走同一通道 |
| 会话 Side Pane 预览 | 现有 `useAppPanels` / `code-viewer` | 默认点文件仍走这里 |

```
用户点底栏「文件」
  → 主视图投影为 files
       ├─ 左：下拉（已打开工作区）+ 当前项的文件树
       └─ 右：编辑工作台（保活的任务树在下层，不画、不可点）

用户在下拉中另选工作区
  → 只换左栏树
  → 不改当前会话工作区，不关右栏标签

用户在树中点文件
  → 已有相同（工作区 key, 路径）标签则聚焦，否则读盘建缓冲并开标签
  → 文本挂编辑器；非文本挂预览

用户新建
  → 只加未命名缓冲 + 标签，不写盘

用户保存
  → 未命名则选路（默认目录见上）
  → 再读盘；冲突则停写并让用户选覆盖或用磁盘
  → 成功后基准 = 当前正文

会话里点文件
  → 仍 open code-viewer Side Pane
  → 点「在文件视图中查看」才走文件主视图打开/聚焦
```

## 文件服务缺口（第一版必须补）

现有文件服务能列目录、读文本/媒体、搜索、监听，以及读写 `.zcodeignore`。通用写盘没有。

第一版需要：按路径写文本（覆盖或新建文件）。不包含重命名、删除、建目录、移动。写接口必须带工作区作用域，远程不得只靠路径。

## 负面边界

- 不把文件做成 Side Pane 的一种 tab，也不把 Monaco 塞进现有 `code-viewer` 预览里冒充可编辑。
- 不分屏、不做面包屑、不把 AI / 终端 / 搜索揉进文件工作台。
- 第一版不做重命名、删除、拖拽、自动建中间目录。
- 下拉不打开新工作区，不改全局当前工作区。
- 不把会话默认点文件改成跳进文件主视图。
- 不热更新正在编辑的缓冲；不在保存以外的时刻弹 Agent 冲突。
- 不把 instant-app 的虚拟文件系统、窗口系统、「打开方式」注册表搬进来。
- 不恢复设置覆盖层；文件主视图与设置一样是外壳档位，不是整窗遮罩。
- CLI/runtime 工具写文件的通道不变；本需求只加 UI 保存这一条写盘入口。

## 验收场景

1. 宽屏有两个已打开工作区：底栏可切到文件；左栏下拉能选到这两个；选 B 只换树，右栏里从 A 打开的标签仍在；会话仍属于原来的工作区。
2. 在树中打开文本、编辑、⌘S/Ctrl+S 写回；关脏标签出现保存 / 不保存 / 取消。
3. 新建（命令或树）只出现未命名标签；保存对话框默认目录为当前下拉工作区根（树里选中了文件夹则为该文件夹）；保存后标签变成该路径。
4. 打开图片 / PDF：右栏是预览标签，不是编辑器。
5. 任务行「查看文件」切到文件主视图并选中该工作区，不再叠层盖住任务列表。
6. 会话点文件仍开 Side Pane 预览；预览上「在文件视图中查看」切到文件主视图并打开同一路径。
7. 切文件 → 设置 → 任务：会话滚动位置仍在，文件未保存缓冲仍在。
8. 无项目可进文件主视图，看到空态；任务项仍不可用。
9. 窄屏：切到文件不关抽屉；点开一个文件后抽屉关、看见编辑区。
10. Web 访问 `/files` 停在文件主视图；下拉选中不出现在地址栏。
11. 远程工作区打开与保存带身份隔离；仅路径相同的另一个工作区不会读串或写串。
12. 编辑器有未保存内容时 Agent 改了同一文件：编辑过程无提示；点保存才出现冲突，选覆盖或用磁盘。
13. 重启后恢复未保存草稿与打开路径；启动时不弹冲突。
14. `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 通过（实现阶段）。
