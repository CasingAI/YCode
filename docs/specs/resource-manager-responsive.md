# 资源管理器的窄屏布局与能力展示

## 产品规则

- 采用「概览优先」布局。小于 768px 时，标题与刷新设置为第一行，指标页签单独一行；正文按当前指标概览、趋势、进程分组的顺序排列，使用一个纵向滚动区域。
- 宽屏保留指标卡、进程列表与底部固定概览的结构。窄屏概览进入正文，不保留占据视口高度的固定三栏底栏，不靠缩小字体或裁切页面解决溢出。
- 宽屏进程分组保持内容自然高度，不参与父级 flex 收缩；进程分组区域仅由父级进程列表 section 负责纵向滚动，固定底栏始终位于滚动区域之外。分组卡片不得因列表高度不足而被压缩或裁切内部进程行。
- CPU、内存页仍展示宿主整机与 YCode 进程树的占用。页头明确说明数据来自宿主，不能让手机用户误认为是手机自身的资源。
- 磁盘 I/O 页签仅在平台提供 getDiskIoSnapshot 时出现。初始页签不可用或能力消失时，呈现 CPU 页；能力缺失不是采样失败，不显示整页红色故障或伪造的 0。
- 窄屏进程行主行显示名称与当前指标，PID 与来源会话进入次行；长名称或会话允许换行，信息不依赖 hover。宽屏继续显示独立 PID 与指标列。分组计数、归属与展开操作保持原语义。
- 磁盘 I/O 有能力时也必须支持窄屏：统计卡自适应列数，来源明细使用可展开摘要，宽屏保留表格。无快照时显示占位或明确状态，不能把缺失数据解释成真实零使用。
- 所有界面文字使用现有 text-ui-\* 标尺、主题语义色和中英文本地化；触屏主要交互保留至少 44px 的命中高度。

## 所有权、接口与时序

    现有宿主采样 owner
      → 既有 getSnapshot / getDiskIoSnapshot
      → ResourceManagerApp / DiskIoTab 的唯一快照与历史
      → 指标概览、趋势和进程行（随屏宽重新排版）

    刷新选择 → ResourceManagerApp 的周期偏好 → 既有串行轮询
    分组操作 → ResourceManagerApp 的 expanded → 进程列表投影
    磁盘接口存在性 → 可见页签 / 有效选中页签（纯派生）

- 不增加服务、协议、订阅、采样器、持久化字段或第二份快照。
- ResourceManagerOverviewFooter 仍为纯展示组件。窄屏摘要通过展示 slot 注入，与宽屏使用同一份快照；重排不新增轮询。
- CSS 负责屏宽变化，不将断点写入业务状态，不改变 Host owner、lease、workspace identity 或 Desktop continuous / Web replayable 链路。
- 已有请求失败处理、串行请求保护、卸载取消与刷新周期保存语义保持；本轮不补齐 Server 磁盘遥测。

## 验收与验证

1. Web 只有 CPU / 内存能力时不渲染 I/O 页签；指定不支持的初始 I/O 页签也能落到 CPU。Desktop 提供磁盘接口时三页签均可用。
2. 360 / 390 / 430px 下，中文与英文页头、选择器、页签、图表与进程列表不产生页面级横向滚动；增加 UI 字号后仍能换行。
3. 窄屏从顶部向下依次为概览、趋势、进程分组，正文只纵向滚动；宽屏概览栏处于滚动区域之外，进程分组区域仅由父级进程列表 section 负责纵向滚动，分组保持自然高度，不被 flex 收缩裁切。
4. 切换 CPU / 内存、修改刷新周期、折叠分组与查看完整来源时，统计口径与原有状态一致；进程总数不随折叠或屏宽改变。
5. 含很长进程名、长会话名和无会话来源的进程都可阅读，未采样行使用 — 和既有采样说明。
6. 磁盘来源明细在窄屏可以展开查看原表格的读写量、操作数、耗时、失败与 OS I/O 等信息；无能力时不出现伪造数据面板。
7. 展开包含多个进程的分组使内容超过进程列表高度时，宽屏能滚动到该分组最后一行；折叠后重新展开，滚动范围恢复且仍能到达最后一行。窄屏保持同一纵向滚动路径，不新增第二层滚动。

自动化验证覆盖能力页签、渲染信息与统计口径，并执行相关现有测试、pnpm typecheck、pnpm lint、格式检查和架构检查。

GUI E2E 场景为第 2–7 项，需分别检查手机 Web 与桌面/宽屏，覆盖 Zai Light / Dark 与中英文。仓库禁止未经明确授权使用 UI 自动化操作 YCode；未获授权时只执行可用的非 GUI 验证，明确记录未执行的 GUI E2E，不将其记作通过。
