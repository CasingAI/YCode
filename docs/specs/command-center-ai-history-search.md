# Spec: 命令中心一次性 AI 会话搜索（Command Center One-Shot AI History Search）

命令中心（`packages/ui/src/command-center/CommandCenterDialog.tsx`）在保留关键词搜索的同时，
增加一次性自然语言历史搜索：问一句，得到归纳答案 + 可跳转的会话引用。底层仍走 History
三件套的模型回合，但用隐藏一次性会话承接——不换掉当前对话、不进侧栏任务列表、
不占用当前对话的排队闸门。

## 入口与形态

- 入口：现有命令中心搜索浮层，不另做独立页、不新开窗口、不进侧栏、不换成完整聊天页。
- 形态：问一句，得到归纳答案 + 可跳转的会话引用；浮层内不追问。
- 关键词搜索保留；AI 搜索是显式动作，不跟随每个按键自动开火。
- 作用域是当前聚焦工作区的会话存档（含归档）。命令中心关键词任务搜索可以跨已打开
  工作区；AI 搜索不跨远端/多个 Host 扇出，避免一次运行读到另一套存档。

## 一次性语义

- 每次发起 = 一次独立运行。改搜索框里的字 = 取消当前运行（若还在跑），回到结果列表，
  AI 项按新查询更新，关键词结果照常刷新。这不是追问，是一次新的搜索意图。
- 关浮层不取消不回收：运行中关掉重开，回到回答态看进度（查询框恢复上次查询）；
  完成后关掉重开，直接看答案与来源，不重新发起。改字才开始新意图，跳转来源
  后才真正关闭回收。
- 不在侧栏、任务列表、命令中心关键词结果里露出这次运行。
- 不打断当前正在跑的对话（独立排队闸门）。
- 浮层内多轮追问、把搜索转正成正式任务：不做。
- 用 TaskIndex 的关键词结果冒充 AI：不做。新全文索引：不建。

## 隐藏会话所有者

唯一所有者是 Host/CLI 侧的隐藏一次性会话机制：

- 新的会话任务类型 `ai_history_search`（见 `SESSION_TASK_TYPES`），不进入
  `task-list-session-membership.ts` 的侧栏可见类型（今天只有普通交互、fork、
  workflow 父任务进列表）。不要复用框选副屏（副屏依赖父会话、会占侧栏旁路，
  语义不对），也不要用草稿首发（草稿一旦发出第一条会提升成正式任务）。
- 独立排队闸门，不占用当前对话的忙闲。
- 工具面只开放 History 三件套；只读档开启，模型就算想改文件也走不通。因此隐藏会话的扫描自动走 History 三件套的只读旁路（见 `docs/specs/session-history-tools.md`），不另开扫描入口、不另做第二套检索实现。`cancelAiHistorySearch` 仍靠现有回合取消把工具 `abortSignal` 传到旁路（终止工作线程并关连接），不改协议形状。
- 专用系统说明：只查历史、用工具坐标引用、用用户语言回答；一轮内可多次调用工具。
- History 列表/搜索默认排除这类隐藏会话（对齐现在默认藏子代理会话），避免搜到
  搜索过程自己。实现上以后缀/任务类型双重过滤：id 前缀 `sess_ai_search_` + taskType 检查。
- 回合收口后 CLI 侧删除会话（终态帧先刷出再删，浮层至少能看到一次
  sessionEnded）；UI 侧保留最后快照供浮层展示最终答案与来源。
  取消、改字/新搜索、卸载时回收 UI 租约；关浮层不回收——运行中继续跑，
  重开浮层看进度，完成后重开直接看答案。Host 断开时删除该会话。
  允许内存态、重启即消失，不要求进任务索引。
  服务/UI 不把这次运行写入 tasks-index。
- 模型意图沿用当前工作区上次选用：浮层不另开选择器；UI 在 `startAiHistorySearch`
  载荷里带上发起时工作区的当前模型意图，CLI 把它落到隐藏会话再跑这一轮。当前意图 =
  工作区**最后展示的模型意图**（`readComposerDisplayedModel`，见
  `docs/specs/composer-displayed-model.md`），有两种互斥形态：具体 `selection` 或
  `modelGroupIntent`（组 ID + 组名快照）。优先级为 displayed 具体 → displayed 组 →
  `readComposerRecent` 具体 → `readComposerRecent` 组（既有最近提交偏好，行为不变）；
  均缺失才退回目录的 `preferredSelection` / CLI 配置默认。displayed 是组意图时，
  UI 不查具体兜底、不在 UI 选成员，直接下发 `modelGroupIntent`，由 CLI 在
  admission 权威选成员；displayed 是具体模型时沿用原路径：当 input 传给模型服务
  视图解析出的 `effectiveSelection`，再按最低成本档位下发 `model`。
  原因：不带 input 的 `getView()` 本来就没有 `effectiveSelection`，只有目录 +
  `preferredSelection`；CLI 是另一个进程，读不到 UI 进程的模型目录，唯一可用
  事实源是 UI 侧该工作区的模型服务，单向随命令下发，不反向回查。组意图不需要
  UI 进程目录就能下发，成员裁决本来就属于 CLI。
- 组意图的权威裁决与失败：CLI 用现有组 admission（同一份个人配置与目录）选出实际
  成员，按该成员支持档位的最低成本项启动；组已删除、为空、全部不可用或已停用时不
  回落旧/default，ACK `status=failed`，`reasonCode` 为 `modelGroup.deleted` /
  `modelGroup.noMembers`，`message` 用当前名或组名快照。浮层只透传 ACK 的
  `message` 报错，不在 UI 侧重试或改选成员。
- 搜索只用最低成本档位：具体模型身份（provider/model）沿用当前选择，但思考档位
  （`reasoningLevel`）在下发前压到该模型档位表的最低成本项——档位表含关闭语义值
  （`off`/`disabled`/`none`/`no-think` 等，不分大小写）时用关闭值，否则用档位表
  第一项（配置声明顺序为低→高）。组意图不带档位，档位由 CLI 按被选成员的档位表
  同规则压低。副文案显示的必须是同一份输入解析出的同一份选择，保证显示即所用。
  原因：搜索是只读归纳，不值得烧高思考档位；压低只影响本轮隐藏会话的下发载荷，
  不改用户工作区的当前选择与 recent。

```text
input → HiddenSearchRun（唯一 owner）→ 一次 turn → 结构化回答+引用
                                    └── 关闭/取消/改字 → 删除会话（无残留）
```

## 协议

- 新增一条工作区级一次性命令 `startAiHistorySearch`，由 Host/CLI 内部创建隐藏会话、
  跑一轮、对外只流式回答与引用。不要让浮层自己拼「创建会话 → 发文本 → 再删」：
  那条路径容易漏进侧栏。
- 载荷：`{ workspaceId, query, language?, model?, modelGroupIntent? }`。`model` 与
  `modelGroupIntent` 互斥（严格 runtime 校验：同时出现即拒绝），两者都缺席是合法的
  旧行为（CLI 配置默认）。成功 ACK 的 `result` 仍是
  `{ type: "startAiHistorySearch", sessionId }`，浮层投影与取消协议不变。组意图的
  成员选择、档位压低与失败码由 CLI 权威裁决，UI 不在本地把组展开成成员。
- 路由跟现有工作区会话命令同一条：桌面持续链路与远端可回放链路都打到该工作区的
  Host，不能只按本地路径猜。无可用运行时则浮层明确失败，不降级成关键词搜索冒充 AI。
- 浮层用现有对话投影订阅这份隐藏会话，但只渲染回答与引用，不挂完整会话页。
- 取消命令 `cancelAiHistorySearch`：关浮层 / Esc / 改字时中止运行并回收会话。

delivery 边界：

```text
desktop: continuous ── direct live stream ──┐
                                           ├─ same owner and sequence
mobile: replayable ─ snapshot + gap repair ┘
```

## UI 呈现

还是现在这个顶部搜索浮层：圆角卡片、顶栏搜索框、下面范围标签、再下面可滚动列表。
浮层有两种内容态：结果列表（现在这样）和 AI 回答区。搜索框始终留在顶上。

### 结果列表里怎么出现

输入不为空时，列表最上面多一项，和任务/文件行同一套列表样式，不要做成第五个范围标签。

- 主文案：用 AI 搜索。不复述搜索框里的查询——查询就在输入框里，复述一遍是废话。
- 副文案：当前工作区的**模型意图**。具体模型时显示「模型名 + 思考等级」
  （如「Deepseek V4.1 Flash · 高」），取与发起时下发给 CLI 的同一份模型视图，
  让用户在按回车前就知道这一轮会用哪个模型跑。模型名用
  `formatModelDisplayName`，思考等级查思考控件同一张档位词表
  （`thoughtLevelLabelId`），不得直接显示规范值。displayed 是模型组意图时**只显示
  组名**（当前视图名优先，组不在视图时用 `groupNameSnapshot`），不猜成员、不猜
  档位，也不附加“自动选择”等冗余说明。模型视图未就绪（loading / error /
  unavailable）且具体意图无效时，退回静态文案「查阅对话历史并归纳」。
  原因：命令中心是浮层，浮层开着时用户够不到工作区的模型切换器，模型在浮层打开那一刻就
  定死了；用户改不了它，那"会拿哪个跑"只能在发起前告知，事后显示没有决策价值。
- 右侧可带快捷键提示（回车，当它被高亮时）

显示模型只是告知，不在浮层内提供切换入口（见「明确不做」）。

它排在关键词分区之前。有查询时 cmdk 默认高亮第一项，所以这时回车就是发起 AI 搜索；
方向键往下才是原来的任务/文件/操作命中。空查询不出现这一项，打开浮层的默认近期列表不变。
没有关键词命中时，不要只显示「暂无相关结果」：只要查询非空，AI 这一项仍然在，
空状态退到它下面。

### 点下去之后：回答区

列表换成回答区，浮层外壳和宽度不变，高度仍受现有上限约束，内容在内部滚动。
范围标签进入回答态后收起或淡出，避免还以为在筛关键词。

回答区从上到下：

1. 加载态只在输入框右侧（两行过程区不再放 spinner）：
   - 第一行是模型最新一条正文的单行预览：运行前显示安静的「正在查阅历史…」占位；
     模型一旦输出文字，改显示最新一条正文的首行（中间态，正常）；只占一行，超出省略。
     左侧图标语义：运行中是安静的圆点占位（不转），完成后换星星。
   - 输入框右侧的加载圈是唯一的运行指示：关键词防抖/任务/文件查询 loading 之外，
     AI 搜索运行中（`aiAnswerOpen && status === "running"`）也常亮，回合收口成功或
     失败（`done` / `failed`，由投影 control.sessionEnded / phase=error 驱动，
     不是 ACK accepted）后熄灭。之前 status 只有 idle/running/failed 三态且完成时
     不流转，ACK 成功后 status 永远 running，圈一直转到天荒地老。
   - 第二行是当前工具调用：显示模型正在执行的最后一次工具调用，
     复用正常聊天工具行的同一套折叠行布局（History 三工具的 kind 文案 +
     摘要 helpers 与聊天卡同实现），只读不展开。
   - 运行中过程区常驻（过程可看）；回合收口后过程区整体隐藏（见下），不闪烁消失。
   - 失败语义拆两处：运行失败（ACK rejected / 命令异常 / 启动失败）时第一行换成一句
     可操作的错误，可再点列表里那一项重试；回合失败（turn 收口 phase=error，
     服务端文案进投影 lastError）时第一行换成服务端失败文案 + 重试入口。
2. 归纳正文：仅在回合完成后出现，默认收起的一行入口，点击手动展开看
   最后一条完成消息（最终答案）。展开后用与正常聊天同一套 Markdown 渲染
   （`MessageResponse`），按普通助手文本密度排，不是聊天气泡，也没有输入框。
   运行中不存在「最后一条」的概念，因此不展示该入口；也不展示历史中间
   操作的完整过程（工具只保留第二行的摘要行）。
   收口后过程区（含 Esc 取消按钮）整体隐藏：第一行预览是未渲染的 Markdown
   中间态（`## 结论…**没有字面命中**` 这类记号原样露出），完成后继续摆在
   上面会跟下面的渲染正文打架、还让人以为任务没跑完。失败时过程区保留
   （第一行是错误文案 + 重试入口）。
3. 来源列表（仅在回合完成后出现，默认展开）：回答下方单独一块「来源」，每一行与普通关键词搜索的
   任务行统一为同一套列表样式（`quickPickItemClassName` + 同一套标题/片段/
   时间徽标布局）：标题 + 一段原文摘录 + 相对时间。点击后关掉浮层，跳到该会话
   并按摘录高亮——和现在点关键词任务行一样。来源从模型正文的会话引用指令抽取
   （docs/specs/assistant-session-citation.md），经存在性校验（引用指向真实存在
   的会话才进列表）；不存在会话的引用（模型编造）与无原文片段的引用不进列表。回答区正文同样把引用指令
   投影成可点芯片，点击与来源行同一跳转。

不展示 History 工具的完整工具卡、权限条、Composer、模型切换。运行中可 Esc 取消；
关浮层不取消不回收（运行继续、结果保留）；改字 / 跳转来源 / 卸载时才回收。

### 侧栏入口的后台指示

关浮层后搜索在后台继续跑，侧栏的命令中心入口按钮要让人知道这件事，
与任务行「运行中转圈、完成后蓝点」同一套语义：

- 后台运行中（浮层关闭且 status 为 running）：入口的搜索图标换成转圈，
  与任务行运行中的 spinner 同样式（`animate-spin`）。
- 后台已收口（浮层关闭且 status 为 done）：入口右侧快捷键标签旁多一个
  蓝色圆点（`h-1.5 w-1.5 rounded-full bg-sky-500 dark:bg-sky-400`），
  与任务行未读圆点同样式，表示「有没看的搜索结果」。
- 打开浮层即视为已读：蓝点熄灭（回到回答态看答案）。
- 新一轮发起 / 改字 / 跳转回收时，指示随 status 复位。
- 状态经 zustand 小 store 按 workspaceKey 广播（Dialog 写、侧栏读），
  不经 App / WorkspaceShellLayout 逐层透传 props。

### 回答之后怎么回去

改搜索框里的字：取消当前运行（若还在跑），回到结果列表，AI 项按新查询更新，
关键词结果照常刷新。这不是追问，是一次新的搜索意图。

关浮层再打开：回到回答态——查询框恢复上次发起的查询，运行中看进度条与工具行，
已完成直接看归纳正文与来源，不重新发起。浮层关闭期间订阅不断（租约由 Dialog
持有，Dialog 常驻 App 层不随 open 卸载），CLI 侧收口后删会话不影响 UI 已有快照。

点来源跳走后，浮层关闭并回收本次运行，当前工作区切到目标任务；
当前正在跑的对话不被这次搜索打断。

```text
空查询     → 近期任务 / 变更 / 操作（现状）
有查询     → [用 AI 搜索「…」] + 关键词分区
发起 AI    → 运行中：过程两行（正文预览+工具行）+ 输入框右侧加载圈
收口成功   → 过程区隐藏：折叠正文 + 来源行（Esc 同步隐藏）
改字 / Esc → 回到列表或关闭并回收
点来源     → 关浮层，跳转会话并高亮
```

## 失败语义

- 无可用运行时（未连接 Host）：浮层明确失败提示，不误创建可见任务。
- 运行失败：回答区状态行换成可操作的错误文案，保留重试入口（再点列表 AI 项）。
- 组已删除 / 为空 / 无可用成员 / 停用：CLI 拒绝，浮层展示 ACK `message`；不回落
  旧具体模型、不改写成默认、不静默降级成其他组。
- 取消（Esc / 改字 / 关浮层）：中止运行并回收会话，无残留任务，不报错。

## 明确不做

- 浮层内多轮追问、把搜索转正成正式任务。
- 用 TaskIndex 的关键词结果冒充 AI。
- 新建全文索引。
- 跨多个远端 Host 一次搜完。
- 给 History 工具单独做工具卡。
- 模型选择器（沿用发起时工作区当前模型，见「隐藏会话所有者」）。

## 验收场景

1. 当前对话正在运行时发起 AI 搜索：当前对话继续，搜索在浮层进行。
2. 搜完侧栏任务数不变；关键词搜索也搜不到这次隐藏运行。
3. 自然语言问「上次改鉴权的结论」：回答里有可点击引用，点进对应会话并高亮片段。
4. 关浮层或取消：运行停止，无残留任务。
5. 运行时不可用（未连接 Host）：浮层失败提示，不误创建可见任务。
6. 有查询时列表第一项为「用 AI 搜索」；默认高亮时回车发起 AI 搜索。
   空查询打开浮层仍是近期列表，无此项。
7. 点来源关闭浮层并跳转高亮；改搜索框回到结果列表，不把它当成追问。
8. 前台 Composer 最后展示的是模型组 G：副文案只显示组名（当前视图名优先名快照），
   发起载荷只带 `modelGroupIntent`，不带 `model`，UI 不查具体兜底。
9. 记录中的组已删除 / 无可用成员：CLI 拒绝并返回 `modelGroup.deleted` /
   `modelGroup.noMembers`，浮层展示 `message`，不回落旧具体/default。
10. 最近一次发送偏好是具体模型 A、最后展示的是组 G：命令中心使用 G，而不是 A。
    没有 displayed 记录时才使用 recent 的具体/组意图。
