# Spec: Markdown 折叠块连续分组

## 目标

Markdown 正文里的 `<details>` 折叠块渲染成卡片。回答里经常连续给出多个折叠块（例如「根因链路 / 改了哪些地方 / 验证结果」这类分节），它们表达的是同一件事的若干侧面，应当被读成一张卡片，而不是若干张互不相干的卡片。

本 spec 规定：连续的折叠块合并成一个连续组件——整组只有一条外轮廓，块与块之间只有一条分隔线，不再各自留白、各自圆角。

## 产品规则

### 连续判定

- 「连续」指两个折叠块在渲染结果里是相邻的同级兄弟元素，中间没有其他块级内容。
- 判定只看渲染后的 DOM 相邻关系，不看 Markdown 源码里的空行数量：中间隔一个空行、隔一行普通段落，只要最终没有其他块插在两者之间，仍然是连续的。
- 中间出现任何其他块级内容（段落、列表、代码块、引用）即打断连续性。被打断的折叠块各自成组，前后两组互不影响。
- 折叠块嵌套在别的折叠块正文里时，只在同一层级内判定连续：外层折叠块与它正文里紧邻的折叠块不是同级兄弟，不合并。

### 视觉合并

一组连续折叠块渲染成一张卡片：

- 整组只有一条外轮廓：左边框、右边框连续贯穿全组，组内块之间没有竖向断裂。
- 组内相邻两块之间只有一条 1px 分隔线，不出现双线，也不出现上下留白。
- 圆角只出现在整组的外侧：组首保留上圆角，组尾保留下圆角，组内块的上下圆角都去掉。
- 组内块与组外相邻内容之间的间距沿用正文既有的块间距，不因为合并而改变。

### 分组边界

- 组的上下外边距与单个折叠块一致，合并不改变该块在正文里的占位。
- 展开任意一块只影响该块正文高度，不影响同组其他块的分组关系与边框。
- 折叠块的展开状态仍然由每个块自己持有，合并只发生在视觉层，不引入跨块的共享状态。

## 状态所有者与不变式

- 折叠块的展开状态所有者不变：`MarkdownDetails` 内部的 `expanded` state，仍是唯一来源；合并规则不引入新的状态、事件或订阅。
- 「是否连续」的所有者是渲染出的 DOM 结构，由 CSS 相邻兄弟选择器表达；Markdown 解析层、流式分块逻辑不感知分组，也不新增分组标记。
- 不变式：分组只影响边框、圆角与外边距，不改变折叠块的内容、顺序、可访问性属性与交互语义。

## 接口

- `packages/ui/src/components/ai-elements/markdown-details.tsx`
  - 折叠卡根节点新增 `data-slot="markdown-details"`，作为分组样式的选择器锚点。
- `packages/ui/src/styles.css`
  - 承载「连续折叠块合并为一个组件」的相邻兄弟规则；规则不进 Tailwind 的 cascade layer，优先级高于折叠卡自身的 `my-4` / `border` / `rounded-xl`。
  - 放在全局样式表而不是组件内 CSS 文件：组件内 CSS 会被测试运行器当作 ESM 加载而报错，折叠块的渲染测试需要直接引用该组件。
- 无协议、持久化、远程恢复或跨模块接口变化。

## 验收场景

1. 正文里连续出现两个 `<details>`：两块之间没有空隙，上下边缘对齐为一张卡片，块间只有一条分隔线。
2. 连续出现三个 `<details>`：整组只有一条外轮廓，组首有上圆角、组尾有下圆角，中间块四个角都是直角。
3. 两个 `<details>` 中间插入一段普通文字：两块各自成组，恢复成两张独立卡片。
4. 展开组内中间的一块：该块正文展开，其余块位置与边框不变，整组仍是一张卡片。
5. 流式输出时折叠块逐块到达：已到达的相邻折叠块立即合并成一张卡片，不出现先分后合的跳动。
6. 折叠块前后有其他内容时，该块与相邻内容的间距与合并前一致。

## 负面边界

- 不改折叠块的内容渲染、默认收起行为与 `open` 初始状态语义。
- 不改折叠块头部按钮的交互与时间线折叠触发器槽位。
- 不引入跨块的联动展开/收起，也不做分组级动画。
- 不改 Markdown 解析与流式分块逻辑。
- 不改 i18n 文案。
