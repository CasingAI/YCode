# 使用系统对话框选择文件位置

## 产品规则与范围

- 文件工作台的「另存为」保留内置目录浏览与文件名输入，并提供「使用系统对话框」按钮。点击即打开宿主操作系统的另存为组件，不新增全局设置或持久化偏好。
- 仅在目标属于当前 Desktop 本机、平台声明可返回本机绝对路径且提供原生保存选路方法时显示按钮。Web、手机远控、SSH / WSL / Docker 等远程工作区、旧 preload 缺少该能力时不显示，继续使用现有内置浏览器。
- 「保存」、未命名文件保存、标签右键「另存为」、菜单与快捷键以及全部保存遇到选路时，共用同一 `FilesSaveAsDialog`，不单独维护入口。
- 其他文件 / 文件夹位置选择沿用同一平台接口规则。已使用原生选择器的打开工作区、设置目录、SSH 私钥、附件和导出入口不再叠一层自定义选择器。服务端或远程目录浏览不能使用当前客户端的系统对话框。本次不改变下载、导出内容或文件树新建 / 改名语义。
- 系统对话框以当前目录和当前文件名作为默认路径，标题使用应用当前语言；用户可以在系统组件中改名、选择位置，创建目录和覆盖确认由系统组件负责。内置目录浏览仍只进入已存在的目录。

## 唯一所有者与边界

- `useFilesWorkbenchController.saveAsBufferId` 拥有另存为目标。弹窗拥有当前目录、文件名、原生请求中状态和错误；这些都是临时 UI 状态，不写入文件工作台 Store 或持久化。
- `filesWorkspaceFileService` 统一判定本地 / 远程目标，使用 `workspaceIdentity?.trim() || workspacePath` 匹配工作区，并检查工作区及对应标签的 remote session；原生选路的准入和实际文件服务解析复用这一规则。不能根据路径长相或是否存在 Electron 判断目标主机。
- UI 通过 `usePlatform` / `useOptionalPlatform` 消费 `IPlatformService`，不直接调用 `window.zcode`。Desktop renderer、preload 和 typed IPC 转发到 Electron main。
- 新增可选 `IPlatformService.showSaveDialog(options?)`，只返回本机绝对路径或 `null`，不写入文件。`NativePathDialogOptions` 只包含可选 `defaultPath`、`title`。既有目录、单文件和多文件选择方法接受同一可选参数；无参数调用保持兼容。
- Electron main 负责展示原生组件，以发起请求的窗口为父窗口，校验参数类型和字符串边界，取消返回 `null`（多选返回空数组），不得记录用户路径或文件内容。Main 不保存工作区或会话状态。
- 现有 `saveFile` 继续负责导出时的原生选路与字节写入；文件工作台不能用它替代 `saveTextBuffer`，避免绕过工作区归属、保存冲突、错误提示和缓冲更新。
- 原生确认后只调用现有 `onConfirm(path)`，仍由 `saveTextBuffer(buffer, { path, force: true })` 和该工作区的 `IFileService` 执行保存，不新增磁盘写入或远程请求路径。Desktop continuous 与 Web / 手机 replayable 链路不变。

## 异步与失败语义

- 一个另存为目标至多有一个原生选择请求；请求期间禁用重复触发与会改变该请求目标的确认操作。
- 原生取消不等于取消另存为：保留原弹窗的目录和文件名，不调用 `onCancel`，不写盘，不停止全部保存或待续接的关闭流程。
- 原生调用失败时保留原弹窗，显示当前语言的失败提示并允许继续内置保存或重试；不静默确认，不清除脏态。
- 弹窗关闭、卸载、更换缓冲 / 工作区 / 文件服务后，未完成的原生请求失效。迟到路径和错误都不得确认或覆盖新的选择目标，不用超时处理竞态。目录读取也不能用过期结果覆盖当前弹窗。

```text
当前另存为目标（controller.saveAsBufferId）
  → 文件工作区目标判定（唯一的本地 / 远程规则）
    ├─ Desktop 本机 + 平台能力 → 使用系统对话框
    │   → 弹窗创建当前目标的请求标识 → IPlatformService.showSaveDialog
    │   → preload / typed IPC → Electron main → 系统另存为组件
    │   ← 本机路径 / null / 失败
    │   → 核对请求仍属于当前打开目标
    │      ├─ 取消 / 失败 → 保留原弹窗和保存队列
    │      └─ 有效路径 → 现有 onConfirm → controller.saveTextBuffer
    │          → 当前工作区 IFileService → 更新原缓冲 / 基准 / 持久化
    └─ Web / 手机 / 远程 / 缺少能力 → 仅内置目录浏览
关闭 / 卸载 / 更换目标 → 使请求失效 → 迟到结果不提交
```

## 验收场景

自动化回归：

1. 本地 Desktop 显示「使用系统对话框」，Web、缺少方法、远程 identity / session、仅工作区标签标记远程时均不显示；远程文件服务不接收原生路径。
2. 默认路径覆盖 Windows 盘符、根目录、反斜杠与 POSIX 路径；当前文件名原样进入系统默认路径。原生确认仅调用一次现有确认动作；调用不直接写盘。
3. 原生取消保留目录 / 文件名、不调用确认或取消动作；异常显示失败信息，重试可成功。
4. 连续点击不重复打开系统对话框；等待时关闭、重新打开或更换目标后，旧结果及旧错误不影响新目标。
5. Main 的目录、单选、多选和保存选路正确透传可选默认路径 / 标题；以请求窗口为父；取消语义正确；错误参数被拒绝；保存选路不触发文件写入。
6. 旧的无参数选择调用和旧 preload 缺少新增方法时保持兼容。现有保存、冲突、取消与全部保存续接测试保持通过。

交互 E2E（需明确获准操作隔离应用后执行）：

1. Desktop 本地文件与未命名文件分别打开另存为，点击「使用系统对话框」后使用系统位置与文件名控件完成保存，确认标签路径与正文正确。
2. 系统对话框取消后可回到原弹窗继续内置保存；中英文、浅色 / 深色与 Windows / macOS / Linux 使用对应系统组件。
3. Desktop 远程、Web 和手机远控只保留内置浏览器；对话框不溢出手机视口，保存归属与远程身份不变。

本次不自动启动、关闭、重启或自动化操作 YCode，不把单元测试通过写成真实系统交互已通过。
