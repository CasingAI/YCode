# Spec：思考过程始终显示

## 目标与产品规则

- 对话消息流中始终显示有内容的模型思考过程，不提供关闭选项。
- 设置页不再展示“显示思考过程”开关；设置状态、协议字段及用户操作追踪中不再包含该选项。
- 普通空 reasoning 行（包括加密块与空 delta）仍然隐藏；带明确 Responses 思考阶段标记的空行仍按既有生命周期规则处理。此变更只取消按用户偏好隐藏思考行，不改变空内容过滤、请求字段或协议解析行为。
- 旧 `setting.json` 或共享设置消息中的 `messageStreamShowReasoning` 与迁移标记属于未知字段，schema 解析时忽略；旧值 `false` 不得影响思考显示，也不触发专属迁移写回。

## 状态所有者与接口

- 思考行由会话投影提供，UI 读取并渲染；没有“是否显示思考过程”的可变状态。
- `ConversationRowRenderContext` 不承载思考显示偏好。会话工作项投影保留现有行序、空行过滤与工具分组规则，但不再依据首条 reasoning 行或设置值裁剪 reasoning。
- 旧设置读取由 `appSettingsSchema` 处理：Zod 对象的默认未知字段剥离行为负责兼容旧配置，无新迁移标记或持久化写入路径。

## 迁移边界与失败语义

- 不迁移或重写所有用户的设置文件。旧字段在读取后不进入类型化设置对象；后续任意正常设置写入会随 schema 结果自然移除这些字段。
- 仅有旧思考显示字段不导致 `settingService.get()` 排队写盘；已有其他设置迁移（例如托盘默认值迁移）继续按原规则运行。
- 对话数据中的 reasoning 内容、Responses summary 请求、分享视图和工具结果均不在本次迁移范围内。

## 验收场景

1. 设置页不渲染“显示思考过程”开关，且不再为该选项维护本地状态或持久化回调。
2. 旧全局设置与 patch 中即使携带 `messageStreamShowReasoning: false` 或迁移标记，schema 输出也不含这两个字段。
3. 常规会话与 CUA 分组中的非空 reasoning 行始终进入渲染投影，不再依赖首条行 ID。
4. 普通空 reasoning 行仍不显示；带 Responses 阶段标记的空行行为保持不变。
5. 现有过程折叠、间距和空摘要测试通过，且 Responses 推理请求行为没有变化。
