# Spec: 文件工作台编辑器状态栏（VS Code 式底栏）

## 目标

文件工作台的编辑区底部目前是空的：标签条在上、编辑器在下，没有 VS Code 那条状态栏。
本 spec 在**每个编辑器组底部**补一条状态栏，并且**每一项都必须有真实行为**：
要么显示来自编辑器的真实事实，要么点了能真的改到编辑器。

形态对齐 VS Code 状态栏：贴底、单行、右对齐、`h-6`、弱化文字色、项可点。
不做装饰性假控件——没有行为的项一律不渲染成按钮。

上游 spec：`workspace-files.md`（文件主视图与工作台结构）。

## 已对齐决策

| 边界     | 决定                                                                       |
| -------- | -------------------------------------------------------------------------- |
| 落点     | 每个编辑器组底部一条（分屏时每组各一条），不是整窗一条                     |
| 覆盖范围 | 只覆盖文本编辑器（Monaco）；图片 / PDF / Office 等只读预览标签不显示状态栏 |
| 条目来源 | 全部来自当前编辑器实例的真实状态，不读缓冲、不猜磁盘                       |
| 可点条目 | 光标位置、缩进、换行符、语言、诊断问题                                     |
| 只读条目 | 编码（UTF-8）                                                              |
| 分支名   | 第一版不做，见「负面边界」                                                 |
| 平台     | Desktop / Web / 远程工作区同一套；状态栏不引入任何新的服务调用             |

## 产品规则

### 位置与外观

- 状态栏在编辑器组内部、编辑器主体**下方**，属于该组的一层（`flex-col` 里的最后一项）。
- 单行、高度 `h-6`、上边框 `border-t border-border`、文字 `text-ui-xs text-foreground-subtle`。
- 条目右对齐，顺序沿用 VS Code：**问题 → 缩进 → 编码 → 换行符 → 语言 → 行列**。
- 状态栏不可拖窗口（`[app-region:no-drag]`），点击条目不抢编辑器焦点。
- 窄屏（手机 Web）允许只保留问题数与行列，其余条目按可用宽度隐藏，不允许折行。

### 条目语义

| 条目   | 显示                                                         | 行为                                                                          |
| ------ | ------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| 问题   | `⊗ 错误数` `⚠ 警告数`                                        | 点开诊断列表，点条目跳到该行该列                                              |
| 缩进   | `空格: 2` / `制表符: 4`                                      | 菜单切换缩进类型（空格 / 制表符）与缩进大小（2 / 4 / 8）                      |
| 编码   | `UTF-8`                                                      | 只读文本，Tooltip 说明当前按 UTF-8 读写                                       |
| 换行符 | `LF` / `CRLF`                                                | 菜单切换；切换会改写全文并把标签置脏                                          |
| 语言   | 当前语言的规范名（如 `TypeScript`；无别名的语言回退显示 id） | 浮层列出 Monaco 已注册语言，切换即改语言模式；另有「保存为关联…」写入用户关联 |
| 行列   | `行 12，列 3`                                                | 点开输入框，输入「行号」或「行:列」跳转；语法与越界规则见「跳转到行/列」      |

- 语言选择器用 **Popover**（不是 DropdownMenu）：浮层里要同时放搜索框、语言列表和
  「保存为关联…」入口，Radix 的菜单项承载不了输入框，Popover 才能做成 antd Select
  那种「上面输入、下面列表」的形态。
- 语言浮层的每行是**固定两行**：第一行显示可读语言名称，优先使用 Monaco 注册项的
  第一个别名（如 `JSON`、`YAML`、`JavaScript`、`Plain Text`），没有别名时回退到语言 id；
  第二行显示其余别名或扩展名，没有就不显示。语言 id 仍是切换语言、搜索和文件关联的
  稳定值，不因显示名称改变。行高固定、内容一律截断，**不允许换行**：
  Monaco 注册的语言里有 `freemarker2.tag-angle.interpolation-bracket` 这类长 id，
  一旦让文字折行就会溢出行盒、压到相邻行上。
- 状态栏上的语言项与浮层行显示**同一个规范名**：都取 Monaco 首个别名（`TypeScript`、
  `JSON`），没有别名的语言回退到 id。切换与「保存为关联」仍以 id 为准，
  显示名不参与存储与匹配。
- 语言浮层的**列表顺序按流行度降序**，不按首字母序：Monaco 注册了 80 多种语言，
  首字母序会把 Abap、Cameligo、Msdax 这类几乎没人手写的语言排在前面，
  把 TypeScript、JSON、Markdown 这些天天要用的语言埋在中段。
- 排名的口径是**仓库覆盖率**：抽样 GitHub 公开仓库，统计「含有该类文件的仓库占样本
  仓库的比例」；同一语言有多个扩展名时取并集，仓库只要含其中之一就算命中。
  排名表在 `filesEditorLanguagePopularity.ts`，抽样方法与数据来源见
  「流行度数据来源」。没有份额数据的语言不进表，排在表后并按 id 升序。
- 语言浮层的搜索匹配 id 与别名；**扩展名只在查询以 `.` 开头时参与匹配**：
  Monaco 给 XML 注册了 `.targets`、给 Kotlin 注册了 `.kts`，这类扩展名的子串
  会沾上普通词（`ts`），无条件匹配会让搜「ts」的结果被 XML、Kotlin 刷屏。
  因此按「Angle」仍能命中 FreeMarker2 的方言 id，按「.ftl」能按扩展名搜到，
  而「ts」只命中 id/别名里含 `ts` 的语言（TypeScript、ATS）。

- 问题计数恒显示（哪怕是 `0 0`），与 VS Code 一致；点开无诊断时给出空态文案。
- 诊断只统计**当前文件**（当前 model）的 marker。语义诊断按 `workspace-files.md` 保持关闭，
  剩下的语法诊断、JSON 校验等照常出现。
- 缩进切换作用于**当前 model 的已解析缩进选项**：Monaco 在建 model 时按文件内容探测缩进，
  这组值也就是插入文本时实际使用的缩进。切换不写进工作台缓冲，也不落盘（缩进是视图偏好）。
  读值走 model 的已解析选项而不是编辑器计算选项：后者的值只存在内部数组里，
  公开 API 取不到属性。
- 换行符切换作用于**当前 model**：整篇文本的换行统一到目标序列，标签随之变脏，
  由用户按既有保存链路写盘。切换不改「基准」，因此保存冲突判定仍按原规则。
- 语言切换只改 Monaco 的语言模式，不改文件内容。切换后该文件记为「用户显式选定」，
  推断结果不得再覆盖它；用户可把选择保存成文件关联（按模式或按文件），
  规则与优先级见 `files-editor-language-detection.md`。
- 行列跳转只移动光标，不改内容。

### 跳转到行/列

「跳转到行」支持列：交互规则对齐 VS Code 的 Go to Line/Column（`gotoLineQuickAccess`），
形态保持现有轻量浮层（标题 + 输入框 + 跳转按钮），不引入 quick access 式的候选列表。

- **语法**：`行` 或 `行:列`；分隔符 `:` `,` `#` 等价（`12:5`、`12,5`、`12#5` 均可）；
  允许一个前导冒号（`:12:5`，照顾 VS Code 肌肉记忆）。数字按 `parseInt` 解析，
  `12abc` 按行 12 接受（与 VS Code 一致）。
- **列省略**：列段缺失、为空或非数字（`12`、`12:`、`12:x`）都按第 1 列。
- **越界夹取，不拒绝**（对齐 VS Code）：
  - 行：`line >= 0 ? line : (行数 + 1) + line`，再夹到 `[1, 行数]`。
    所以 `0` 落第 1 行，`-1` 落最后一行，超界按最近边界夹取。
  - 列：同式夹到 `[1, 行长 + 1]`（Monaco `getLineMaxColumn`，含行尾后一位）。
    行先夹取，列按夹取后的行取上限。
- **列口径**：按 Monaco 模型列（与状态栏「列 N」同口径，输入输出可往返）。
  不做 VS Code 的可视列（tab 展开）换算：那需要复制 Monaco 内部的
  `CursorColumns` 逻辑，而状态栏展示与 `setPosition` 用的都是模型列。
- **职责边界**：UI 只做语法解析（`filesEditorParseGotoTarget`，纯模型层）；
  行列夹取与跳转都在句柄（`filesMonacoStatusHandle.goToLine`）完成——
  列上限依赖 model 行内容，UI 层不持有 model，也不该持有。
- **失败语义**：语法非法（空串、无数字行段）不动作、浮层不关闭；
  越界视为合法，按夹取结果跳转并关闭浮层。

### 编码说明

文件服务 `readTextFile` / `writeTextFile` 一律按 UTF-8 处理，因此编码显示恒为 `UTF-8`。
这一项**不做成按钮**：没有可执行的编码切换动作时，按钮就是死控件。
需要真正的编码支持（GBK 等）时，先扩 `IFileService` 契约，再把这一项升级成可点菜单。

### 流行度数据来源

语言流行度排名表的数值必须来自可复现的调研，不能凭印象手排。

- **口径**：仓库覆盖率——含该类文件的仓库占样本仓库的比例。同一语言的多个扩展名取
  并集，仓库只要含其中之一就算命中。
- **抽样框**：GitHub 公开仓库，排除 fork 与已归档；分两层抽样——高星层
  `stars ≥ 100`（991 个），低星层 `created 2019–2026 且 stars 1–99`（3,982 个），
  两层都按最近更新排序抽取，合计 4,973 个仓库。
- **采集**：对每个仓库调用 Git Trees API 拉全量文件树，按扩展名（转小写）与文件名
  （忽略大小写）统计，文件名额外做前缀匹配（`Dockerfile*`、`Makefile*`、`.env*`）。
- **交叉验证**：论文《What's Inside a GitHub Repository? (2026)》（arXiv:2605.16701v2，
  Table II）用同口径给出 Markdown 98.6%、.yml 84.1%、.json 69.2%、.txt 56.9%、
  .sh 46.8%、.yaml 42.1%、.js 40.5%、.py 39.4%；本次抽样得到 .md 96.1%、
  .yml 79.6%、.json 69.7%、.txt 54.5%、.sh 42.5%、.yaml 40.5%、.js 42.1%、
  .py 40.9%，量级与趋势一致（偏差最大的是 .gitignore：论文 95.0%、本次 78.0%，
  抽样偏向仍在维护的新仓库）。论文的数据集在 Zenodo（doi:10.5281/zenodo.20185536），
  本次**未直接取用**，只作为交叉验证。
- **稳健性**：高星层与低星层各算一遍排名，两层的 Spearman 秩相关为 0.974，
  说明排序不依赖抽样偏向。
- **数据库方言**（`mysql`、`pgsql`、`redis`、`redshift`）没有独立扩展名，
  份额取 DB-Engines 排名分；`sparql` 按 `.rq` 文件覆盖率计。
- 数值改动时必须同步更新排名表与 `filesEditorLanguagePopularity.test.ts` 的断言。

### 分支名不进第一版

文件工作台没有 Git 表面，Git 状态在会话视图的 Git 面板里。在底栏显示分支名需要额外
拉一次 `git status`，且切分支后这份数据会过期；显示一个可能过期的分支名比不显示更糟。
第一版不做，等文件工作台有稳定的数据通道后再评估。

## 状态所有者

| 状态                                             | 所有者                                  | 说明                                                                                                                            |
| ------------------------------------------------ | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 编辑器实例                                       | `FilesMonacoEditor`                     | 仍然是编辑器的唯一所有者；状态栏不新建编辑器                                                                                    |
| 状态栏快照（行列 / 语言 / 缩进 / 换行符 / 诊断） | Monaco 事件 → `filesMonacoStatusHandle` | handle 由 `FilesMonacoEditor` 创建，对外只暴露快照与命令，不暴露 Monaco 原始对象。缩进读 model 已解析选项，其余读编辑器实时状态 |
| 状态栏渲染                                       | `FilesEditorGroupPane`                  | 只读快照 + 下发命令，不缓存第二份真相                                                                                           |
| 缓冲正文 / 脏态                                  | 文件工作台 Store（既有）                | 换行符切换通过既有的内容变更通道回写，脏态判定不变                                                                              |

## 事件顺序

```text
用户移动光标
  → editor.onDidChangeCursorPosition
  → handle 汇总快照（行列 / 语言 / 缩进 / 换行符 / 诊断）
  → 组内订阅者 setState
  → 状态栏重绘

用户点「换行符 → CRLF」
  → handle.setEol("CRLF")
  → model.setEOL(CRLF)（Monaco 触发一次 EOL 变更内容事件）
  → 既有 onDidChangeModelContent 通道
  → 缓冲正文变成 CRLF、标签置脏
  → 用户保存时按既有冲突规则写盘

用户点「诊断条目」
  → handle.revealMarker(marker)
  → editor.setPosition + revealPositionInCenter
```

- 快照订阅是**单向**的：编辑器 → 状态栏。状态栏不回写自己的快照。
- 换行符切换**不允许**用「先改缓冲再灌模型」的顺序，那会触发两次内容变更并可能撞上
  `workspace-files.md` 记录过的规范化来回写问题。统一走 `model.setEOL`。

## 负面边界

- 不做整窗级状态栏（VS Code 是整窗一条）；本工作台按编辑器组各画一条。
- 不在状态栏里放 Git 分支、账号、远控、通知等非编辑器事实。
- 不做编码切换按钮（见上）。
- 不把 Monaco 原始对象透传给状态栏组件；只给结构化快照与命令。
- 不给只读预览标签（图片 / PDF / Office）加状态栏。
- 不新增文件服务调用，不新增协议字段，因此不涉及 `zcode-protocol` 变更。
- 不改工作台缓冲的脏态判定、冲突判定与保存链路。
- 不做 VS Code 的字符偏移模式（输入 `::N` 按全文偏移跳转），行列已覆盖需求。
- 不做输入过程中的实时预览与目标提示：预览需要 UI 直接操作 model 和装饰器，
  违背「不透传 Monaco 对象」的边界；跳转结果由状态栏行列项即时反馈。

## 验收场景

1. 打开一个 TypeScript 文件：底栏出现，显示当前语言 `TypeScript`、缩进 `空格: 2`、
   换行符 `LF`、编码 `UTF-8`、`行 1，列 1`。
2. 点击文本：行列实时更新到光标所在行列。
3. 点「行列」→ 输入行号或「行:列」→ 确定：光标跳到该行该列，编辑器滚动到可见位置；
   输入 `9999`（超出行数）跳到最后一行；输入 `9999:9999` 跳到最后一行行尾；
   输入 `-1` 跳到最后一行。
4. 点「缩进」→ 选「制表符」：状态栏文案变为 `制表符: 2`；再选大小 4：变为 `制表符: 4`。
   再次输入时按新缩进生效。
5. 点「语言」→ 列表中 JSON 的首行显示 `JSON`；选中后仍以语言 id `json` 切换模式，
   状态栏显示 `JSON`，文件按 JSON 高亮（不报错）。
6. 点「换行符」→ 选 `CRLF`：全文换行变为 CRLF，标签出现脏点，保存后磁盘文件为 CRLF。
7. 打开一个 CRLF 文件：状态栏直接显示 `CRLF`，不出现切换提示。
8. 语法有错的文件：问题计数显示错误数；点开列表能看到消息，点条目跳到出错行。
9. 切到图片 / PDF 标签：不显示状态栏。
10. 分屏两个编辑器组：每组底部各有一条状态栏，各显示自己文件的行列与语言。
11. 切换语言（应用语言）后：状态栏文案随之切换。
12. `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 通过；纯模型层有单测。
13. 点「语言」→ 选 `json`：再点「保存为关联…」→ 选「按模式」：状态栏语言项下方
    出现该关联入口，保存后重新打开同后缀文件仍为 `json`。
14. 点「语言」→ 浮层里输入 `angle`：命中 `freemarker2.tag-angle.interpolation-bracket`
    这类方言 id（按别名与扩展名也能命中）；浮层里每行固定两行、长 id 截断显示，
    相邻行不互相压住。
15. 点「语言」→ 不输入任何关键词：列表第一项是 `markdown`，其后依次是 `plaintext`、
    `yaml`、`json`、`ini`、`xml`；`javascript`、`shell`、`python`、`typescript`
    这些常用语言紧随其后；`flow9`、`msdax`、`abap` 这类长尾方言出现在列表末尾。
16. 点「语言」→ 输入 `ts`：列表命中 `TypeScript`、`ATS`（id/别名含 `ts`），不出现
    XML（扩展名 `.targets`）、Kotlin（`.kts`）这类仅扩展名沾边的语言；
    输入 `.kts` 仍能按扩展名命中 Kotlin。
