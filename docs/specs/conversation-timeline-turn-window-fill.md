# Spec: 对话时间线整轮取窗与静默补齐

## 目标

**一次取窗至少一整轮**（该轮的 turnHeader、用户消息、正文、工具行全部到齐），**挂载前折叠内容至少铺满一屏**：不够就在同一次补齐里按整轮继续往上加，加够或撞上单帧体积上限才一次性挂进可见区。首开与跳转定位因此一次到位，不再出现「先画出半截、再补一截、列表跟着跳」。

取窗单位是**轮**，不是固定行数：`snapshotTailWindowRows: 60` 与 `rowsRangeMaxLimit: 200` 都是行数常量，切页切在轮中间，用户定的产品指标里没有它们。

## 现状与根因

- **CLI 按行切窗**：`conversation-topic-publisher.ts` 的 `getWireSnapshotForProfile`（首窗 `slice(-limit)`）与 `getRowsRange`（`findIndex` + `slice(limit)`）都只看行数，完全不感知 `row.turnId`，页边界落在轮中间。`beforeRowId` / `afterRowId` / `aroundRowId` / 尾窗四个方向共用这一套行级切片。
- **UI 靠补丁兜**：首轮缺 turnHeader 时 `shouldAutoLoadIncompleteLeadingTurn` 就地补拉；补页跨轮时 `timelinePrependBlocks` 把页与窗口首轮缝合起来量。两者都是「先画半截、再补一截」的补丁形态。
- **没有满一屏的停止条件**：折叠后不足一屏的会话打开时自动补页，占位块可见，逐页提交。
- **高度已知的只有补页路径**：staged 块（测量=装载同一个 DOM）只在 `pendingOlder` 页上存在；首开/跳转窗口由订阅 snapshot 直接进虚拟列表，首绘时全部按估算走，实测差逐条回补。

## 产品规则

### 取数（CLI，`getRowsRange` + `getWireSnapshotForProfile`）

1. **页 = 整轮集合**：候选行选定后按 `row.turnId` 向两侧扩展到轮边界。`turnHeader` 行属于它那一轮，因此整轮必然含 turnHeader——`shouldAutoLoadIncompleteLeadingTurn` 随之删除。
2. **页预算 = 单帧体积**：用 `utf8JsonByteLength` 按轮累计序列化字节，预算 = `maxFrameBytes` − `rowsRangeFrameOverheadBytes`（新增限额常量）。行数上限 `rowsRangeMaxLimit` 升为 schema 兜底（不再参与产品切页），且取值保证「字节预算先于行数兜底生效」。
3. **只有撞上单帧上限才允许拆轮**：某轮整体超预算且页内没有任何其它整轮时才对该轮按行切分（切在预算允许的最大行数处）。这是拆轮的唯一许可。
4. `aroundRowId` 的基线是目标行的**整轮**，再向上下交替扩整轮直到预算用尽，目标轮始终完整。
5. 首窗尾窗：自尾向前按整轮累计，直到行数达到 `snapshotTailWindowRows` 且预算允许；不足 60 行时把首个整轮向上补全。该常量从此只是「至少覆盖多少行」的下限，不是切页边界。

### 补齐（UI）

6. **补齐事务**：`pendingOlder` 从单页变为累积缓冲——一次补齐里多次取数的结果按行序合并进同一缓冲，直到停止条件成立才提交一次。
7. **停止条件只有两个**：折叠后铺满一屏（staged 块实测高度 ≥ 滚动视口高度），或没有更早历史（`canLoadOlder=false`，含拆轮已到顶）。撞上单帧上限的轮由 CLI 处理，客户端不拆轮。
8. **补齐静默**：补齐 pass 期间可见区不出现「正在加载更早消息」文字（常驻占位块的透明度开关见 `conversation-timeline-top-placeholder.md`）。
9. **首开与跳转走同一管线**：窗口先整轮进 staged 暗处排版测量，补齐够一屏后**一次挂载**：staged 单元逐轮写入测高缓存，虚拟列表接管时按缓存里的实测高度记账，屏外那一屏因此也有非零高度，尾巴不动。挂载那一帧对前插锚定是**免补偿**的——落点由跟随态决定，前插补偿按旧坐标写入反而会把落点钉在暗处那一帧的位置。
10. **首开必须贴底**：首绘落点由跟随态决定（打开会话定位到最新消息），补齐期间不产生任何一次可见绘制。暗处那一帧里两条定位入口都是瞎的（滚动记忆会被钳成 0、query 行量得到但不在可滚的流里），它们把意图记下、挂载那一帧重放。
    10b. **补齐判定的两个输入都要可靠**：折叠高度取 staged 容器各轮的实测和，视口高度取滚动容器的 `clientHeight`。两者都读 state 而不是当场读 DOM——隐藏面板刚显示、窗口刚缩放都不带 React commit，当场读到的永远是上一次布局的旧值，补齐会停在一个永远不满足也永远不继续的状态上。滚动容器上的 observer 负责把那两次变化推到下一次求值。折叠总高连同测到它的窗口身份一起记账：换代后的第一次判定会读本值，裸数值会沿用旧窗口的实测高度，让新窗口看似「已够一屏」而跳过补齐；身份不匹配按 0（未排版）处理。staging 期间前插块不建帧——块容器是空的，建帧只会在白耗之外把暗处中间态写进前插 diff 基线；暗处帧基线与前插帧基线都按窗口身份就地作废（建帧在渲染期，effect 清理晚一拍）。
11. 上滚补页（滚到已挂内容顶部触发的 `loadOlder`）沿用既有闸门与锁，且**填充条件并入闸门**：staged 折叠高度不足一屏、或整轮未到齐、且仍有更早历史时闸门不放行，只继续静默取页。首绘与上滚共用同一组停止条件，但**两条驱动路径不得合并**——首绘由 staging 判定驱动，上滚由 Timeline 的填充循环驱动，后者必须被 `!stagingActive` 守卫，防止同一时刻两条路径同时驱动 `loadOlder`。
    11a. **整轮到齐**：缓冲最老行是该轮的 `turnHeader`（整轮取窗后每页要么以轮头开始、要么是被单帧上限拆开的巨轮中段），或已没有更早历史。最老行落在轮中段（`kind !== "turnHeader"`）说明边界轮还有更早的行没取回来——此时哪怕折叠高度已铺满一屏也不提交，用户不允许看见同一轮的计数（「工具 N 次」）分批上涨。
    11b. **中断信号（`olderFillInterruptedSeq`）**：`loadOlder` 的每一条不产生窗口变化的路径——纪元不匹配、事务锚点失配、取数失败——都必须留下显式状态变化（bump 单调递增信号），让 Timeline 的填充循环重新求值；静默 `return` 会让闸门请求已被消费、缓冲状态不变、没有任何 effect 再被唤醒，占位块永久显示、滚动锁永不解除。信号语义按失败类别分两档：**取数失败且缓冲非空**（锚点仍有效）→ Timeline 提交已取部分并解锁，不足一屏的部分由挂载后的既有预取路径在冷却到期后继续；**连续丢弃达上限（3 次）**（锚点已失配，提交必被判 retry）→ store 直接作废缓冲并解锁（与「提交后 retry 作废」同一结果，少一次空转），进既有 2s 冷却，冷却到期由预取路径按新游标重取。成功取页即清零连续丢弃计数。
    11c. **不设时间截止**。上滚填充的停止条件全部是显式事实：铺满一屏、整轮到齐、没有更早历史、中断信号。敢等的依据是渲染成本已验证：历史轮折叠态 DOM 只有标题行与最后一条正文（`historyDefaultOpen = unit.isRunning`，Radix Collapsible 关闭即卸载子内容），补齐十几页的暗处排版是折叠态的廉价计算，真正的等待成本只有串行取数往返；填充超过 400ms 由占位块的既有渐显规则承担告知义务。首绘的 `FIRST_PAINT_FILL_DEADLINE_MS` 是首开失败兜底，不因此对齐删除，也不向上滚推广。
12. **补齐有兜底截止**：首绘开始后 `FIRST_PAINT_FILL_DEADLINE_MS`（2000ms，与 store 取数失败冷却同量级）仍未满足停止条件就先挂上去。取数失败不产生新 commit，补齐判定不会被重新求值——没有这条兜底，一次失败就让可见区一直空着，而空着的时间线对用户是「这个会话坏了」。正常路径永远碰不到它。

## 状态所有权

- CLI publisher：轮边界扩展、字节预算、拆轮判定（纯函数，`conversation-turn-window.ts`）。
- `ConversationProjectionStore`：`pendingOlder` 补齐缓冲、纪元/游标校验、合并（`commitPendingOlder` 一次并入全部累积页）。
- `ConversationTimeline`：staged/committed 集合、块容器高度、inset 账本、补齐循环的触发与停止、锁与闸门。

## 事件顺序

```text
首开（订阅 snapshot 到达）
  → 窗口整轮进 staged 暗处（负偏移、真实列宽、已布局）；虚拟列表与 live tail 同时置空
  → layout effect：逐轮量高 → 测高缓存（屏外那一屏也因此有非零高度）+ 折叠总高
  → 不足一屏且 hasMoreOlder → loadOlder（页=整轮）；fetchingOlder 单飞，缓冲累积，staged 增长
  → 够一屏 / 无更早 / 没有取数入口 → commitPendingOlder() + 记下「本窗已挂载」
  → 同一 commit 的 layout 阶段：
      prepend effect：首绘帧免补偿，只把基线对齐到新窗口
      底部锚定 effect：following=true → 贴底（最新消息在屏内）
  → 挂载后的落点重放（滚动记忆 / query 定位，二者互斥，query 优先）
  → 用户开始阅读；此后走既有虚拟滚动语义
```

两条 layout effect 都跑在绘制前：测量写入 state 后 React 立刻同步重渲染，整条链路不落进任何一帧绘制。本地链路（尾窗本身够一屏）在第一次 commit 内就走完；慢链路在补齐期间空着可见区，且期间不显示任何加载文字。

上滚填充（滚到已挂内容顶部触发预取，规则 11）：

```text
接近顶部（离顶两视口）→ loadOlder 第一页 → 行进 pendingOlder 缓冲
  → staged 单元进块容器暗处排版（负偏移，折叠态，不可见）→ layout effect 实测折叠高度
  → 填充循环判定：不足一屏 或 最老行非 turnHeader（边界轮未到齐）→ 继续静默取页（缓冲累积）
  → 铺满一屏 且 整轮到齐 → 闸门放行（仍要求用户已停在顶部）→ 既有单笔提交 → 解锁
中断路径：
  → 某页被丢弃（纪元/锚点失配）→ store bump olderFillInterruptedSeq → 填充循环重新求值
     → 未达丢弃上限：按新游标继续取页
     → 达上限（3 次）：store 作废缓冲 + 2s 冷却 → hasPendingOlder=false → 锁解除
  → 取数失败且缓冲非空 → bump 信号 → Timeline 提交已取部分 → 解锁（冷却到期后预取续补）
```

## 负面边界

- 不改 `rowsRange` 协议载荷形状（rows + 水线 + hasMore/hasMoreNewer）、不改重连/replay 语义。
- `loadAllOlder`（分享只读、问题目录 hydration）不整轮化、不补齐，保持整窗换快照 + 既有 total-size fallback。
- 首绘 staging 与 committed 前插块是两条不同路径：前插页**留在**块容器里（测量=装载同一个 DOM，永不重挂）；首绘窗口在暗处量完之后**必须交给虚拟列表，不留在块容器里**——留着会让整个会话退化成常驻块、turn 级虚拟化失效。首绘因此多一遍「暗处测量 → 可见挂载」的重渲染，它发生在首帧之前、用户不可见；这是本 spec 唯一允许的「量完换节点」，理由是虚拟化所有权。挂载期间块容器强制为空：同一批轮同时出现在两个容器里会撞 key，也会让块容器把暗处高度误记成实心块。
- 首绘缓冲不登记 committed turn id、不经 prepend 提交闸门：闸门的条件是「用户已到顶」，而首绘此刻没有任何滚动可言。
- 不做「越顶越远的页收编回虚拟化」。
- 不用兜底截止去掩盖同步问题：它是失败兜底（补齐失败时宁可少几屏，也不能让可见区一直空着），不是等待手段；正常链路上补齐在第一次 commit 内就走完。
- 不靠减薄样式/字号/行高规避满屏一次排版的开销；满满一屏一次排出来是正常开销。
- 过程区（上千工具行摊开时的屏外挂载）不在本 spec，见后续独立 spec。

## 验收

1. 打开尾部带巨轮（数百工具行、折叠态）的长会话：首绘一次到位、折叠内容 ≥ 一屏，本地链路全程无加载文字，贴底不跳。
2. 轮导航跳转中部旧 query：一次就位，目标轮完整（turnHeader→用户消息→正文→工具行同批到达），上方 ≥ 一屏。
3. 快速上滚到顶：补页静默完成、衔接无跳动；限速下顶部文字渐显；滚回底部看不到占位块；真顶总空白与现在一致。
   3b. 上滚补页遇到超预算巨轮（被 CLI 拆成多页）：同一轮的「工具 N 次」计数不允许在可见区逐步上涨——缓冲累积到「铺满一屏且整轮到齐」（最老行是 `turnHeader`）才一次性挂载。
   3c. 上滚填充期间取数被丢弃或失败：占位块与滚动锁在有限步内解除（丢弃达上限作废缓冲、失败提交已取部分），不允许出现「正在加载更早消息」永久显示且列表滚不动的状态；冷却期间无请求自旋。
4. 折叠后不足一屏的短会话（无更早历史）：无加载文字、无补页自旋。
5. `rowsRange` 返回的每一页在 `beforeRowId` 与 `afterRowId` 两个方向上都不切轮；单轮超单帧预算时才出现切分。
   5b. 补齐事务跨页时按「已取到的最小 rowId」推进游标，页与页之间不重复取同一页；探到真实顶部（最后一页 `hasMore=false`）后不再发请求。
6. `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 与相关包测试通过。
