# Spec: 移动端询问框操作区布局

## 目标

手机端等待用户回答的询问框占据会话底部 dock。展开态的顶部导航与底部操作按钮采用稳定的左右顺序，让用户能直接找到收起入口，并在提交问题前快速确认主要操作集中在右侧。

## 产品规则

- 顶部操作区从左到右固定为：`倒计时（存在时）` → `上一页` → `题目进度` → `下一页` → `整张询问框收起/展开`。
- 整张询问框的收起/展开按钮必须位于顶部操作区最右侧；它与“只展开或收起长问题正文”的按钮是不同控件，不能混用。
- 底部操作区的“跳过/忽略”和“继续/提交”在窄屏下右对齐。键盘提示在 640px 及以下占据独立的一行，不挤占操作按钮的对齐基准；640–768px 保持单行时，父容器的 `justify-between` 已使按钮组靠右，无需提前换行。
- 宽屏保持现有布局语义；本次只调整窄屏的视觉顺序和对齐。
- 收起后仍保留问题摘要、倒计时、题目进度和位于最右侧的展开按钮。

## 状态所有者与不变式

- `ElicitationDialogContent` 的本地 `isDialogExpanded` 是整张询问框展开/收起的唯一状态所有者。
- 调整布局不得改变问题索引、答案草稿、倒计时或 `onRespond` 提交路径。
- 收起/展开不得重置 `autoResolution`；用户仍需在紧凑摘要态看到等待状态。
- 顶部按钮顺序变化不得改变上一页、下一页、提交或取消的业务语义。

## 接口

- `packages/ui/src/ElicitationDialog.tsx`
  - 顶部导航控件的 JSX 顺序。
  - 底部操作按钮组的窄屏对齐 class。
- 无协议、持久化、远程恢复或跨模块接口变化。

## 验收场景

1. 手机宽度下，顶部从左到右显示倒计时（存在时）、上一页、题目进度、下一页、收起按钮；收起按钮紧贴询问框右侧。
2. 点击最右侧收起按钮后，正文、选项和底部按钮隐藏，问题摘要、倒计时、题目进度和最右侧展开按钮保留。
3. 点击最右侧展开按钮后恢复完整询问框，当前题号和已填写草稿保持不变。
4. 手机宽度下，键盘提示位于独立行，“跳过/忽略”和“继续/提交”整体右对齐。
5. 宽屏下询问框内容、题号导航和底部按钮语义不变。
6. 页面刷新、切换会话或恢复远程快照后，仍由新的请求实例按原有规则展示，不依赖本地折叠状态。

## 验证

- 定向回归测试：`TSX_TSCONFIG_PATH=packages/ui/tsconfig.json node --import tsx --test packages/ui/test/elicitationMobileControlLayout.test.ts`
- 静态检查：`pnpm typecheck`、`pnpm lint`、`pnpm fmt:check`、`pnpm architecture:check --changed`
- 当前仓库没有真实 React 交互测试基建；实际触摸命中区域、收起后 dock 高度和滚动可见性仍需在手机宽度下人工回归。
