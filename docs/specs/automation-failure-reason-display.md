# 自动化失败原因展示

## 目标

定时/延时任务与闲时任务失败时，列表卡片直接显示已持久化的失败原因原文，用户不再只看到「已失败」三个字而无法判断原因。

## 背景

失败原因在数据层已完整落库：定时任务派发失败时写入 automation.lastError 与 automation_runs.error（例如「Automation 模型选择不可用，请重新选择模型与思考档位」）；闲时任务终态写入 failureReason。但两张卡片从未渲染这些字段，只以失败图标与状态文字提示；运行历史的错误文本仅存在于悬浮提示里，移动端没有触发路径。曾出现任务因保存的模型选择在派发时解析失败而重试 4 次落败，用户在列表里看不到任何原因的情况。

## 产品规则

- 失败判定沿用现状，不新增判定路径：定时/延时卡片沿用 `hasAutomationFailureState`（lifecycle failed / failed_to_dispatch / lastError 非空）；闲时卡片沿用 `status === "failed"` 的失败脚注判定。
- 失败且原因文本非空时，卡片在状态行上方追加一行原因原文，最多两行截断，完整文本经 title 悬浮可见。
- 展示文本剥掉仅用于跨进程诊断的 `[reason=...]` 后缀；剥完为空则退回原文，原文也为空则不渲染该行、不新增占位文案。
- 原因行使用 destructive 语义色：它是真实错误态，不属于颜色借用。
- 两张卡片所在网格行高从固定 132px 改为 `minmax(132px, auto)`：非失败卡片高度不变，失败卡片随原因行自然增高；列表滚动上限维持现状。
- 纯展示层改动：不改变失败原因的写入方（automationRepo / offPeakTaskRepo 派发与终态回写）、列表刷新通道与失败判定逻辑。

## 状态所有者

| 状态                                 | 所有者                                                 | 说明                                       |
| ------------------------------------ | ------------------------------------------------------ | ------------------------------------------ |
| automation.lastError / failureReason | tasks-index.sqlite（automationRepo / offPeakTaskRepo） | 既有派发失败与终态回写，本次不改           |
| 卡片展示文本                         | automationFormat.automationFailureDetailText           | 纯函数：trim + 剥诊断后缀，空文本返回 null |
| 卡片布局与渲染                       | AutomationsSection / OffPeakTaskList                   | 仅新增原因行与行高规则                     |

## 验收场景

1. 定时任务派发失败（模型选择不可用）后，卡片在状态行上方显示失败原因原文，最多两行截断。
2. 失败原因带 `[reason=modelGroup.noMembers]` 后缀时，卡片只显示人话文本，不出现方括号诊断码。
3. 非失败卡片高度保持 132px 不变；失败卡片增高后列表仍按既有上限滚动。
4. 闲时任务失败且 failureReason 非空时，卡片同样显示原因行。
5. 原因文本为空的失败卡片维持现有展示。
