# 官方插件缓存完整性

## 官方安装记录迁移规则

- 旧 `.zcode` 插件存储根中的官方市场安装记录是待重新安装的历史记录，不代表当前运行时可用，也不得出现在插件概览的当前已安装列表中。
- 官方市场的有效安装记录只从 YCode 官方插件存储根读取；第三方市场的安装记录只从原插件存储根读取。
- 概览、安装、更新和卸载必须使用同一安装记录来源规则。运行时发现结果不能被旧根目录记录覆盖为“已安装”。
- 卸载旧根目录中残留的官方记录时，必须按记录实际所属的根删除该记录与对应旧缓存；不得因按 marketplace 推断新根而返回 `null` 并遗留旧记录。
- 若同一插件 ID 在新旧根都有记录，YCode 官方根中的记录为有效安装；卸载后也必须清理旧根中的同 ID 遗留记录，避免列表再次显示旧状态。清理范围仅限目标插件记录和目标插件缓存，不触碰其他插件。
- 第三方插件的存储、概览与卸载语义保持不变。

## 迁移验收场景

1. 旧 `.zcode` 官方安装记录不会出现在当前已安装列表；卸载旧记录会清理旧根记录并返回明确结果。
2. 新旧根存在同一官方插件 ID 时，概览只显示新根有效记录；卸载后两边都没有该 ID 的残留安装记录。
3. 第三方插件记录仍只在旧插件根读取、显示、更新和卸载。

## 官方安装记录迁移的范围

本节约束官方市场安装记录的读取和清理规则；缓存内容完整性规则仍只针对 bundled 官方插件源。

## 官方源缺失

官方源整体缺失（SEA 无 manifest 且所有候选目录下都没有插件包）时同样 fail closed：bundled marketplace 清单保持为空，并以 warn 级日志记录搜索过的候选目录，不得静默返回。否则用户只能从插件消失推断故障，无法诊断官方插件资产缺失。

## 目标

官方插件的运行时缓存位于 YCode 专属用户目录，但缓存不是可信来源。启动时必须以当前应用随附的官方插件源为唯一事实来源，验证缓存完整后才允许其进入插件发现和子智能体加载流程。官方插件包缓存根为 `{dataBaseDir}/.ycode/cli/plugins`，包括随应用内置插件和官方市场安装插件；第三方插件缓存、插件用户数据及一般 ZCode 数据仍由原有存储根管理。旧 `.zcode` 官方缓存不搬迁、不删除，也不再作为官方插件运行时来源；旧官方市场安装项需重新安装。

## 可信边界

- 官方插件缓存的可信来源只有当前应用内置 filesystem/SEA seed 源。
- 缓存必须包含当前源声明的全部文件，并且不得包含额外文件或符号链接。
- 缓存中的每个文件必须是普通文件，内容 SHA-256 必须与当前源声明一致；需要注入桌面运行时路径的 `plugin.json` 以同一套确定性运行时变换后的内容为准。
- bundled marketplace 清单是官方缓存的运行时授权边界；清单缺失、损坏或写入失败时必须 fail closed，不能退回扫描整个 official cache。
- 清单更新与 seed 结果使用同一组进程锁协调；并发进程只能授权自己已验证或观察到完整验证成功的缓存。
- 用户配置只控制插件启停和存储根目录，不承担官方内容完整性证明。

## 启动行为

```text
官方源
  → 生成期望文件集合与 hash
  → 检查 marker、文件集合、文件类型和内容 hash
  → 命中：加载缓存
  → 不命中：原子重建后再加载
```

当 marker、版本、文件集合、文件类型或内容 hash 任一不匹配时，当前版本目录必须通过临时目录和原子替换流程重建。重建成功后才能进入官方 marketplace 清单和插件加载流程。

## 失败语义

当前官方源缺失 required seed 文件、无法读取或无法完成 seed 时，官方插件必须 fail closed：不得把未经过当前源验证的旧版本缓存作为运行时 official root。旧目录可以保留用于诊断或恢复，但不能被当作官方可执行内容加载。

## 范围边界

本规范只约束官方 bundled plugin cache。以下内容不纳入本次完整性判断：

- 用户主动安装的 marketplace 插件。
- 项目级 `.zcode/agents`、`.agents/skills` 和其他项目扩展。
- 配置中显式注入的 host `extraRoots`。
- 普通插件和用户技能的权限、启停与生命周期。

## 验收场景

1. 在官方插件 `agents/` 目录新增额外 Markdown 后重启：缓存被判定为不可信并重建，重启后额外 agent 不再出现。
2. 修改官方 `visual-judge.md` 后重启：文件恢复为当前应用内置内容。
3. 删除官方插件必需文件或加入符号链接后重启：插件不以未经验证内容继续运行，并产生可诊断的 degraded 状态。
4. 未修改的官方缓存重启：不发生不必要的目录重建，插件、skill、agent、hook 和 MCP 行为保持不变。
5. 普通用户插件和项目插件：继续按照原有加载和启停规则工作。
