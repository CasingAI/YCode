# Bash 只读权限：Git 工作目录

## 规则

- Ask 和 Plan 共用 Bash 只读判定。Windows 会话使用 Git Bash 时，`git -C /c/目录 …` 的盘符路径与 `git -C C:/目录 …` 使用相同的只读规则。其他 Shell 和平台不启用此转换。
- 只转换能够明确识别的 Git Bash 盘符路径。不能确定传给 Git 的目标时，不按只读放行。权限判定不改写原命令，也不增加 Git 子命令或选项的放行范围。
- 依次校验每个 `-C`。后一个相对路径以已校验的前一个目录为基准。每一步都要求目标存在、真实路径位于工作区内，并通过现有的 Git 运行目录检查。缺少工作区上下文、目标越界、链接指向工作区外或使用写命令时，继续拒绝。

## 所有者与接口

会话配置仍是 Shell 类型的唯一来源。CLI 执行器把会话的 Git Bash 类型传入 `@zcode/shared/node/bash-readonly` 的判定上下文。共享判定器负责解析 `-C`、转换路径及验证边界；执行器仍将原命令交给会话选定的 Shell。不新增配置、持久化状态或协议字段。

## 验收

1. Windows Git Bash 会话在 Ask 和 Plan 中可以执行使用 `/c/…` 指向工作区的 `git grep -n -i -E …` 和 `git log -25 --oneline --grep=…`，包括带引号的含空格路径。
2. 工作区外、不存在的目录、指向工作区外的目录链接、相对路径在第二个 `-C` 越界，以及 Git 写命令继续被拦截。
3. Windows 的非 Git Bash 会话和非 Windows 平台不将 `/c/…` 解释为 Windows 盘符路径。已有 Windows 原生路径和相对路径查询继续可用。
