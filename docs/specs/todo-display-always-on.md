# Spec：待办工具卡片始终显示

## 目标与产品规则

- 对话消息流中的 Todo 工具卡片始终参与渲染，不提供关闭选项。工具身份属于 `todo` 家族的 `TodoRead`、`TodoWrite` 及其既有别名沿用同一规则。
- 设置页删除“显示待办”开关；设置类型、校验 schema、页面本地状态、写回回调、国际化文案与用户操作追踪不再包含该选项。
- 普通工具行、展开后的过程内容、工具分组和子代理工具卡均使用同一条待办渲染路径；不保留可将待办隐藏的 prop、context 字段或用户偏好判断。
- “始终显示”表示不再按设置裁剪待办卡片，不强制展开整轮历史、父工具卡或其他既有折叠容器。待办内容、状态、布局与工具卡内部的既有展开行为不变。
- 待办不计入“查阅 / 终端 / 编辑 / 思考”四类过程桶，仍作为可见的独立平铺行隔开前后过程段。此次不修改过程折叠、间距或高度估算规则。
- 待办胶囊与状态面板继续读取既有 plan 投影，不因删除消息流显示选项而改变数据或行为。

## 状态所有者与接口

- 待办事实仍由既有会话运行时和快照所有，UI 读取工具调用行与 plan 投影，不新增待办状态或写入路径。
- `ConversationRowRenderContext`、`ToolCallBlock` 及其渲染 context 不再承载“是否显示待办”的字段；设置页也没有对应的本地副本。
- `AppSettings`、`appSettingsSchema` 与 `appSettingsPatchSchema` 不再声明 `messageStreamShowTodos`。
- 旧字段的兼容读取由设置 schema 的未知字段剥离行为负责，不增加迁移标记、RPC 命令或持久化分支。

```text
会话运行时（既有待办事实所有者）
  ├─ desktop-continuous：实时工具行 ───────────┐
  └─ web-remote-replayable：快照与恢复工具行 ──┤
                                            ▼
                              共享 UI 行投影（保持原顺序）
                                ├─ Todo 工具行 → 既有 Todo 渲染器
                                └─ plan 投影 → 待办胶囊与状态面板

旧设置文件/设置 patch → 设置 schema 剥离未知字段 → 无待办可见性状态
```

- 本次仅取消显示偏好，不修改实时或恢复链路的事件顺序、owner/lease、工作区身份与重放语义。

## 迁移边界与失败语义

- 旧 `setting.json`、共享设置消息或 patch 中即使含有 `messageStreamShowTodos: false`，读取后也不进入类型化设置对象，且不得隐藏待办。
- 旧值为 `true`、`false` 或缺省时，显示规则完全相同。
- 不直接批量重写用户设置文件；仅含该旧字段不触发专属迁移写盘。下一次正常设置写入使用 schema 结果，旧字段自然移除。
- 既有其他设置迁移与错误处理保持不变。工具数据为空、流式输入未完成或工具失败时，继续采用原 Todo 渲染器的既有行为，不新增兜底状态。
- 不修改用户的实时设置文件、会话数据库或已保存的工具结果。

## 验收场景

1. 设置页“常规”分区不再出现“显示待办”，中英文文案、状态和回调均已移除。
2. 全局设置与 patch 含旧字段 `false`、`true` 或缺省时，schema 输出均不含该键；旧字段不改变其他有效设置。
3. 读取仅含旧字段的设置文件不会触发专属迁移写入；正常更新其他设置后，落盘结果不再含旧键。
4. 会话行渲染 context 不提供任何待办显示偏好时，`TodoWrite` 行仍渲染工具卡片与待办内容；`TodoRead` 同样可见。
5. 工具卡嵌套子工具、分组和子代理入口没有可关闭待办显示的传参；普通未知工具仍使用既有 fallback。
6. 输入“过程行 → TodoWrite → 过程行”时，得到“两段过程与中间的可见待办行”；待办不计入四类过程统计。
7. 桌面与手机 Web 使用同一共享渲染规则，实时消息和历史恢复均不再依据旧设置隐藏卡片；现有历史折叠边界保持不变。
8. 待办胶囊、状态面板、其他工具卡、过程折叠与高度估算的回归测试通过。

## 验证

- 设置 schema 单测覆盖旧字段剥离；设置服务测试覆盖只读兼容与下一次正常写盘。
- UI 使用仓库现有 `node:test`、`react-dom/server` 与资源 stub 进行真实卡片渲染回归，并验证设置入口和透传字段移除。
- 回归现有过程折叠、工作项间距、工具离屏可见性与高度估算测试。
- 执行 `pnpm typecheck`、`pnpm lint`、格式检查及 `pnpm architecture:check --changed`。
- 交互验收场景：分别打开桌面/手机 Web 的设置页确认无开关；打开旧设置为关闭的会话，核对历史与新增 TodoRead/TodoWrite 卡片可见，父容器仍可按原规则展开/收起。当前仓库未提供对应 GUI E2E 入口，且未获准自动操作运行中的 YCode；未执行的交互验收必须明确报告，不以服务端渲染测试替代端到端结论。
