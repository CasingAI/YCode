# Spec：存储页把工具输出与临时缓存分开展示

## 目标

设置页「数据与统计 › 存储」把会话仍可能引用的工具产物，和可再生的临时缓存算进同一类。整类因此被标成不可清理，体积大时用户看不到哪一部分能扔。

本改动只拆分类与展示，不把工具产物整类变成可清理。

## 产品规则

- **工具输出**：会话仍可能通过产物引用打开的内容。包括工具结果留档、命令完整输出、工作流会话文件、子代理目录里除 transcript 以外的文件、checkpoint 进行中的 pending/tmp。整类仍不提供清理；任务删除或归档才是它的回收路径。
- **临时缓存**：删了可以再生成、或不被会话引用的过程文件。包括图片/视频/PDF 派生缓存、计划缓存、Bot 模型缓存、剪贴板落盘、编辑器图标临时目录、通用临时目录、checkpoint 用完应消失的 Git 临时 index。这一类提供直接清理。
- **官方插件缓存仍归运行时**：根下 `cache` 是官方插件安装缓存，继续算进「Agent 运行时与插件」，不进临时缓存，也不随临时缓存一起清。
- **子代理 transcript 仍独立**：`transcript.jsonl` 继续走「子代理产物」，24 小时活动窗口规则不变。
- **视频派生缓存归临时缓存**：此前未单独归类，会落到「其他」；本次并入临时缓存。
- 列表与磁盘图例仍按占用从大到小排列；两类各自有名称、说明、明细和下钻。临时缓存占用大于 0 时显示清理；工具输出不显示。

## 状态所有者

- 分类与可清理性的唯一事实源是存储目录（扫描时把相对路径映射到类别）。
- 扫描快照由存储服务持有；设置页只投影快照，不另存一份分类。
- 清理命令仍走存储服务既有入口：不可清理的类别拒绝执行；可清理类别按目录范围枚举后删除。

```text
扫描文件 → 存储目录分类 → 快照按类别聚合 → 设置页列表/明细/图例
用户点清理 → 存储服务按该类别的可清理性与范围删除 → 重新扫描
```

## 接口

- 共享类别 ID 增加 `temporaryCaches`；原 `toolOutputs` 只表示工具输出。
- 设置页文案键随类别 ID 派生，新增临时缓存的名称与说明；工具输出文案去掉「临时缓存」。
- 不新增协议命令；清理请求的类别字段使用新 ID 即可。

## 失败与边界

- 清理进行中的派生缓存或临时 index：删除失败记入部分失败，不回滚已删文件；下次使用会重新生成。
- 受保护文件名规则不变，即使落在临时缓存范围内也不删。
- 不把工具输出做成「只清无主产物」：那需要对照会话库，超出本次展示拆分。

## 验收场景

1. 存储列表出现两行：「工具输出」与「临时缓存」，不再出现「工具输出与临时缓存」。
2. 图片/PDF/视频派生缓存、计划缓存、Bot 模型缓存、剪贴板、编辑器图标临时目录、通用临时目录、Git 临时 index 计入临时缓存；官方插件 `cache` 计入运行时。
3. 工具结果留档、命令输出、工作流会话文件、子代理非 transcript 文件、checkpoint pending/tmp 计入工具输出；`transcript.jsonl` 仍计入子代理产物。
4. 临时缓存占用大于 0 时列表与明细有清理；工具输出始终没有。
5. 清理临时缓存后重新扫描，该类占用下降；工具输出占用不变；官方插件缓存占用不变。
6. 自定义数据路径启用后，home 根下遗留的 `v2` 仍归「其他」，不因本次拆分变成可清理。

## 验证

- 单测：`TSX_TSCONFIG_PATH=packages/ui/tsconfig.json node --import tsx --test packages/ui/test/storageCategoryPresentation.test.ts`（展示键覆盖全部类别 ID）。
- `pnpm typecheck`、`pnpm lint`（0 error）、`pnpm architecture:check --changed`（violations 0 / new 0）。
- 未在运行中的桌面端点开存储页；真机列表两行与清理按钮需在下次打开设置时确认。
