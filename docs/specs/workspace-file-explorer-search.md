# Spec: 文件浏览器的路径搜索与高级筛选

## 范围与产品规则

本规范重整「文件」主视图的文件浏览器顶部，并增强复用的 WorkspaceFileTree 搜索。它不增加全文搜索，不改变手机抽屉导航、全局左上开关、编辑器分屏或保存流程。

- 顶部只显示一次工作区名称。文件主视图继续用已打开工作区下拉选择文件树，名称旁保留新建未命名文件与更多操作；树不再另外显示同名根标题。普通文件树没有工作区选择器时仍显示自己的根标题。
- 更多菜单保留根级新建文件、文件夹、粘贴、打开本机资源管理器与复制路径，并提供刷新。根级右键和长按仍可达。新建未命名文件与命名后直接写盘的新建文件是不同命令，不合并写入路径。
- 搜索框常驻，明确搜索「文件名或路径」。输入即搜，不区分大小写，继续采用前缀、片段、子序列模糊匹配与精确路径优先；不读取正文。
- 搜索框旁提供可展开的筛选入口。展开时显示「包含」「排除」、搜索被忽略文件及 Git 可用时的「仅看改动」。收起不清除条件，入口显示正在生效的条件数量，并提供清除筛选；清除筛选不删除关键词。
- 包含和排除支持逗号分隔的多个路径通配符，去掉各项首尾空白、忽略空项。支持 `*`、`**`、`?`；不支持花括号展开、正则、`!` 反选或逗号转义，界面提供简短语法提示。使用现有文件关联通配匹配语义，不另写一套引擎。
- 模式按工作区相对路径匹配，Windows 反斜杠与正斜杠等价，不区分大小写。不含分隔符的模式匹配任意层级的名称；包含分隔符的模式从工作区根匹配。`**/` 可匹配零层目录。目录后缀 `/` 表示目录及其内容。
- 多条包含取并集，留空表示不额外限制；任一排除命中就移除，排除优先。关键词与路径条件取交集。包含、排除与搜索态的「仅看改动」条件都必须在 top-K 截断之前生效；Git 条件使用当前状态表的精确路径，不在截断后再次过滤。
- 关键词为空但存在包含、排除或「搜索被忽略文件」条件时仍进入搜索结果列表；仅开启「仅看改动」且没有其他搜索条件时保留既有变更树形态。关键词与范围都为空时显示目录树。
- 搜索结果平铺显示相对路径。打开文件继续复用现有预览/固定标签路径；点击目录清除关键词和搜索范围并定位目录，以免筛选态阻止目录揭示。关闭高级筛选不退出结果态。
- 最多显示 1000 条。用额外一个候选判断是否超限；超限明确提示只显示前 1000 条并建议缩小范围，不宣称结果完整。

## 索引与忽略边界

- 文件浏览搜索使用现有 IFileService 文件索引读取通道，新增可选的浏览器用途参数；旧调用缺省保持原有文件引用/快速打开语义。
- 浏览器用途按名称收录普通文件、隐藏文件、目录和二进制产物，不沿用为文件引用设计的 `.env`、编译产物和隐藏目录条目硬过滤；默认仍应用工作区 `.zcodeignore` 的目录/文件排除。
- 「搜索被忽略文件」仅在本次浏览搜索跳过 `.zcodeignore`，不改写该文件，不改变 `@`、命令中心或快速打开候选；不读取文件内容，不自动向聊天添加文件。
- 规则文件自身在浏览器用途中可被搜索；旧用途维持现有行为。符号链接可以作为条目，不递归跟随目录符号链接，避免越界遍历与循环。
- 同一个 Host 的缓存按 `workspaceIdentity?.trim() || workspacePath`、用途、是否跳过忽略规则隔离，并验证路径及规则指纹；用途或选项不能共享错误的整包索引。
- 显式刷新在长度请求上绕过 TTL 重扫，后续分块不能重复强制刷新。文件变更继续走现有失效路径，在途旧扫描不得覆盖新缓存。现有长度 / 范围接口没有快照 token；本次沿用其一致性边界：常规分块复用同一缓存，但跨越 TTL 或并发刷新替换缓存时不保证跨块强一致，不新增假定的快照协议。
- 原有文件引用用途的自定义过滤器继续只支配原用途；不让浏览器的扩大范围修改聊天引用的安全与产品边界。

## 状态所有者与接口

- WorkspaceFileTree 是关键词、包含/排除输入、展开状态、搜索被忽略文件和仅看改动的唯一 UI 所有者，不持久化，不新增 Zustand 状态。
- 切换工作区身份、路径或远程服务目标时清空本次条件与旧结果；远程调用继续经 useWorkspaceServices 路由到对应服务，不根据路径自行选择连接。
- Host IFileService 实例独占文件索引与缓存。shared 的纯匹配函数只决定候选范围与排序，Worker 和同步降级复用同一语义。
- 关键词或筛选变化只在本地 Worker 过滤；用途、忽略选项、工作区或显式刷新变化才重新请求 Host 索引。旧请求通过 generation/清理规则丢弃，不能把旧工作区或旧忽略模式的结果呈现在新上下文。
- 加载、过滤、索引读取错误和无结果应可区分。扩大搜索范围加载时不把旧范围结果当作新范围的已完成结果。Worker 创建或运行失败时复用现有同步后端，以相同索引、关键词和筛选规则计算，不把故障当成无结果，也不靠超时重试或丢弃规则。

```text
用户输入/筛选 → WorkspaceFileTree（唯一临时条件）
                  ├─ 工作区/忽略模式/刷新 → useWorkspaceServices → Host IFileService 索引
                  │                                           └─ 用途与身份隔离缓存
                  └─ 索引 + 条件 → Worker 纯匹配 → 排序/截断提示 → 结果列表
文件/目录点击 → 既有打开/定位命令；不新建读写服务或聊天引用路径
```

Desktop 与手机 Web/远控复用以上 IFileService 请求语义；不修改 `desktop-continuous` 会话流或 `web-remote-replayable` 恢复链路，不新增会话事件与业务队列。

## 自动化验收

实现前先补充相应测试，再执行当前包可用入口：

1. 包含 `**/*.ps1` 命中根目录与嵌套脚本；排除 `**/overlay-*.ps1` 后保留其他脚本。多包含并集、关键词交集、排除优先及 Windows 分隔符有纯函数覆盖。
2. 无关键词但有范围时返回候选；没有条件时继续树形态。候选筛选先于限制，早期不匹配项不能挤掉后续匹配项；第 1001 项触发截断提示。
3. 原用途仍排除 `.env`、编译产物；浏览用途默认可索引它们但遵循 `.zcodeignore`；搜索被忽略文件可以命中被忽略目录内条目且不改变原用途结果。用途、身份、忽略模式缓存独立。
4. 显式刷新可在 60 秒 TTL 内看到外部新建文件；旧扫描不能污染新缓存。真实 RPC 分块调用保留新选项并返回同一语义。
5. 渲染/交互测试覆盖筛选折叠、数量标识、清除保留关键词、搜索范围切换及根操作可达。英文与中文文案键完整，控件使用既有组件和 text-ui-\* 字号；手机可编辑框遵守 text-mobile-input-safe。
6. 回归现有模糊搜索、精确路径优先、文件操作、快速打开与文件语言关联测试。

## GUI / E2E 场景

以下场景应在用户明确允许操作隔离应用后执行；普通改码授权不构成对运行中 YCode 的 UI 自动化或调试协议授权。

- 320px、430px 与桌面宽屏：工作区名称只显示一次，搜索与筛选入口可点，包含/排除输入不横向溢出；展开与收起不丢条件。
- 输入关键词后增加包含、排除，结果按交集变化；只设通配符也能列出文件；清除筛选保留关键词。
- 条件收起后入口持续显示数量；无结果、加载失败和 1000 条截断分别给出准确反馈。
- 开启搜索被忽略文件后能找到测试工作区的忽略目录和 `.env` 名称；关闭后恢复默认，`@` 候选不随之改变。
- 点目录结果回到树并揭示目录；点文件仍打开既有标签，手机自动收起抽屉；切工作区不收抽屉但清除旧条件。
- 更多菜单刷新、根级新建文件/目录、粘贴、复制路径以及桌面资源管理器入口保持现有可用性规则。
