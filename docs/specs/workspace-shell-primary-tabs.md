# Spec: 工作区外壳主视图（任务 / 设置）

## 目标

设置不再是盖住工作区的窗口级覆盖层。有项目时，任务与设置共用同一套左右外壳：左栏底部常驻「任务 / 设置」导航条，点哪一边，左栏列表和右栏正文一起切到哪一边。窄屏导航条跟左侧可操作区走，只出现在抽屉底部。

此前设置是独立 `SettingsPage` 覆盖层（`SETTINGS_TAB_ID` 激活时把工作区做成透明不可点），左栏是另一套固定栅格，不能拖宽度，中等窗口还会收成图标栏。

## 产品规则

### 主视图身份

- 外壳主视图只有两档：`tasks` | `settings`。
- **任务**：左栏为工作区任务/项目列表；右栏为会话，或自动化 / 插件市场这些工作区内页面（`workspaceMainView`）。
- **设置**：左栏为设置分区目录；右栏为对应设置正文。
- 自动化、插件市场仍只作为任务主视图下的工作区内页面，不回到设置分区目录。

### 导航条

- 位置：左栏最底部。不做成整窗底栏，不抬到顶部浮层。不再在导航条上方另留头像 / 账号 / 远控底栏。
- 三格：任务、设置、更多。任务与设置是主视图，当前项有选中态，点当前项为无操作。
- 「更多」不是第三档主视图：只打开杂项下拉（远控、语言、主题、界面模式、缩放、用量、登录/退出），不切左栏 / 右栏。细则见 `workspace-shell-chrome-more.md`。
- 宽屏始终可见。窄屏只在抽屉打开时可见（跟左侧可操作区走）。
- 侧栏原齿轮入口删除；进设置只走导航条、快捷键、用量/管模型等带分区意图的命令、以及地址栏 `/settings`。

### 窄屏抽屉

- 断点与呈现形态仍走 `workspace-shell-responsive-layout.md`。设置外层不再自写抽屉、三档栅格或返回工作区按钮。
- 切任务/设置只换抽屉里的列表，**不收起抽屉**。打开底栏「更多」或点远控，也不收起抽屉。
- 点中一条任务、一个设置分区、命令面板、自动化、插件市场、新建任务，仍按「导航完成即收起」收起抽屉。
- 收起跟在导航之后，不替代它。

### 宽度与 chrome

- 设置共用工作区侧栏的宽度轴：可拖、可记、下限/上限不变。不再使用设置页自己的 68px / 268px 栅格。
- 供应商/模型组的分区内主从（`SettingsMasterDetailLayout`）不动。
- 设置行与快捷键表在 < 640px 的堆叠不动。

### 保活

- 切到设置时，会话列、终端、右侧浏览器继续挂在 React 树上，只是不画、不可点。不要用整页覆盖层把工作区标成 inert。
- 切回任务时，`workspaceMainView` 保持进入设置前的值，不强制回到会话。
- 任务区里的状态胶囊、侧栏、建议条都是任务主视图的东西，切到设置后不得再露出来，也不保留「半透明压在设置上」的中间态。
- 藏法不能用「看不见」（子节点可以自己改回可见，状态胶囊已经这么做了），也不能把整棵任务树摘出布局（分栏、终端、浏览器还要保住盒子尺寸）。正确做法：设置正文是不透明的上层；任务树留在下层，整层透明且不可点，并把内部浮层关在这一层的层叠上下文里。不要靠把某个浮层的层级调低来堵漏洞。

### 无项目退化页

- 没有打开任何项目时不挂整棵工作区树。
- 单独渲染视觉对齐的设置页：左栏为分区目录 + 导航条（含「更多」），任务项不可用。
- 有项目之后走外壳主视图，不再盖覆盖层。

## 状态所有者

| 状态 | 所有者 | 说明 |
| --- | --- | --- |
| 任务还是设置 | `tabStore` 的设置 tab 激活态 | `openSettingsTab` 切到设置；激活 workspace tab 切回任务。外壳只投影，不另存一份。不再把该态解释成覆盖层。 |
| 会话 / 自动化 / 市场 | `App.tsx` 的 `workspaceMainView` | 仅在任务主视图下有效；切去设置时记住。 |
| 设置停在哪个分区 | `settingsNavigation.ts` | 分区意图与上次分区偏好。 |
| 左栏宽、显隐、抽屉形态 | 工作区外壳既有所有者 | 设置不再另写一套。 |

```
用户点导航条 / 快捷键 / 带分区意图的入口 / 地址栏 /settings
  └─ openSettingsTab 或 activateWorkspaceTab
       └─ 外壳投影 primaryView
            ├─ tasks → 左：任务列表；右：workspaceMainView
            └─ settings → 左：设置分区；右：设置正文（下层会话树保活、不画、不卸载）
```

窄屏切 tab 不写 `isSidebarVisible`。点分区/任务才走 `shouldCollapseWorkspaceSidebarAfterNavigation`。

## 负面边界

- 不新增第三档主视图。「更多」只是下拉，不得扩成 `WorkspaceShellPrimaryView`。
- 不把导航条做成整窗底部或顶部浮层。
- 不恢复设置覆盖层。
- 不把自动化/插件市场搬回设置目录。
- CLI/runtime、协议、持久化业务设置项一律不动。

## 验收场景

1. 宽屏有项目：左栏可拖、刷新宽度保持；底导航可在任务/设置之间切换，左右一起换；齿轮与头像行消失；第三格「更多」打开下拉、不切主视图。
2. 快捷键与 `/settings` 进入设置主视图，工作区不被整页盖住；任务状态胶囊、顶栏、侧栏都不得露在设置正文上；切回任务后会话、终端、浏览器页签还在。
3. 从自动化进设置再切回任务：仍停在自动化，不强制回到会话。
4. 窄屏：抽屉未开时看不到导航条；打开后切任务/设置只换列表、抽屉仍开；点分区或任务后抽屉关、正文满宽。
5. 无项目仍能进设置，任务项不可用。
6. `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 通过。
