# Spec: 系统设置页的窄视口布局（行堆叠 + 内层主从）

## 目标

设置外层左右分栏已并入工作区外壳（见 `workspace-shell-primary-tabs.md`）：分区目录住在左栏，窄屏走工作区抽屉，不再使用设置页自己的三档栅格、覆盖层或返回工作区按钮。本 spec 只覆盖设置**正文内部**在极窄宽度下的行堆叠，以及分区内主从的既有窄屏规则。

此前的窄屏处理是设置页自写抽屉 + `max-lg:` 图标栏；`SettingsRow` 的控件列固定 192px，375px 视口下标签列只剩约 60px，中文标签与描述被挤成竖排单字。外层那套已经废止。

## 产品规则

### 外层形态

- 有项目时外层形态、抽屉开合、导航条位置全部委托 `workspace-shell-responsive-layout.md` 与 `workspace-shell-primary-tabs.md`。
- 设置页不再持有 `isNavDrawerOpen`，不再渲染 68px/268px 栅格，不再在顶栏放返回/分区开关。
- 点选设置分区仍算「导航完成」：窄屏抽屉收起，正文满宽。
- 无项目退化页视觉对齐左栏结构，任务项不可用；不挂整棵工作区树。

### SettingsRow 行堆叠（< 640px）

- `SettingsRow` 默认栅格从 `grid-cols-[minmax(0,1fr)_192px]` 改为移动优先：**< `sm`（640px）单列堆叠**——标签与描述在上，控件在下、左对齐、允许换行（`flex-wrap`）；≥ `sm` 恢复既有两列右对齐，观感不变。
- `controlLayout: "wide"` 变体同样在 < `sm` 堆叠（`sm:grid-cols-[minmax(0,1fr)_280px]` 不变）。
- 阈值取 `sm` 而非自定义断点：640px 以下内容列（扣除边框与内边距）不足以为 192px 控件列保留可读标签宽度；640–768px 虽仍两列但标签列 ≥ 300px，可读。

### 模型行换行（流式，无断点）

- `ModelRowInput`（`packages/ui/src/settings/model-provider-section/ProviderFormControls.tsx`）行主容器与左侧信息区允许换行（`flex-wrap`）：行宽足够时保持现有单行紧凑布局；行宽不足时操作组（测试/编辑/删除/开关）整体折到第二行右对齐，徽标先折到模型名下一行，模型名保留 `truncate` 不再被压到单字。
- 操作按钮组包一层不拆散的容器，换行后两行保持 `8px` 级紧凑间距；不新增颜色、字号与断点，桌面宽屏观感不变。
- 徽标文案口径（K/M/B）、视觉徽标显隐规则、增删改开关行为不变。

### 快捷键表堆叠（< 640px）

- 表头只保留「命令 / 操作」两列，键位与作用域表头隐藏。
- 数据行改为两行栅格：第一行命令名 + 操作；第二行键位组（占满行宽，键帽序列可换行）+ 作用域文本。≥ `sm` 恢复既有四列。
- 窄屏下操作列表头与操作控件统一右对齐，与同一列的作用域文本共享右边界（宽屏的操作列居中口径见 `keyboard-shortcuts-settings.md`）。

### 根网格高度口径（无项目退化页）

- 无项目退化设置页的根高度必须与窗口框架的动态视口对齐：使用 `h-dvh`，**禁止 `h-screen`/`100vh`**。
- 原因：外层 `DesktopWindowFrame` 与 `#root` 都是 `h-dvh` + `overflow:hidden`。手机浏览器上 `100vh` 会把地址栏区域算进高度，根网格比可视区高出一截，滚动条滚到底也够不到。
- 有项目时设置正文吃工作区内容列高度，不再自建根网格，嵌入式页面使用 `h-full`，独立窗口使用 `h-dvh`。
- 测试应分别定位嵌入式与独立窗口布局，而不是仅匹配第一个设置页 data-testid。

### 不改动项

- `SettingsMasterDetailLayout`（供应商和模型等内层主从）维持 56px 窄栏与 `md:224px` 栅格：其导航承载 dnd-kit 纵向拖拽排序，横向化会破坏排序语义。模型组页按 `model-group.md` 的窄屏呈现走：左栏文字组名收为首字入口（`sr-only` 保留组名），详情区行允许换行，不新增断点。
- 各分区的表单、对话框、面包屑投影逻辑不变；本 spec 只覆盖纯呈现层。
- safe-area / `viewport-fit=cover`：仓库 `env(safe-area-inset-*)` 仅用于 toast，`packages/web/index.html` 的 viewport 也没有 `viewport-fit=cover`；手势条遮挡属于另一件事（需改 viewport meta 与多处底部内边距），且它无法解释「能滚但滚不到底」，本次不纳入。

## 验收场景

1. Web 版 375px：常规/外观/网络/浏览器控制/记忆/实验特性分区的每一行标签与描述完整换行，不再出现一字一列竖排；控件堆叠在标签下方。
2. Web 版 375px：设置分区目录在工作区抽屉里；点选分区后抽屉收起并切换正文。外层没有独立的返回按钮或设置专用导航开关。
3. Web 版 375px：快捷键表行内命令名完整、键帽组可换行、作用域可见。
4. Web 版 768px 与 1440px：设置共用工作区可拖侧栏，不再出现 68px 图标栏；行两列右对齐、快捷键四列表。
5. 桌面端（共用组件）≥768px 与工作区外壳一致；窄窗口下走工作区抽屉。
6. 纵向滚到底可达：Web 版 375px（地址栏展开状态）把任意长分区滚到底，最后一行完整露出，其下留有底部内边距；地址栏收放前后底部依然可达。
7. `pnpm typecheck` 与 `pnpm lint` 通过。
