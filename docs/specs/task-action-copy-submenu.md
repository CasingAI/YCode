# Spec: 任务菜单的「复制信息」二级菜单

## 目标

任务右键菜单原来有 11 行，其中「复制路径 / 复制任务路径 / 复制日志路径 / 复制会话 ID」四项以和置顶、重命名完全相同的行权重平铺在一级——除了「复制路径」，其余三项都是排障时才会用到的低频诊断动作，却占据了和主流程动作一样的视觉位置。

本次把这四项收进一个名为「复制信息」（`taskList.copyInfo` / `Copy info`）的二级菜单，一级菜单只剩任务管理动作。

## 产品规则

### 折叠范围

以下四项是折叠的全部对象，出入二级菜单时保持原有顺序、文案、`disabled` 条件、`title` 理由和 `onSelect` 回调，一行逻辑不改：

1. 复制路径
2. 复制任务路径
3. 复制日志路径
4. 复制会话 ID（仅 `onCopySessionId` 存在时渲染）

一级菜单从 11 行缩到 6 行：置顶 / 重命名 / 归档 / 标记为未读 / 在分屏打开（仅桌面）/ 在文件管理器中打开，之后是一条 `Separator`，再是「复制信息」子菜单触发器。

### 子菜单触发器的禁用规则

`SubTrigger` **只**在 `disableTaskActions`（只读态）时禁用，`title` 挂 `disabledReason`；**不**受 `disableTaskTargetActions` 影响。

理由：`disableTaskTargetActions` 由 header 的 `taskMenuMembershipLoading` 派生，它只禁用后三项，「复制路径」此时仍可用。如果触发器跟着它一起禁用，会出现「唯一可点的复制项点不到」——为了折叠菜单反而制造死路。只读态下四项全禁用，触发器一并禁用是准确的，且和同级「在文件管理器中打开」的既有行为一致。

### 共用约束

任务右键和工作区标题栏「⋯」下拉共用 `TaskActionMenuContent`，注入的只是渲染原语（`ContextMenu*` / `DropdownMenu*`），本次把 `Sub` / `SubTrigger` / `SubContent` 三个槽位接进来，两处入口同时折叠，不存在只改一处的中间态。

## 状态所有者与事件顺序

无新增状态。子菜单的开合是 Radix 内部状态，不进 zcode store。复制回调实现（`handleCopyText`、toast、剪贴板兜底）一行不碰。

## 负面边界

- 分组任务列表右键菜单（`workspace-grouped-tasks/task-context-menu-content.tsx`）是独立实现，同样有四项复制项，**本次不改**。
- 折叠后四项复制动作没有命令面板或快捷键入口——这是复制了 `sidebar-more-menu.md` 的同类取舍，有意识接受。
- 文件树的「复制路径」是另一条路径，不动。

## 验收

1. 侧边栏右键任意任务 → 一级菜单只剩 6 行，「复制信息」带右箭头；悬停展开后是原来那四项，顺序、文案、禁用态与折叠前完全一致。
2. 工作区标题栏点「⋯」→ 同一份折叠后的菜单，作用对象仍是当前激活任务。
3. 任务列表展开过程中（成员关系加载中）右键 → 「复制信息」仍可展开，「复制路径」可点，后三项仍灰着。
4. 只读态右键 → 「复制信息」整行灰掉，悬停出禁用理由。
5. 逐个点四项复制动作 → toast 文案和剪贴板内容与改动前一致。
