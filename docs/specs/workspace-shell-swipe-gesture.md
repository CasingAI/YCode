# Spec: 窄视口下大幅右滑打开侧栏

## 目标

窄视口（≤768px）下侧栏是覆盖式抽屉（见 `workspace-shell-responsive-layout.md`），目前只能点左上角浮层的那颗开关按钮打开。在手机上这是主要的导航入口，但「点按钮」要求用户精确命中 28px 的目标，滑动比点击容易得多。

本条规范给侧栏抽屉增加一个手势入口：**在会话界面里做一次大幅度的从左往右滑动，拉出侧栏**。滑动是触发式的——手势本身即意图，触发后走抽屉既有的 200ms 滑入动画，不做手指跟手。

这条规范只覆盖「打开」。抽屉打开后的关闭仍走既有的点遮罩与浮层开关，不新增反向手势。

## 产品规则

### 适用范围

- **只在任务主视图的会话阅读面生效。** 外壳主视图必须是 `tasks`，且工作区主视图是会话阅读面 `chat`。文件主视图（含文件树、Monaco、空态）、设置、自动化与插件商店都不启用本手势。文件编辑面的横向手势、滚动条拖动与文本选择全部归编辑器；不读取 Monaco 内部滚动状态，也不把 Monaco 内部节点加入让位选择器。
- **只在抽屉形态生效。** 宽视口（≥768px）侧栏是内联列，本来就常驻可见，没有「打开」这回事。判定读 `resolveWorkspaceSidebarPresentation()`，与外壳形态同源。
- **只在侧栏收起时生效。** 侧栏已展开时它是覆盖在内容之上的模态层，遮罩吃掉全部触摸事件，手势无从谈起。
- **只认触摸。** 手势走 touch 事件，鼠标拖拽不触发——鼠标拖拽在会话里是选择文本的既有语义，不能抢。
- 桌面 Electron 的窄窗口与 Web 同等生效，不按平台分叉。

### 手势定义

「大幅右滑」= 一次触摸序列中，**净右移量**达到阈值：

- 阈值 = `max(96px, 视口宽度 × 25%)`。取两者的较大值：固定下限保证小屏上不会因为屏宽小而把阈值压到几十像素（那会让「随手一划」误触发）；比例项保证大屏上仍然需要一次**明显的大幅**滑动，而不是轻微的手腕动作。
- 判的是**净位移**（`clientX` 相对起点的差），不是路径长度。滑出去再滑回来不算数。

### 方向仲裁

- 第一次位移超过 **8px** 时锁定方向：`(|dx| >= |dy|)` 判为横向，否则判为纵向。
- **纵向立即作废整个手势。** 竖向是滚动意图，绝不与滚动竞争。
- **向左也作废。** 本次只做打开方向。
- 锁定之后不再改判：手指先右后下的斜向滑动，按横向累计净位移；斜向滑动不会误触发（净右移量达不到阈值）。
- 手势全程**不调用 `preventDefault`**，不干预浏览器的原生滚动与文本选择。判定与让位都是「观察」而非「拦截」。

### 让位规则：起手点落在谁身上，手势就归谁

会话内容里有大量能横向滚动的元素（代码块、Markdown 表格、内联 diff、Mermaid 图、多图图集），它们和本手势争夺同一次触摸。规则是**起手点决定归属**，在 `touchstart` 时一次性判定：

1. **输入区（composer）不做手势。** 用户在输入区的意图是打字与选模型，不是导航。composer dock 整体排除。
2. **终端面板排除。** 终端有自己的选区与滚动语义。
3. **右侧 Side Pane 覆盖层排除。** 那是另一个模态层，滑动应归它。
4. **侧栏自身排除。** 收起态侧栏是 `pointer-events-none`，本来就收不到触摸；这一条只是兜底。
5. **可横向滚动的容器排除。** 判定：沿事件的 `composedPath()` 自下而上找，找到任何一个「`overflow-x` 是 `auto`/`scroll` 且内容确实超宽（`scrollWidth - clientWidth > 1`）」的祖先，就放弃手势，让该容器自己滚。
   - **必须用 `composedPath()`，不能用 `closest()`。** 代码块的滚动容器在 `@pierre/diffs` 的 Shadow DOM 里，事件在 shadow 树外被重定向到宿主，`closest()` 看不见内部节点。
   - **判「内容确实超宽」而不是「容器有 overflow-x」。** 代码块默认不换行（`wrapLongLines` 默认 false），但用户开了「自动换行」后内容就不再超宽——此时滑动应当打开侧栏。开了换行的代码块不该因为「长得像滚动容器」而一直被排除。
   - 这条用运行时判定而不是给每个组件挨个打标记，以后新增横向滚动元素自动生效。
6. **文件编辑面在订阅层整体排除。** 文件主视图不启用本手势，因此从 Monaco 最左侧、编辑器滚动条或文本选区起手的右滑都不会打开侧栏；不要为了判定去读取 Monaco 的 `scrollWidth` / `scrollLeft` 或内部滚动 DOM。任务会话里的代码块等仍按第 5 条让位。

### 触发时机

- **抬手时提交，不在越过阈值的瞬间提交。** 若在滑到一半时就把抽屉展开，抽屉的遮罩会落到用户手指底下；抬手时浏览器合成 click，命中判定可能落到遮罩上，把刚打开的抽屉又关掉。改成抬手时提交就没有这个窗口：整个触摸序列期间侧栏都是收起态，遮罩始终 `pointer-events-none`。
- 触发后本次触摸序列作废，不再重复触发。

### 与既有开关的关系

- 浮层里的侧栏切换按钮**始终是**唯一可点的开合入口，本手势是**并存的第二条路径**，不替换它。抽屉展开后按钮仍在原位可点。
- 手势只写 `isSidebarVisible` 这一根轴，不新增状态、不新增第二份显隐真相。抽屉的滑入动画、遮罩、层级全部复用既有实现。

## 状态所有者与事件顺序

```
启用条件：抽屉形态 && 侧栏收起 && 外壳主视图 tasks && 工作区主视图 chat
  └─ 触摸序列
       └─ touchstart（shell 根）
            ├─ 记录起点 clientX/clientY
            └─ 让位判定：composedPath 上有输入区 / 终端 / Side Pane / 侧栏 / 可横向滚动容器 → 整个序列作废
       └─ touchmove（shell 根）
            ├─ 未锁定且位移 < 8px → 继续观察
            ├─ 锁定为纵向或向左 → 整个序列作废
            └─ 锁定为横向 → 继续累计净右移量
       └─ touchend
            └─ 净右移量 ≥ max(96px, 视口宽 × 25%) → 请求打开侧栏
                 └─ useAppPanels 的 showSidebar() → setIsSidebarVisible(true)
                      └─ 抽屉按既有 200ms translate-x 滑入 + 遮罩淡入
```

- `isSidebarVisible` 仍是显隐的唯一状态源，归属 `packages/ui/src/hooks/useAppPanels.ts`。本条规范只增加一个**幂等**的写入口 `showSidebar()`：滑动语义是「打开」而不是「翻转」，不能复用 `handleToggleSidebar()`——那会在侧栏已展开时被解释成「关闭」。
- 手势过程中不写任何 React state。判定用的起点、方向、累计位移全部放在 ref 里，随触摸序列结束而丢弃。

## 接口

- `packages/ui/src/app-shell/workspaceShellSwipeGesture.ts`：手势判定的纯函数，不读 DOM——方向锁定、阈值计算、是否达阈值、是否算横向滚动容器，以及手势状态机（`createSwipeGestureState` / `advanceSwipeGesture`）。状态机单独抽出来是为了能被 `node --test` 直接覆盖：接线部分在 hook 的 effect 闭包里，没有 DOM 就跑不起来。
- `packages/ui/src/app-shell/useWorkspaceSidebarSwipe.ts`：把纯函数接到真实触摸事件上，订阅目标为 shell 根元素；让位区域的选择器常量 `WORKSPACE_SWIPE_BLOCKED_SELECTOR` 也在这里。
- `packages/ui/src/hooks/useAppPanels.ts`：新增 `showSidebar()`，幂等地把侧栏置为可见。
- `packages/ui/src/app-shell/WorkspaceShellLayout.tsx`：仅在「抽屉形态 && 侧栏收起 && 外壳主视图 `tasks` && 工作区主视图 `chat`」时启用手势订阅；文件主视图、设置、自动化与插件商店不订阅。新增 `data-workspace-side-pane-wrapper="true"` 标记，供让位判定排除右侧覆盖层。

## 已知限制

- **iOS Safari 的边缘返回手势会抢走屏幕最左侧约 20~30px 起手的触摸。** 从屏幕中部起手的手势不受影响。这是可接受的降级，不是阻塞项：手机的系统边缘手势优先级高于网页，网页无法覆盖。
- **手勢不做跟手。** 抽屉在抬手后整体滑入，滑动过程中没有视觉反馈。跟手需要绕开抽屉的 `transition-transform`（过渡属性与位移属性同源这条不变式，见 `workspace-shell-responsive-layout.md`）并引入拖拽进度，是另一条独立的改动。
- **斜向滑动不算。** 净右移量必须真的达到阈值，一次明显的斜向划动通常达不到。
- 本检出没有 E2E 基建（无 vitest/playwright），手势的判定逻辑用 `node --test` 覆盖，真实触摸行为靠手动验收。

## 验收场景

1. 手机竖屏（约 390px）打开网页版工作区，在会话正文里从左往右划一段明显距离（≥98px）后抬手：侧栏从左侧滑入并带遮罩，约 200ms。划一段短距离（<98px）抬手：什么都不发生，会话不位移。
2. 同一屏里从左往右划，但划到一半改成向下拖：这是竖向滚动，浏览器正常滚动会话列表，侧栏不打开。
3. 同一屏里从右往左划：什么也不发生（本次不做关闭手势）。
4. 在代码块上（未开自动换行、长行超宽）大幅右滑：代码块横向滚动，侧栏不打开。在同一块代码上开了「自动换行」后大幅右滑：侧栏打开。
5. 在 Markdown 表格上大幅右滑：表格横向滚动，侧栏不打开。
6. 从输入框或输入区工具条上大幅右滑：侧栏不打开，输入行为正常（文本不被选中、不被改写）。
7. 侧栏已展开时在会话里右滑：什么也不发生（遮罩吃掉触摸）；点遮罩仍能收起。
8. 宽视口（1280px）下在会话里右滑：什么也不发生，侧栏本来就是内联列常驻可见。
9. 桌面窄窗口（约 700px）下用触摸屏右滑：侧栏打开；用鼠标右键拖拽选择文本：走浏览器原生选择，侧栏不打开。
10. 侧栏用右滑打开后，点击浮层里的切换按钮仍能收起，且按钮屏幕坐标不跳。
11. 文件主视图（320px / 430px，含空态与已打开大文本）在文件树、Monaco 最左侧、编辑器滚动条和文本选区上大幅右滑：侧栏都不打开；Monaco 的横向滚动、滚动条拖动与文本选择保持原语义，且判定过程不读取 Monaco 内部滚动 DOM。
12. 设置、自动化与插件商店里大幅右滑：侧栏不打开；切回任务会话阅读面后同一手势恢复。
13. `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 通过；新增的 `node --test` 用例通过。

验收命令（沿用仓库既有约定，`.js` 说明符指向 `.ts` 源文件）：

```
TSX_TSCONFIG_PATH=packages/ui/tsconfig.json node --import tsx --test packages/ui/test/workspaceShellSwipeGesture.test.ts packages/ui/test/workspaceShellSwipeWiring.test.ts
```
