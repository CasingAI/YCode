# 会话上下文与缓存统计冷恢复修复

## 背景

`snapshot.usage.contextWindow` 是运行时快照。冷恢复时 `seedUsage()` 整体提前返回
（`usedTokens > 0` 即跳过），导致事件重放恢复了用量、却缺缓存字段时无法补齐。
前端另有 78% 命中率展示门槛，低命中率被隐藏。

## 规则

- `seedUsage()` 改为字段级合并：已恢复用量缺缓存时补缓存；两者皆无则全量恢复；
  实时事件（`touchedByEvent`）的权威值不被覆盖；旧分支/旧模型数据不覆盖当前态；
  容量未知时不伪造（`contextWindow` 保持 null，内部 `usedTokens` 仍保留）。
- 缓存命中率口径：`cacheRead / input` 加权总体值，不重复计分母；无有效数据返回未知。
- 前端：取消 78% 门槛；可计算即显示真实值（含 0% 显示 "0%"），无法确认显示未知。
- 展示唯一来源仍是 `ConversationSnapshot.usage`；不新增表/字段/迁移/协议字段/模型调用。

## 验收（实机测试暂缓）

- AC-01/02/10/11：重启恢复用量、命中率、低命中率与明细（代码走查 + 单测）。
- AC-03/04：0% 显示、无数据未知不伪造。
- AC-05/06/07/08/09：compact/fork/并发/切模型/重复打开不污染（代码走查）。
- `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 通过。

## 工具栏用量展示补充（2026-10-18）

- 工具栏悬浮详情采用紧凑标题、Token 数值、分段进度条与按来源排序的明细；明细占比按既有 breakdown 计算，不生成虚构用量。
- 缓存命中率只要可计算即展示，包括 0%；无有效统计时不展示缓存命中行。
- 移动端触摸工具栏入口必须能打开详情，且复用受控展开时已有的额度刷新行为；桌面 hover/focus 保持不变。
