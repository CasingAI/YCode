# Spec：存储独立清理对话框

## 目标

设置页「数据与统计 › 存储」当前每类只能整类全清（只有日志留当天、子代理跳过 24h 活跃），而占大头的命令完整输出（`cli/exec`）被锁在不可清理的工具输出里，用户清不动。

本改动把「逐类一键清空」改成独立清理对话框：勾选要清的内容、选「24 小时前 / 7 天前 / 30 天前 / 全部」，确认后一次发给存储服务。命令完整输出从工具输出里拆出来可清理；打开会话和继续聊天不依赖这些文件。

## 产品规则

- **清理入口独立**：存储分区顶部与「重新计算」并列一个「清理…」。分类行和明细页去掉逐条清理按钮，只保留占用、说明、下钻。
- **对话框是草稿**：勾选内容和时间范围只存在对话框内，确认后才发给存储服务。不清会话库、配置凭据、运行时/插件、未归类。
- **时间范围**：24 小时前 / 7 天前 / 30 天前 / 全部（默认 30 天前）。前三项按文件修改时间（mtime）过滤，只删 `now - mtime >= olderThanMs` 的文件。
- **近期活动保护**：24 小时前、7 天前和 30 天前仍保护最近 24 小时有活动的子代理与命令输出会话目录；「全部」不执行活动保护。
- **日志规则**：前三项均保留当天日志；「全部」删除所选类别中所有符合类别规则的日志文件，包括当天日志。
- **全部删除警告**：执行前必须再次确认，明确说明文件将永久删除、无法恢复，且可能影响正在运行的任务。
- **删除范围**：「全部」只影响用户勾选的可清理类别；仍拒绝会话数据库、配置凭据、运行时/插件和未归类类别，并继续跳过受保护文件名。文件删除失败必须计入结果并反馈。
- **打开会话、继续聊不依赖被清文件**。图和完整命令原文可以没；工具卡摘要和聊天文字仍在。不为此做「已清理」专用协议。
- **按路径读取已清理产物时显示普通缺失 fallback**：图片预览和后台命令输出不得因文件缺失永久停留在 loading，也不得产生未处理的读取异常。仅在明确识别为文件不存在时显示缺失提示；其他读取失败仍使用通用错误提示，不推断文件已被清理。
- **对话框高度约束**：外框不超过视口（`max-h: 100dvh - 2rem`）；分类列表是唯一的滚动区（内部 `overflow-y-auto`），标题、时间范围、底部按钮保持固定可见。小窗口下底部操作区不得被裁剪到不可触达。
- **结果反馈**：显示成功删除文件数和失败数量；可展示删除失败路径及系统错误码。不得把文件逻辑大小描述为实际释放的磁盘空间。完成后重新扫描并刷新统计。

可勾选项（占用取当前扫描快照）：

- 命令完整输出（默认勾选；从现有工具输出中拆出 `cli/exec`）
- 临时缓存（默认勾选）
- 子代理产物
- 模型调用轨迹
- 开发诊断抓包
- 日志与崩溃报告
- 备份（勾选后沿用现有二次确认文案）
- 导出与反馈包
- 工具结果留档（`cli/artifacts`、`cli/sessions`、非 transcript 的 `cli/agents`、checkpoint pending/tmp；默认不勾；勾选时显示后果一句：会去掉图片原件和完整工具结果，会话仍可打开）

```text
勾选 + 时间范围（对话框草稿）
  → 普通范围直接确认；全部范围先显示不可恢复警告，再次确认
  → 存储服务按类别枚举 → 按范围过滤与保护 → 立即删除
  → 反馈删除数与失败数 → 重新扫描
```

## 状态所有者

- 分类与可清理性的唯一事实源仍是存储目录（`storageCatalog.ts`）。
- 清理计划（`cleanPlan.ts`）是纯函数：给定类别、候选、范围与当前时间，决定删哪些；删除动作由 adapters 执行。
- 存储服务（`storageService.ts`）是清理的唯一 owner：按类枚举，应用选定范围的时间过滤与保护规则后执行删除，并合并删除数与失败结果；`keepDirectories` 取各类 scope 的并集。
- 对话框只持有草稿态（勾选集合、时间范围），不持有快照以外的事实；确认后才发命令。

```text
扫描文件 → 存储目录分类 → 快照按类别聚合 → 设置页列表/明细 + 对话框占用
用户确认 → 存储服务按类枚举 → 应用所选范围的过滤与保护 → 删除 → 反馈结果 → 重新扫描
```

## 接口

- 共享类别 ID 增加 `commandOutputs`（前缀只含 `cli/exec`，可清理）；原 `toolOutputs` 去掉 `cli/exec`，剩下 `cli/artifacts`、`cli/sessions`、非 transcript 的 `cli/agents`、checkpoint pending/tmp，对话框内可选（默认不勾）。
- `StorageCleanRequest` 扩展为一次带多个类别和明确范围：`{ rootId, categoryIds, ageRange }`；旧单类别 `{ rootId, categoryId }` 仍兼容。
- `storageService.clean` 按类枚举，返回成功删除数、跳过数和失败路径/错误码。会话库、配置凭据、运行时/插件、未归类仍拒绝。
- 设置页文案键随类别 ID 派生，新增命令完整输出的名称与说明；工具输出文案去掉「命令完整输出」。

## 失败与边界

- 接受的缺口（写明不补）：不判定跨进程「正在跑但没在写」的任务。`bash-file-output.ts` 以 `O_APPEND` 打开 fd，进程不写就不更新 mtime，长时间无输出的后台任务可能被选中删除；子进程继续写进已 unlink 的 inode，磁盘不释放、UI 读不到输出。清理请求不带活跃会话/任务 id，main 不转给 CLI 判定。
- `cli/sessions/<sess>/workflows/` 里 paused workflow 的脚本随工具留档可删，删后能否恢复未验证过，默认不勾是对的，spec 在此写明。
- `cli/exec/sess_subagent_agent_*`（单个可达数百 MB）算进「命令完整输出」，与「子代理产物」框的直觉边界对不上，对话框文案要说清。
- 清理进行中的文件：删除失败记入部分失败，不回滚已删文件。
- 受保护文件名规则不变，即使落在范围内也不删。
- 官方插件 `cache` 仍归运行时，不被临时缓存带走。

## 验收场景

1. 分类列表无逐条清理按钮；「命令完整输出」与「工具输出」分行，体积与扫描快照对得上。
2. 对话框默认勾选命令完整输出 + 临时缓存；会话库/配置/运行时不出现在可选项里；工具结果留档默认不勾且有后果说明。
3. 选「24 小时前」只删超过 24 小时且不在活跃保护期内的文件；选「全部」会删除近期活跃的命令输出和当天日志，但仍跳过不可清理类别及受保护文件。
4. 清完后同一会话能打开、能继续发送；历史文字和工具卡摘要还在；被清掉的超长 Bash 路径再读为普通文件不存在。
5. 清理含工具卡图片产物的会话后重新打开工具卡，图片预览显示文件缺失 fallback，不永久 loading；非缺失读取错误显示通用媒体失败提示。
6. 清理后台 Bash 输出文件后打开输出面板，显示输出文件缺失提示且不显示无效重试；其它读取失败仍显示通用错误并允许重试。
7. 官方插件 `cache` 在运行时不被临时缓存带走。

## 验证

- 单测：分类拆分、四种范围过滤、范围模式的活跃与当天保护、全部模式不受时间保护、拒绝不可清类别、删除失败回报。
- `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed`。
- 不操作正在运行的 YCode；真机点对话框放实现后确认。
- 交互改动需要 E2E 场景：以验收场景 1–4 为 E2E 用例（打开存储页 → 开对话框 → 选范围确认 → 重扫后占用下降 → 同一会话可打开可续发）。
