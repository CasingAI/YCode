计划模式（Plan Mode）让模型**先探索、先计划，批准后再动手**。适合改动面大、方向需要确认的任务：模型在只读约束下调研代码库，产出一份计划交给你审批。

## 基本流程

1. 用 `/plan` 进入计划模式（命令需要顶格），或通过模式切换入口选择。
2. 模型以只读方式探索代码库——计划模式下普通文件写入会被权限拒绝。
3. 模型通过 `CreatePlan` 提交计划，输入包含三个字段：`title`（标题）、`overview`（1-3 句概述）与 `plan`（正文，上限 20000 字符）。
4. 计划以卡片形式出现在对话里，卡片右上角可「查看」完整正文，底部「执行计划」把会话切到完全访问并开始实施。
5. 执行过程中的审批仍按[安全与权限](/docs/safety)的规则走。

`CreatePlan` 在 Plan / Ask / Agent 三档下都可用：不切档、不询问、调用即落盘。在 Ask 档向模型要方案时同样会出计划卡；档位只决定模型能不能改文件，不决定能不能提交计划。

## 计划文件：落盘与找回

每次 `CreatePlan` 提交时，**运行时**会把计划原文落盘为工作区文件，三档都落：

- 路径：`<workspaceRoot>/.zcode/plans/<sessionId>/<slug>-<hash8>.md`，`slug` 由计划标题机械推导（中文原样保留）。
- 文件 = YAML frontmatter（`title`、`overview`、`created`、`toolCallId`）+ 计划正文；frontmatter 由运行时生成，模型提交的正文保持纯净。
- **一个会话可以有任意多份计划**，每次提交写一个新文件，从不覆盖。
- 上下文压缩后，模型会收到**最新计划文件**的工作区相对路径；正文不重新注入，需要时模型可以自己读取。
- 内置只读工具 `ListPlans`：一次调用返回本会话全部计划（标题、概述、路径、时间、是否最新）与最新一份的全文；任何模式下都可用，单份文件读不出来时逐份降级，不影响其他计划。
- UI 提供「会话计划」目录侧边栏：一条计划文件一条目录项，点击可打开计划详情。

## 边界与注意

- 计划文件由运行时唯一写入；模型不能自己写计划文件，UI 也不直接读文件（目录数据由运行时透传）。
- 只有 `CreatePlan` 提交会落盘；模型自己用 Write 写的计划文件不算数。
- `/plan` 不参与句中命中：它仍要求顶格输入，这与 `/goal` 的句中语义不同。
- 会话 Fork 时，Fork 边界之前实际出现的计划会复制到子会话自己的计划目录，父目录保持不变。
