长会话会不断逼近模型的上下文窗口。YCode 把上下文当成可治理的资源：用量可查、压缩可自动触发、也可以手动请求。

## 查看上下文用量

- 输入框的上下文浮层会显示当前占用；对话中也可以直接查询上下文余量并请求模型主动压缩。
- 模型侧有内置只读工具 `GetContextUsage`，返回与自动压缩决策**完全同口径**的用量：已用 token、剩余 token 与剩余百分比。分母是「有效上下文窗口」（上下文窗口减去输出预留），而不是标称窗口。

同一个浮层里还会显示[官方 Provider](/docs/zhipu)的套餐用量（OpenCode 见[单独一页](/docs/opencode)），以及 DeepSeek 的账户余额；其余供应商没有用量查询，只能自行去各家控制台看。

## 自动压缩

会话接近阈值时，运行时会在模型请求边界自动压缩历史，保证事件顺序与所有权和手动压缩完全一致。压缩有三道安全闸：功能被关闭（`disabled`）、消息太少没有压缩价值（`not_enough_messages`）、连续失败熔断（`circuit_breaker`）——后两道闸不会被强制请求越过。

## 手动压缩

- 用户命令 `/compact` 与模型工具 `Compact` 是两个入口、同一条压缩路径：工具只**登记一次压缩请求**，实际压缩发生在回合循环的自动压缩边界，事件流与自动压缩一致。
- 压缩是会话维护动作：它重写会话历史，但只改当前会话、不触碰工作区，因此在 Ask / Plan 模式也可用（这不对普通写工具开口子）。
- `Compact` 工具正常返回只表示「本次调用没有失败」，不表示压缩已经完成。
- 历史工具名 `CompactNow` 仅作为旧会话记录的兼容别名保留。

## 压缩之后

- 压缩摘要之外，[计划模式](/docs/plan)落盘的计划文件路径会作为提醒带给模型，正文不重复注入；模型可以用 `ListPlans` 或按路径读回。
- 会话本身支持恢复：重启后回到同一会话，上下文按持久化的历史重建。
