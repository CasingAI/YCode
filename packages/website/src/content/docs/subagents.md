子代理（Subagent）让主 Agent 把一块独立工作交给另一个 Agent 实例执行：探索代码库、并行调研、跑独立评审等。YCode 的子代理有几条明确的行为规则。

## 前台执行

普通子代理**只能在父回合内前台执行**：父 Agent 的工具调用要等子代理进入成功、失败或取消的终态后才返回，父回合不会在子代理还在跑时提前完成。

- 同一模型步骤里的多个独立子代理可以**并发运行**，但并发批次结束后必须统一收束（join）——并行不等于脱离父回合。
- 父回合被中止时，中止信号会传播到所有子代理；全部收束后父工具才返回。
- 不支持把子代理「扔到后台」：显式请求后台启动会得到明确的错误，而不是假装异步成功。

## 持久身份

- 每个子代理在创建时分配唯一逻辑身份 `agentId`，并与它的 child session 绑定（同一事务内写入）；身份持久化在会话存储里，**跨进程重启仍然有效**。
- 进程内的运行控制表（registry）只是缓存，进程退出即失效——「找不到运行时记录」不等于「Agent 不存在」。
- 只要 `agentId` 已分配，成功、失败、取消、停止的任何终态结果都会带这个 ID 返回。

## 续跑与冷恢复

- 对运行中的子代理，`SendMessage` 用于转向（steer）或排队消息；对已终态的子代理，`SendMessage` 会以**前台续跑**的方式拉起新一轮执行，结果返回给父模型。
- 重启后只凭 `agentId` 调用，也能定位到同一个 child session 恢复执行——不新建第二个代理。
- 冷恢复是**采用**而不是复活：恢复身份与历史内容的可达性，不恢复已丢失的运行中状态；续跑会校验当前父会话与 workspace 身份，跨工作区的 `agentId` 会被明确拒绝。
- 历史内容不可恢复时，保留同一 `agentId` 并显式标记 `contextReset` 建立新上下文，不会静默换一个代理。

## 内置与自定义

- 客户端设置里提供子代理管理入口；除内置类型（通用、探索、代码评审等）外，**插件也可以贡献子代理**（插件清单的 `agents` 字段，见[插件](/docs/plugins)）。
- 子代理的历史会话以 `sess_subagent_*` 形式持久化，可查询、可展示。
