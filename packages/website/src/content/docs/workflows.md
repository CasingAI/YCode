动态工作流（Dynamic Workflow）让你用一个 **TypeScript 脚本**编排多个模型子代理：脚本里有真正的控制流——循环、条件、并行扇出，中间结果有类型，而不是把「多步流程」全部押在模型的自由发挥上。

## 能做什么

- **fan-out**：同时派出多个子代理，各自负责一块独立工作（例如按目录切分代码评审）。
- **循环与门禁**：写一个循环，让子代理迭代修复直到某个条件满足。
- **类型化中间结果**：子代理返回结构化结果，脚本在类型检查通过后才运行。
- 脚本可以**保存复用**：保存后可以按名字带参数再次运行，适合沉淀成团队的标准流程。

## 默认关闭，按需开启

动态工作流是用户显式 opt-in 的能力：

- 桌面 / Web / 服务端的开关在**设置 → 实验功能 → Dynamic Workflow**，默认关闭；开启只影响之后**新建或冷恢复的会话**，正在运行的会话不会被热改写，运行中的 workflow 不会被强制停止，历史 run 仍可只读查看。
- 独立 CLI 是独立入口：默认不注册 Workflow 工具，只有显式设置环境变量 `ZCODE_DYNAMIC_WORKFLOW_MODE=onDemand`（按需）或 `alwaysOn`（常开）才开启；该变量不由桌面端读取或转发。
- 关闭设置后普通会话照常创建；协议层的 start/resume/amend 能力端口独立存在，不会因为模型工具未注册而被误报为「功能被禁用」。

## 与子代理的关系

工作流的每个步骤背后是一个子代理运行。子代理本身遵守[前台执行与持久身份](/docs/subagents)规则；工作流脚本只是把多个子代理的调度从「模型即兴」变成「代码保证」。
