「设置 → 网络」是独立的一级分区，管理所有全局网络出口策略；在此之上，模型与 MCP 服务器还可以各自覆盖出口行为。

## 全局代理与证书

分区里有两个分类：

- **网络代理**：「为全局启用」总开关、HTTP 代理地址、不使用代理的地址（No Proxy）。
- **证书**：自定义 CA 证书路径。证书与代理无关——直连场景同样需要自定义 CA，所以独立成分类、不受总开关影响。

「为全局启用」的语义要特别注意：

- **默认关闭**。开关未打开时，无论是否填了代理地址，模型、MCP、命令工具与应用渲染层流量一律直连；**填写地址 ≠ 启用代理**。
- 存量已填地址的用户升级后同样是关闭状态，代理停止生效，需手动开启。
- 开关打开后：渲染层即时生效；Agent 子进程与 Host 侧 API 在新会话/重启后完全生效（保存时有 toast 提示）。

## 按模型选择出口

模型编辑弹窗 → 高级配置 → 「网络代理」，四选一：

| 选项           | 行为                                                           |
| -------------- | -------------------------------------------------------------- |
| 未指定（默认） | 跟随全局开关的结果                                             |
| 使用代理       | 无视全局开关，强制走「网络」分区填写的代理地址；地址未填时直连 |
| 系统代理设置   | 无视全局开关，走操作系统配置的代理；系统未配代理时直连         |
| 不使用代理     | 无视全局开关，强制直连                                         |

范围**仅限该模型的推理请求**：MCP、WebFetch、Bash 子进程、内置浏览器等出口没有「当前模型」的概念，不读取该设置。「系统代理设置」由桌面 Host 在启动 Agent 时解析操作系统配置下发（macOS 读 `scutil --proxy`、Windows 读注册表、Linux 以环境变量为准）；**不解析 PAC 自动配置脚本**；独立 CLI 没有宿主下发时该模式按直连处理。

## 按 MCP 服务器选择出口

MCP 服务器编辑弹窗提供同样的四选一，作用范围是**该服务器的全部出站流量**（http/sse 的 transport 请求与 stdio 子进程的代理环境变量）：

- 「使用代理」「系统代理设置」拿不到地址时判**配置错误（config_invalid）**并在连接状态里明确提示去设置页补地址，不静默直连——显式选择缺材料是配置遗漏，不该伪装成网络不可达。
- 「不使用代理」会主动剥离子进程的全部代理环境变量，而不是「不注入」了事。
- 配置持久化在 MCP 配置文件里，与其它服务器字段同待遇；生效时机是连接建立时，改完需重连该服务器。

## 建议

- 需要代理才可达的模型 + 拒绝代理出口 IP 的模型可以混用：给前者选「使用代理」、后者选「不使用代理」，互不牵连。
- 密钥与凭据不放代理配置相关的仓库文件里，用环境变量或本地配置。
