> 本页扩展机制部分改编自官方 zcode-guide 插件（Apache-2.0），并以本仓库检出为准修订。

YCode 支持五类扩展资源（技能、自定义命令、Hooks、MCP、插件），外加 `AGENTS.md` 指示文件。这些资源分布在**用户作用域**与**工作区作用域**两级位置：用户级对你所有工作区生效，工作区级随仓库走、可以提交给团队共享。

## 配置文件在哪里

| 文件           | 路径                                                  | 内容                                               |
| -------------- | ----------------------------------------------------- | -------------------------------------------------- |
| 用户配置       | `~/.zcode/cli/config.json`                            | MCP 服务器、Hooks、插件启停状态、技能/命令禁用覆盖 |
| 工作区配置     | `<repo>/.zcode/config.json`（或 `<repo>/zcode.json`） | 同上，但只对该项目生效                             |
| 用户指示文件   | `~/.zcode/AGENTS.md`                                  | 每个工作区默认加载的个人指示                       |
| 工作区指示文件 | `<repo>/AGENTS.md`                                    | 项目级指示，从当前目录向上查找到项目根             |

## 五类资源一览

| 资源  | 形态                    | 用户作用域                                          | 工作区作用域                                               | 冲突规则                                                     |
| ----- | ----------------------- | --------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| 技能  | 目录 + `SKILL.md`       | `~/.zcode/skills/`、`~/.agents/skills/`             | `<repo>/.zcode/skills/`、`<repo>/.agents/skills/`          | 身份是文件路径；按发现顺序**先到先得**，用户级优先           |
| 命令  | `.md` 文件              | `~/.zcode/commands/`、`~/.agents/commands/`         | `<repo>/.zcode/commands/`、`<repo>/.agents/commands/`      | 按规范化命令名去重，**先到先得**（用户级覆盖工作区级）       |
| MCP   | JSON 对象               | 用户配置 `mcp.servers`（回退 `~/.agents/mcp.json`） | 工作区配置 `mcp.servers`（回退 `<repo>/.agents/mcp.json`） | 同名服务器**用户级覆盖工作区级**；两级默认都会自动连接       |
| Hooks | 配置对象 / `hooks.json` | 用户配置 `hooks`                                    | 工作区配置 `hooks`                                         | 配置文件 Hooks 需 `hooks.enabled: true`；插件 Hooks 追加在后 |
| 插件  | 目录 + `plugin.json`    | 从市场安装，启停状态存于用户配置                    | —                                                          | 一个插件可同时贡献技能、命令、Hooks、MCP 与子代理            |

关于技能目录的完整发现顺序（共 6 层）见[技能](/docs/skills)；`.agents/mcp.json` 是**兼容性回退**：同一作用域内先读 `.zcode`，该作用域没有 MCP 服务器时才回退读 `.agents/mcp.json`（注意两者键位不同：`.zcode` 用嵌套的 `mcp.servers`，`.agents` 用顶层 `mcpServers`）。

## AGENTS.md 的合并顺序

`AGENTS.md` 不是扩展资源，而是加载进模型上下文的行为指示文件：

- `~/.zcode/AGENTS.md` 放个人偏好：默认语言、评审风格、本地工作流约定。
- `<repo>/AGENTS.md` 放项目规则：架构边界、日志规范、测试要求、提交策略。
- 两者同时存在时，**用户级先加载、工作区级后加载**，工作区可以对宽泛的个人默认做收窄或覆盖。
- 内置 `/init` 命令面向当前工作区的 `AGENTS.md`（创建或更新仓库指示），不会去改用户默认文件。

## 该把配置放哪里

- 个人使用、跨项目 → 用户作用域（`~/.zcode/...` 或 `~/.agents/...`）。
- 团队或项目共享、随仓库版本化 → 工作区作用域（`<repo>/.zcode/...` 或 `.agents/...`）。
- 跨工具共享（Claude、Codex、Cursor 等）→ 技能放 `~/.agents/skills/`；只想在 YCode 内覆盖同名技能时用 `.zcode/skills/`。
- MCP 服务器 → 个人服务器放用户配置；要与团队共享放工作区配置。**两级默认都会在会话启动时自动连接**，所以只打开你信任的工作区。
- 密钥 → 永远不提交进版本库，用环境变量或本地配置。
