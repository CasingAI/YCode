`/goal` 是一条斜杠命令：下达一个目标，让模型朝着这个目标持续工作，而不是只回答一轮。它是命令体系的一员——凡是会被当作命令发出去的内容，输入框里都会以命令蓝高亮标出，发送前就能看见。

## 不用顶格：句中直接下达

原版要求斜杠命令必须写在消息开头；`/goal` 不需要。先说前情、最后落指令是中文输入的常态：

```text
先看一遍 auth 模块。/goal 修复登录超时的问题
```

命中规则（`/` 前面是什么决定生不生效）：

- 直接写在开头，或前面是空格：`/goal 修复登录` 生效。
- 前面是中文标点也行：`关系。/goal 一直分析` 生效（中文句末一般不加空格）。
- 前面紧贴着汉字不行：`前缀/goal` 不生效。
- `/` 后面必须有空格：`/goal修复登录` 不生效。
- `/target` 与 `/goal` 同义，大小写不敏感。
- `/goal` 之后到段落末尾的全部正文都是目标参数，之前的前文会被丢弃。
- 一条输入只允许一个命令：`/goal` 之后再写 `/plan`、`/init` 只会变成目标正文的一部分。
- 其余命令（`/plan`、`/compact` 等）仍要求顶格：只有 `/goal`、`/target` 支持句中下达。

## 高亮：发出去的是命令还是正文，一眼看出

凡是会被当作命令消费的内容，输入框与发送后的气泡都会以命令蓝标出作用域：

- `/goal` 的命令词与其后的目标正文同色，之前的前文保持普通颜色。
- 顶格命令的参数同样高亮：`/compact` 后面的压缩说明与它同色，发送前即确认哪一段会生效。
- 高亮是纯视觉，不进入复制文本与草稿存档。

## 子命令

`/goal` 后面的第一个词是子命令，同样支持句中写法：

| 子命令 | 作用 |
|---|---|
| （直接写目标） | 下达新目标并开始执行 |
| `resume` | 恢复之前暂停的目标 |
| `replace` | 用剩余文本替换现有目标 |
| `pause`、`clear`、`show` | 预留，暂不支持 |

## 发错了会怎样

- 在 Ask（只读问答）或 Plan（计划）模式下发送：被拦下并提示，草稿保留，需切到 Agent 模式再发。
- 带附件或上下文发送：被拦下并提示，需移除附件或上下文再发。
- 写了第二个命令：不执行、不提示，它只是目标正文的一部分。

## 执行中看到什么

- 状态面板显示一行目标原文（或其摘要标题），附带已用时间、暂停/恢复按钮与完成标记。
- 每次迭代校验在时间线以分隔线呈现（第 N 次迭代 · 校验中/完成/未完成）。
- 迭代推进中不发任务完成通知；目标真正完成、手动暂停或任务失败时正常通知。
