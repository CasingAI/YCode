目标模式让你用一条 `/goal` 命令下达一个**持久化目标**：运行时会把目标写进 `target` 状态并启动自主循环，持续朝着目标工作，而不是只回答一轮。

## 怎么用

在输入框里写：

```text
/goal 修复登录超时的问题
```

也可以把 `/goal` 写在句中——先说完前情、最后落指令是中文输入的常态：

```text
先看一遍 auth 模块。/goal 修复登录超时的问题
```

命中边界：

- `/goal` 之前的字符必须是**行首、空白或 CJK 标点**（`。`、`，`、`！` 等）。`关系。/goal 一直分析` 会命中；`前缀/goal` 不会命中（不把汉字当边界）。
- 触发符后必须跟空白：`/goal修复登录` 不命中。
- `/target` 与 `/goal` 同义，大小写不敏感。
- 目标范围是 `/goal` 之后直到段落末尾的**全部正文**，不在句读或换行处截断；之前的前文会被丢弃，不进入目标、也不随消息下发。

## 控制命令

`/goal` 后面的第一个词决定行为：`resume` 恢复自主循环；`replace` 用剩余文本替换现有目标；`pause`、`clear`、`show` 预留。控制命令也可以句中命中，行为与顶格完全一致。

## 与 Ask / Plan 模式的关系

自主循环只能在 Agent 模式下运行。在 Ask（只读问答）或 Plan（计划）模式发送 `/goal` 会弹出拦截提示、发送被拦下，草稿与模式档位保持不动——目标模式不会自作主张替你切档。

## 运行时语义

- 目标是**持久化状态**：提交后先写成 active，再启动自主循环登记执行轮次；「刚提交、循环还没开跑」的 Goal 在活会话读取时保持 active，不会被误判成僵尸暂停。
- 僵尸收口（进程崩溃留下的 active 但没有任何 run 的目标）只发生在**会话恢复**时；活会话上的读取是只读投影，不改状态。
- 一条输入只允许一个命令：`/goal` 之后的一切都是它的目标参数，再打 `/plan`、`/init` 只会变成目标正文，不会被执行；编辑器也会在已有命令芯片后清空命令候选。
- 输入框与发送后的气泡里，命令芯片和目标正文会用「命令蓝 + 中等字重」呈现作用域（纯着色、不画线），复制出来的是不含样式的纯文本。
