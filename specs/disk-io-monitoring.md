# YCode 磁盘 I/O 监控设计

## 目标与非目标

在现有 Resources Manager 增加「磁盘 I/O」页签。监控只观察应用已有的 I/O；所有计数器、延迟分布和历史样本仅保存在进程内存中，应用退出后自然销毁。不得为监控创建文件、写入日志/数据库/配置/缓存/浏览器持久化存储，也不得向远端上报监控数据。

本功能不替换设置页现有的存储空间扫描/清理功能，不改变 CPU/内存采样生命周期，不把逻辑读写量当成物理磁盘 I/O。

## 状态所有权

- Main 进程是磁盘 I/O 总览的唯一事实所有者：合并累计计数器、5 秒历史桶、进程级 OS I/O 差值与去重序列。
- Main、每个 Window Host、每个本地 ZCode Agent 分别在实际 I/O 执行边界记录本地增量；子进程只保留尚未汇报的内存增量。
- Host 每约 5 秒把本进程增量发送给 Main；Agent 每约 5 秒经现有 ZCode Protocol 通知发送增量，Host 仅透传本地 Agent 批次。远端 workspace 的 Agent 批次不进入本机磁盘统计。
- 对短生命周期的 SQLite Worker（Agent 的 history/sqlite read lane、Host 的 tasks-storage worker），在 Worker 内独立统计逻辑操作，并在完成/退出前提交最后一批内存增量。Worker 与父线程共享进程级 OS 计数，因此 Worker 批次不携带 OS 字节，避免物理 I/O 双计数。
- Resources Manager 只读取 Main 的快照。打开/关闭窗口只启停 UI 轮询，不启停采集器，不重置累计值或历史窗口。

## 事件顺序

```text
Main / Host / Agent 的实际 I/O 边界
  -> 进程内计数器（固定模块枚举；不保留路径、SQL 或内容）
  -> 每 5 秒批量增量
       Host -------------------------------> Main
       Agent -> ZCode Protocol -> Host ----> Main（仅本地运行面）
  -> Main 去重并合并累计计数器
  -> Main 固定长度历史环形缓冲区（最多 30 分钟）
  -> 窗口打开时读取快照并计算速率、趋势和延迟分位数
```

同一进程实例以随机内存实例令牌和单调递增批次序号标识；Main 丢弃重复或过期批次。去重表本身也有上限。正常退出尽力发送最后一批，崩溃时未发送的增量允许丢失，不进行磁盘恢复。

## 指标口径

- 文件 API：读取/写入操作次数、成功返回/提交的应用层逻辑字节数、耗时、失败次数。读取/写入流在结束或出错时汇总，不逐块发 IPC。
- SQLite：记录语句/事务执行次数、耗时和失败；不将 SQL 文本、参数或数据库写入量伪装成物理读写字节。
- OS 进程 I/O：只展示操作系统能可靠提供的实际读写字节。Linux 使用 `/proc/self/io` 的 `read_bytes` / `write_bytes` 差值；监控读取本身排除在业务计数外。Windows/macOS 在没有可靠跨平台 API 的情况下明确标记不可用，不用 `process.resourceUsage()` 的块操作计数推算字节数。
- 应用层逻辑字节与 OS 进程 I/O 分开显示，不直接相加。
- 延迟分布使用固定数量的直方图桶，内存有界；P95 是分桶近似值，UI 明示口径。平均耗时使用累计耗时 / 操作数。
- 现有日志写入为同步路径，队列积压显示为 0（无异步日志队列）；日志写入失败计入日志失败/丢弃数。不能把未知队列状态伪装成已测值。

## 采集边界

在 Node 进程启动早期安装轻量级文件 I/O 边界包装，覆盖常用 `node:fs` / `node:fs/promises` 读写 API 与读写流，捕获绕过 `FileSystemPort` 的操作；单独包装 `node:sqlite` 的数据库/语句执行边界。只记录固定枚举模块与数值，不保存路径、完整 SQL、密钥、会话正文或附件内容。监控记录函数不调用文件、数据库、网络或日志 API。

模块归类仅在当前调用栈内短暂检查路径后映射为固定类别（日志、SQLite、缓存、配置、会话、附件/存储、普通文件系统）；原始路径不进入任何计数器、IPC、历史样本或 UI。无法可靠归类时使用「文件系统/其他」。

## 生命周期与容量

- Main、Host、Agent 在自身运行期间持续采集，与资源管理器窗口无关。
- Main 每 5 秒生成一个历史桶，最多保留 360 个桶（30 分钟）；累计数值按本次应用运行周期保留。
- 模块、延迟桶、历史桶、去重表均为固定或有界结构；不保存逐次 I/O 事件。
- UI 默认查看 5 分钟，可切换 15 分钟和完整保留窗口（30 分钟）。关闭窗口停止 UI 定时器与分析，不影响采集。
- 采集/汇报异常只丢失对应增量，不得影响原始文件、数据库和日志操作。

## 验收

- Resources Manager 新增磁盘 I/O 页签，包含累计量、速率、次数、平均/P95 延迟、失败、日志写入失败/积压、趋势和可筛选来源明细。
- 关闭窗口时后台采集继续；重新打开可立即看到已有累计值和历史趋势。
- 文件读写流、同步/异步文件 API、日志和 SQLite 执行边界均有测试；重复批次不会重复累计。
- 不记录路径、SQL 或业务内容；不增加持久化写入、网络上报或逐事件 IPC。
- Linux OS I/O 显示可靠的进程实际读写字节；Windows/macOS 的不可用状态明确可见。
- CPU/内存监控和设置页存储空间管理行为保持不变。
