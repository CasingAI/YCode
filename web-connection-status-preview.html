手机 Web 连接状态 UI 预览

对比「现状」与「优化后」在手机浏览器各个连接状态下的表现。重点看两件事：切后台再回来能不能立刻恢复，以及状态条会不会用无意义的重试次数吓到人。

1 · 不再显示「第 N 次」 次数只在连接稳定存活 30 秒后才归零，手机切后台几秒就回来永远达不到，于是它实际等于「你切 App 的次数」。UI 改用倒计时表达确定性，把次数留在快照里给日志用。
2 · 切回来立刻重连 现状里 retryNow() 状态为 connected 时直接返回，前台事件被吞掉；而浏览器端没有任何存活性检测，卡住的 socket 只能等系统报 close。改为：隐藏超过 8 秒后回前台，无条件重建连接。
3 · 瞬断不闪屏 断线后等 800ms 再决定要不要显示 UI，恢复了就什么都不出现。切后台那一瞬间的抖动不该在对话上方闪一条横幅。
4 · 状态分级 细条 → 升级文案 → 卡片，只在真的需要用户介入时给按钮。同时补上 pageshow，覆盖 iOS 从 BFCache 恢复的路径。
